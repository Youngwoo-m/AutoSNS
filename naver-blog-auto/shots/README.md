# 화면 캡처 두는 곳

직접 찍은 프로그램 화면을 여기에 두면, 그 글을 발행할 때 '따라하기' 칸에 알아서 들어간다.
`geoai_steps.py` 가 그리는 것은 **도식**이지 실제 화면이 아니다 — 진짜 화면은 사람이
띄워서 찍어야 한다. 캡처가 있으면 도식 대신 캡처가 쓰인다.

## 파일 이름 규칙

```
shots/<slug>/
  cover.png             ← 단계 목록 맨 위. 도식을 대신한다
  01 레이어 추가.png      ← 1단계 밑에 붙는다. 숫자 뒤 글자가 그림 설명이 된다
  02.png                ← 설명 없이 2단계 밑에만
```

- `<slug>` 는 `geoai_series.py` 의 주제 slug (예: `qgis-start`, `genai-doc`).
  확인:  `./.venv/bin/python geoai_series.py --plan`
- **자리는 파일 이름의 낱말로 정해진다.** `04 화면 오른쪽 아래의 좌표계 표시.png` 는
  '좌표계'라는 낱말 때문에 '좌표계 확인' 단계에 붙는다 — 그 단계가 2번이든 4번이든.
  따라하기 단계 글은 발행할 때 정해지므로, 번호만 믿으면 글이 다시 생성돼 순서가
  바뀔 때 엉뚱한 자리에 붙는다. 그래서 **설명을 꼭 적는 편이 좋다.**
- 낱말로 못 찾으면 번호를 쓴다. 번호를 아예 안 붙여도 된다(`속성 테이블.png`).
  단계 수보다 큰 번호는 무시된다.
- png · jpg · jpeg · webp 를 받는다. 폭은 업로드할 때 자동으로 줄어든다.
- 캡처가 없으면 도식이 그대로 쓰인다. 있으면 더 좋은 것이지 발행 조건이 아니다.

## 쓰는 법

```bash
./.venv/bin/python geoai_shots.py list            # 어떤 slug 에 몇 장 있는지
./.venv/bin/python geoai_shots_apply.py <slug>          # 이미 나간 글에 무엇이 바뀔지만
./.venv/bin/python geoai_shots_apply.py <slug> --go     # 실제로 반영
```

아직 안 나간 글은 아무것도 안 해도 된다 — 발행할 때 알아서 들어간다.
**이미 나간 글**은 `geoai_shots_apply.py` 로 따라하기 칸만 고친다(글·제목·라벨·주소는
그대로). 같은 단계에 다시 돌리면 갈아 끼운다(겹치지 않는다).

보통은 글이 나온 뒤에야 무엇을 찍을지 알게 되므로, 이쪽이 실제로 더 자주 쓰인다.

## 찍을 때 주의

- 개인정보·내부자료·계정 정보가 화면에 나오지 않게 한다(주소창·알림·파일 이름도 본다).
- 타사 프로그램 화면은 설명에 필요한 범위만 담는다.
- 캡처는 공개 저장소(`geoai-assets`)에 올라가 CDN 주소로 쓰인다 — 한 번 올라간 것은
  공개된다고 보면 된다.
