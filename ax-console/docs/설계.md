# AX 발행 콘솔 설계안

학과 계정과 개인 계정의 여러 매체에서 하던 글쓰기, 영상 제작, 업로드, 예약 발행을
**하나의 로컬 웹 화면**에서 다루기 위한 설계 문서다. (작성 2026-10-17, 상태: 검토용 초안)

---

## 1. 목표와 원칙

**목표**
- 지금은 매체마다 따로 있는 스크립트 20여 개, launchd 예약 작업 24개, 상태 JSON 파일 여러 개를 화면 하나로 모은다.
- "기획 → AI 초안 → 사람 검토 → 제작 → 예약 → 발행 → 성과 확인"을 한 흐름으로 잇는다.
- 학과 계정과 개인 계정을 한눈에 구분하되, 같은 방식으로 다룬다.

**원칙**
1. **기존 스크립트는 새로 짜지 않고 감싼다.** 지금 잘 돌고 있는 발행 코드는 그대로 두고, 콘솔은 그 코드를 호출하고 결과를 읽기만 한다. 갈아엎는 일은 매체별로 따로 판단한다.
2. **사람이 승인해야 나간다.** AI가 쓴 글과 영상은 '승인함'을 거쳐야 예약에 오른다. 이미 자동으로 돌고 있는 시리즈는 지금처럼 자동으로 두되, 매체마다 켜고 끄는 스위치를 단다.
3. **이 Mac 안에서만 돈다.** `127.0.0.1`에서만 접속받고, 비밀값은 지금처럼 암호화 저장소(`secrets.env.enc`, `shared/secret_*.py`)에서 읽는다. 화면에 토큰을 보여 주지 않는다.
4. **외부에서 들어온 글은 데이터로만 다룬다.** 질문 큐, 댓글처럼 남이 쓴 글은 화면에 이스케이프해서 보여 주고, AI 지시문에 섞지 않는다.
5. **영상은 CLAUDE.md 영상 지침을 따른다.** Remotion 편집, 디오라마 2~3장, Pretendard Bold, AI 합성 고지.

## 2. 시작: 구글 계정 로그인 (학과·개인)

콘솔을 열면 가장 먼저 **구글 계정 두 개를 연결하는 화면**이 나온다. 이 연결이 끝나야 나머지 메뉴가 열린다.

| 칸 | 구글 계정 | 이 계정으로 여는 매체 |
|---|---|---|
| 학과 | 학과 구글 계정 | 학과 유튜브, 학과 블로거(smuds2026), 서치콘솔 |
| 개인 | 개인 구글 계정 | 개인 유튜브, 블로거(geoaina·토목 연재), 서치콘솔 |

**동작 방식**
- 칸마다 **[Google로 로그인]** 버튼 하나. 누르면 시스템 브라우저에 구글 로그인 창이 뜨고, 사람이 직접 계정을 고르고 권한을 허락한다. 콘솔은 비밀번호를 받지 않는다.
- 데스크톱 앱용 OAuth(로컬 주소로 돌아오는 방식)를 쓴다. 지금 쓰는 방식과 같다:
  학과는 `youtube_login_setup.py`, `blogger_auth_setup.py`, 개인은 `geoai_youtube_auth.py`, `geoai_auth_setup.py`.
  콘솔은 이 흐름을 한 버튼으로 묶고, 받은 토큰은 지금처럼 `shared/token_store.py`의 암호화 저장소에 계정별로 넣는다.
- 권한은 한 번에 모아서 요청한다: `youtube.upload`, `youtube.force-ssl`, `blogger`, `webmasters.readonly`.
- 로그인한 뒤 화면에 **어떤 구글 계정인지(이메일·프로필 사진)와 그 계정에 딸린 유튜브 채널·블로그 목록**을 보여 준다. 사람이 "이 채널은 학과용"이라고 확인해야 연결이 끝난다. 학과 칸에 개인 계정으로 로그인하는 실수를 막기 위해서다.
- 연결된 계정마다 **[다시 로그인]**과 **[연결 해제]** 버튼, 토큰 상태(정상/만료 임박/만료)를 둔다. 토큰이 만료되면 '오늘' 화면 맨 위에 경고를 띄운다.
- 앞으로 할 일: 구글 로그인이 아닌 매체(네이버, 티스토리, 인스타, 틱톡, 그리고 학과 계정만 있는 X·스레드)는 학과·개인 칸을 나눠 같은 화면 아래쪽에 "매체 연결" 칸으로 두고, 기존 chrome-profile 로그인 창을 여는 버튼을 단다.

**콘솔 자체의 잠금**
- 콘솔은 이 Mac의 `127.0.0.1`에서만 열리므로 처음에는 따로 로그인을 두지 않는다. 다른 기기에서 접속하게 되면 그때 학과·개인 구글 계정 중 하나로 로그인해야 들어오도록 바꾼다.

## 4. 전체 구조

```
브라우저 (127.0.0.1:8700)
   │
콘솔 서버 (Flask, 파이썬)  ── insta-manual 과 같은 방식
   ├─ 콘텐츠 저장소 (SQLite: console.db)
   │     콘텐츠 · 매체별 변환본 · 예약 · 실행 기록 · 승인 기록
   ├─ 매체 어댑터 (매체마다 하나)
   │     읽기:  기존 상태 JSON → 콘텐츠/예약으로 변환해 보여 줌
   │     쓰기:  기존 run_*.sh · 발행 함수 호출
   ├─ AI 작업기
   │     글: shared/llm.py (학교 게이트웨이)
   │     그림: 게이트웨이 이미지 모델 (디오라마)
   │     영상: remotion-shorts 렌더
   ├─ 예약 실행기
   │     launchd 작업 목록·다음 실행 시각 표시, 켜기/끄기 (launchctl)
   │     콘솔에서 만든 예약은 1분 주기 launchd 작업 하나가 꺼내 실행
   └─ 성과 수집기: analytics/collect_*.py 결과를 읽어 표시
```

**단계적으로 옮기는 방법**
- 1~2단계에서는 기존 JSON 파일(`publish_schedule.json`, `blogger_post_state.json`, `state.json` 등)이 원본이다. 콘솔은 읽어서 보여 주고, 고칠 때도 그 파일을 고친다.
- 3단계부터 새로 만드는 콘텐츠만 `console.db`에 저장한다. 기존 시리즈는 한 매체씩 옮긴다.
- 지금 만든 `dashboard/build.py`는 1단계 홈 화면으로 흡수한다.

## 5. 핵심 흐름 (AX 파이프라인)

```
① 기획      주제 제안(뉴스·기출·시리즈 다음 편) 또는 직접 입력
② 초안      AI가 원문 하나를 쓰고, 매체별 변환본을 만든다
              블로그 긴 글 / 인스타 카드 문구 / 숏츠 대본 / 스레드·X 짧은 글
③ 검토      승인함에서 사람이 고치고 승인 (출처·수치·AI 고지 점검표 포함)
④ 제작      썸네일·카드·디오라마 이미지, Remotion 영상 렌더
⑤ 예약      매체별 시각 지정 (추천 시각 제시), 달력에 표시
⑥ 발행      예약 실행기가 어댑터 호출 → 결과 URL 기록
⑦ 성과      조회수·노출·클릭을 모아 콘텐츠 옆에 붙인다
```

콘텐츠 하나는 이 상태를 차례로 지난다:
`아이디어 → 초안 → 검토 대기 → 승인 → 제작 중 → 예약됨 → 발행됨 / 실패`

실패하면 원인(로그인 만료, 토큰 만료, 업로드 오류)을 사람이 읽을 수 있는 말로 보여 주고, **[다시 시도]**와 **[로그인 다시 하기]** 버튼을 둔다.

## 6. 화면 구성

왼쪽 메뉴 + 위쪽 [전체|학과|개인] 스위치 + 본문. 휴대폰 폭에서는 메뉴가 아래 탭으로 바뀐다.

| 메뉴 | 하는 일 |
|---|---|
| **계정 연결** (첫 화면) | 학과·개인 구글 로그인, 연결된 채널·블로그 확인, 토큰 상태 |
| **오늘** (홈) | 오늘·이번 주 발행 예정, 승인 기다리는 글, 실패한 작업, 로그인 만료 경고, 주요 지표 4개 |
| **달력** | 주·월 달력에 매체별 색으로 예약 표시. 끌어서 날짜 옮기기, 빈 칸 눌러 새 예약 |
| **작성 스튜디오** | 주제 입력 → AI 초안 → 매체별 변환본 탭 → 미리보기(매체 모양 그대로) → 승인 요청 |
| **영상 스튜디오** | 대본 → 장면 목록 → 디오라마 생성(2~3장) → Remotion 미리보기 → 렌더 → 숏츠·릴·틱톡 변환 |
| **승인함** | 검토 대기 목록. 점검표(출처, 수치, 금칙어, AI 고지, 글자 깨짐) 통과 후 승인 |
| **채널·계정** | 계정 카드 목록: 연결 상태, 로그인 만료일, 최근 발행, 자동 발행 켜기/끄기 |
| **자동화** | launchd 작업 24개의 다음 실행 시각·최근 결과·로그 보기, 켜기/끄기, 지금 실행 |
| **성과** | 매체별·시리즈별 조회수 추이, 잘 된 글 목록, 주간·월간 보고서 열기 |
| **설정** | 글꼴, AI 모델, 기본 발행 시각, 디스크 사용량 |

**디자인 기준**
- 글꼴 Pretendard Bold 하나. 위계는 크기와 색으로 준다 (CLAUDE.md 3항).
- 매체 색: 유튜브 빨강, 인스타 자주, 블로그 초록, 티스토리 주황, X 검정, 스레드 회색, 틱톡 청록.
- 학과 계정은 파란 띠, 개인 계정은 보라 띠로 카드 왼쪽에 표시한다.
- 발행·삭제처럼 되돌릴 수 없는 버튼은 한 번 더 확인한다 ("유튜브 학과 채널에 지금 공개 발행합니다").
- 라이트·다크 모드 모두 지원.

## 7. 보안·안전

- 서버는 `127.0.0.1`에만 연결. 다른 기기에서 보려면 1단계 대시보드처럼 **읽기 전용 화면**만 따로 내보낸다.
- 화면에서 실행하는 명령은 미리 정한 목록(어댑터 함수, 정해진 run_*.sh)만 허용한다. 임의 명령 입력창은 두지 않는다.
- 로그인이 필요한 매체(네이버, 티스토리, 틱톡 등 브라우저 자동화)는 콘솔이 비밀번호를 받지 않는다. **[로그인 창 열기]**로 기존 chrome-profile 창을 띄우고 사람이 직접 로그인한다.
- 실행 기록에는 누가(사람/자동) 무엇을 언제 발행했는지 남긴다.

## 8. 데이터 폴더 구조

콘솔이 만드는 데이터는 모두 `ax-console/data/` 아래에 모은다. 날짜와 콘텐츠 ID로 나눠서 나중에 찾기 쉽게 한다.

```
ax-console/
  docs/        설계 문서
  design/      화면 시안
  app/         콘솔 코드
  data/        (git 제외, 백업 대상)
    dashboard/   생성된 대시보드
    content/YYYY/MM/<콘텐츠ID>/   원문.md, 변환본_블로그.md, 변환본_숏츠대본.json …, meta.json
    media/YYYY/MM/<콘텐츠ID>/     디오라마_01.png, 썸네일.png, 최종.mp4 …
    runs/YYYY-MM-DD.jsonl         발행 실행 기록 (누가·언제·어느 계정·결과 URL)
    analytics/                    성과 수집 결과
    console.db                    콘텐츠·예약 목록 (3단계부터)
```

**기존 모듈의 데이터**: `publish_schedule.json`, `blogger_post_state.json`, `posts/` 영상 등은 launchd 예약 작업 24개가 지금 경로를 그대로 쓰고 있다. 그래서 지금은 옮기지 않고, 매체 어댑터를 옮기는 단계에서 한 매체씩 `data/` 아래로 옮긴 뒤 원래 자리에는 링크를 남긴다.

## 9. 단계 계획

| 단계 | 범위 | 끝난 모습 |
|---|---|---|
| 0 | 구글 계정 연결 | 학과·개인 구글 계정 로그인, 채널·블로그 확인, 토큰 상태 표시 |
| 1 | 읽기 전용 콘솔 | 오늘·달력·채널·자동화 화면이 기존 파일과 launchd를 읽어 보여 준다 |
| 2 | 예약 관리 | 예약 추가·수정·취소, 지금 실행, 자동화 켜기/끄기, 실패 다시 시도 |
| 3 | 작성 스튜디오 + 승인함 | 원문 하나 → 매체별 변환본 → 승인 → 예약 (새 콘텐츠부터 console.db 사용) |
