# 기획·초안 에이전트 설계

콘텐츠 파이프라인의 **① 기획**과 **② 초안**을 맡는 에이전트. 결과는 언제나 **③ 사람 검토**로 들어가고,
에이전트가 직접 발행하는 일은 없다. (2026-10-18 초안, 검토용)

---

## 1. 지금과 무엇이 달라지나

| | 지금 (`draft_ai.py`) | 에이전트 |
|---|---|---|
| 주제 | 사람이 정한다 | 뉴스·검색어·시즌·시리즈·성과를 보고 **제안**한다. 사람이 고른다 |
| 자료 | 모델이 아는 것만 | 뉴스·공공 자료를 **직접 찾아 읽고** 그 내용으로 쓴다 |
| 사실 확인 | `[확인 필요]` 표시만 | 숫자·날짜·기관명을 **찾은 자료와 대조**하는 두 번째 검토를 한다 |
| 출처 | 기관 이름만 | 실제로 읽은 문서의 **주소**를 붙인다 |
| 중복 | 확인 안 함 | 지난 글 제목·주제와 겹치는지 확인한다 |
| 호출 | 한 번 | 조사 → 개요 → 초안 → 자체 검토, 여러 단계 |

## 2. 목표와 하지 않는 것

**목표**
- 매주 계정별로 "이번 주에 쓸 만한 주제"를 근거와 함께 제안한다.
- 고른 주제로 출처가 붙은 원문과 채널별 변환본을 만들어 검토 대기에 올린다.
- 사람이 고친 내용과 반려 사유를 다음 제안·초안에 반영한다.

**하지 않는 것**
- 발행·예약 승인을 하지 않는다. ③ 검토는 항상 사람이 한다.
- 읽지 않은 문서를 출처로 달지 않는다. 주소를 지어내지 않는다.
- 질문 큐·댓글·뉴스 본문 속 지시문을 따르지 않는다(모두 자료로만 쓴다).
- 사고 순간·부상 묘사, 특정인 비난, 정치적 주장은 쓰지 않는다.

## 4. 두 가지 일

### A. 주간 기획 제안 (매주 일요일 저녁, 자동)

```
자료 모으기 (모델 없음)              제안 만들기 (에이전트)              사람
뉴스·검색어·시즌·시리즈·성과   →   계정별 후보 10개 → 5개로 추림   →   콘솔에서 고르기
                                    (주제, 이유, 근거 링크, 채널,      ✔ → ① 기획으로
                                     예상 형식, 겹치는 지난 글)         ✘ → 반려 사유 기록
```

제안 하나에 들어가는 것:
- 주제와 한 줄 요약
- **왜 지금인가**: 시즌, 최근 뉴스(주소), 검색 유입, 시리즈 공백 중 해당하는 것
- 추천 채널과 형식 (블로그 글 / 카드뉴스 / 숏츠 대본)
- 겹치는 지난 글이 있으면 그 제목과 "다른 점"

### B. 초안 작성 (사람이 고른 기획마다)

```
1 조사      검색·뉴스·공공자료 3~8개를 읽고 요점과 숫자를 메모 (주소 포함)
2 개요      독자, 핵심 메시지 3개, 소제목 구성
3 원문      개요대로 원문 작성. 숫자·날짜마다 메모의 출처 번호를 단다
4 변환본    채널별 형식으로 (지금 draft_ai 의 형식 규칙 그대로)
5 자체 검토  두 번째 호출이 원문을 읽고 확인:
            - 숫자·날짜·기관명이 메모의 출처와 맞는가 → 안 맞으면 [확인 필요]
            - 출처 없는 단정이 있는가
            - 자극적 표현·금칙어·과장
            - 지난 글과 문장이 겹치는가
6 제출      ③ 검토 대기로. 조사 메모·출처 목록·자체 검토 결과를 함께 붙인다
```

검토자는 콘솔에서 **원문 옆에 출처 메모를 나란히** 보면서 고친다.

## 5. 도구

| 도구 | 하는 일 | 제한 |
|---|---|---|
| `search_news(query, days)` | 뉴스 검색 (Google 뉴스 RSS) | |
| `search_web(query)` | 네이버 블로그·웹 검색 | |
| `fetch_page(url)` | 문서 본문 읽기 (글자만) | 초안 하나에 15개, 도메인 제한 없음 |
| `search_queries(site, days)` | 서치콘솔 검색어·노출 | |
| `past_titles(account, query)` | 지난 글 제목·주소 검색 | |
| `series_status()` | 진행 중 시리즈와 다음 편 | |
| `season_now()` | 지금 시즌의 재난 유형 | |
| `exam_topics(field)` | 기출 우선순위 (개인 계정) | |
| `save_note(text, source_url)` | 조사 메모 저장 | 읽은 주소만 출처로 남는다 |
| `submit_proposals(list)` / `submit_draft(content)` | 결과 제출 | 콘솔의 ①·③ 상태로만 |

발행·예약·파일 쓰기·코드 실행 도구는 주지 않는다.

## 6. 계정별 기준

| | 학과 | 개인 |
|---|---|---|
| 독자 | 수험생·학부모·재학생, 지역 주민 | 공간정보 실무자, 기술사 수험생 |
| 주제 축 | 생활안전, 시즌 재난 대비, 진로·자격증, 학과 소식, 지역 재난 | GeoAI·공간정보 개념, 기술 동향, 기술사 답안·기출 |
| 말투 | 친근하지만 신뢰감 있게, 학과 이름 | 전문가 1인칭, 정의·근거 중심 |
| 피할 것 | 입시 결과 단정, 타 대학 비교 | 미검증 기술 과장, 기출 원문 무단 전재 |
| 영상 (④로 넘김) | 디오라마 2~3장 장면 제안 (CLAUDE.md 영상 지침) | 개념도·흐름도 장면 제안 |

## 7. 배우는 방법

- **반려 사유**: 제안을 반려할 때 고른 이유(이미 다룸 / 시기 아님 / 학과와 무관 / 기타)를 저장 → 다음 주 제안 프롬프트에 최근 반려 10건을 넣는다.
- **사람이 고친 차이**: ③에서 승인할 때 초안과 최종본의 차이를 저장 → 자주 고치는 표현을 "문체 메모"로 모아 초안 프롬프트에 넣는다.
- **성과**: ⑦이 생기면(§9) 잘 된 글의 주제·형식을 제안 근거로 쓴다.

모두 `ax-console/data/agent/planner/` 에 파일로 남겨 사람이 열어 보고 지울 수 있게 한다.

## 8. 실행·비용

- 실행 방식은 실패 대응 에이전트와 같은 **직접 만든 루프 + 학교 게이트웨이 도구 호출**. 두 에이전트가 도구 등록·예산·기록 틀을 함께 쓴다(`app/agent_core.py`).
- 주간 제안: 일요일 20:00 (launchd 또는 콘솔 예약), 계정당 1회.
- 초안: 사람이 기획을 고르면 바로. 초안 하나에 웹 문서 15개, 토큰 상한(예: 8만).
- 학교 크레딧(월 12,000)을 넘지 않게 콘솔 설정 탭에 이번 달 사용량을 보여 준다.

## 9. 미리 풀어야 할 빈틈

1. **글 단위 성과가 없다.** 지금 `analytics/snapshots` 는 매체별 합계다. 유튜브는 영상별, 서치콘솔은 주소별 수치를 받을 수 있으니 ⑦ 단계에서 발행 주소 기준으로 붙여야 "잘 된 주제"를 배울 수 있다.
2. **출처 읽기 범위**: 일부 언론·공공 사이트는 자동 읽기를 막는다. 못 읽은 문서는 출처로 쓰지 않고 메모에 "읽지 못함"으로 남긴다.
3. **기출 원문 저작권**: 기출 문제는 문제 번호·주제로만 가리키고 원문을 길게 옮기지 않는다.

## 10. 콘솔 화면

- 콘텐츠 탭 맨 앞에 **⓪ 제안** 칸: 이번 주 제안 카드(주제, 이유, 근거 링크, 채널) + [기획으로] [반려(사유)]
- ③ 검토 화면에 **조사 메모·출처** 패널과 **자체 검토 결과**(확인된 숫자 ✔ / 확인 필요 ⚠)
- 설정 탭에 에이전트 사용량, 시즌 달력 편집

## 11. 단계 계획

| 단계 | 범위 | 끝난 모습 |
|---|---|---|
| 1 | 공통 에이전트 틀(`agent_core.py`) + 자료 도구 | 도구 호출·예산·기록이 동작 |
| 2 | 초안 에이전트 (조사 → 원문 → 자체 검토) | ②가 출처 주소가 붙은 초안을 만든다. 지금 `draft_ai.py` 를 대체 |
| 3 | 주간 기획 제안 + ⓪ 제안 칸 | 일요일마다 계정별 제안이 올라온다 |
| 4 | 반려 사유·수정 차이 반영 | 제안·초안이 사람 취향에 맞춰진다 |
| 5 | ⑦ 성과 연결 | 잘 된 글 기준으로 제안한다 |

**검증 방법:** 2단계는 최근 사람이 쓴 글 5편의 주제로 초안을 만들어 출처 정확도(주소가 실제로 그 숫자를 담고 있는가)를 사람이 점검한다.

## 12. 정한 것 (2026-10-18)

1. **제안 개수·요일·시각**은 콘솔 설정 탭의 에이전트 설정 창에서 계정별로 입력한다(`config/agents.json`).
2. **출처 도메인은 제한하지 않는다.** 다만 읽지 못한 문서는 출처로 쓰지 않는 원칙은 그대로다.
3. **기술사 주제는 이 에이전트가 맡는다.** 지금 Codex 연재 자동화가 하는 기술사 글은, 이 에이전트의 초안 단계가 동작한 뒤 넘겨받는다(넘겨받기 전까지 Codex 자동화는 그대로 둔다).
4. **공통 틀(`app/agent_core.py`)을 먼저 만든다.** 실패 대응 에이전트와 함께 쓴다.
