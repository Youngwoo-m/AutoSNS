# AX 발행 콘솔

학과·개인 계정의 글쓰기, 영상 제작, 업로드, 예약 발행을 한 화면에서 다루는 로컬 콘솔.

| 폴더 | 내용 | git |
|---|---|---|
| `docs/` | 설계 문서 (`설계.md`) | 올림 |
| `design/` | 화면 시안 HTML | 올림 |
| `app/` | 콘솔 코드. 지금은 대시보드 생성기 `build_dashboard.py` 하나 | 올림 |
| `data/dashboard/` | 생성된 대시보드 `index.html` (발행할 때마다 다시 만들어짐) | 제외 |
| `data/content/` | 콘텐츠 원문·매체별 변환본 (`YYYY/MM/<콘텐츠ID>/`) | 제외 |
| `data/media/` | 디오라마 이미지·썸네일·렌더된 영상 (`YYYY/MM/<콘텐츠ID>/`) | 제외 |
| `data/runs/` | 발행 실행 기록·로그 (`YYYY-MM-DD.jsonl`) | 제외 |
| `data/analytics/` | 매체별 성과 수집 결과 | 제외 |

`data/` 는 실행할 때 생기는 산출물이라 git 에 올리지 않는다. 백업은 `backup_state.sh` 대상에 넣는다.

## 실행

```
python3 ax-console/app/server.py      # http://127.0.0.1:8700
```

- **계정 연결** (첫 화면): 학과·개인 구글 토큰(유튜브·블로거·서치콘솔) 상태와 실제 연결된 채널·블로그, 로그인 버튼(기존 인증 스크립트 실행). 네이버(학과·개인)·카카오(개인)·Netlify 상태, GitHub 계정 3개(모두 개인 구글) 기본 계정 전환
- **자동 작업**: launchd 작업 25개를 계정별·채널별로 (분석: `config/automations.json`, `docs/자동작업_목록.md`)
- **콘텐츠**: 파이프라인 보드(① 기획 ~ ⑥ 발행). 세명대 게이트웨이로 원문·채널별 변환본 초안, 점검표 승인 후 채널별 예약
- **작업**: 학과/개인 → 채널을 고르고 수행 내용 입력·수정, 실행 작업 선택, 예약 걸기, 지금 실행, 실행 기록 보기
- **예약 목록**: 콘솔 예약과 launchd 자동 작업을 앞으로 8일치 시간순으로 (계정·채널·출처로 거르기)
- **설정**: 계정 정보 수정, 비밀값 저장 여부, 세명대 AI 게이트웨이(모듈별 설정·사용량·키 확인), 플러그인 켜기/끄기, 커넥터, 설치된 스킬
- 서버는 launchd `com.smuds.axconsole` 로 로그인할 때 켜지고, 꺼지면 30초 안에 다시 켜진다.
  다시 시작: `launchctl kickstart -k gui/$(id -u)/com.smuds.axconsole` · 로그: `data/logs/server.*.log`
- 예약은 서버가 켜져 있을 때만 실행된다(USB가 빠져 있으면 서버도 못 켠다). `data/tasks.json` 에 작업, `data/runs/` 에 실행 기록이 쌓인다.

## 로그인·계정 관리

- **콘솔 로그인**: 처음 열 때 비밀번호(8자 이상)를 직접 만든다. PBKDF2 해시만 `data/auth/auth.json`(600)에 저장.
  쿠키 세션 30일(3일 안 쓰면 끝), 1분에 5번 틀리면 1분 막음. 위 **관리자 ▾** 에서 비밀번호 바꾸기·로그아웃.
  잊으면 `data/auth/auth.json` 을 지우고 다시 만든다. 이 Mac 의 에이전트는 `data/auth/internal.key` 로 API 를 부른다.
- **채널 계정 관리 ▾**(계정 연결 탭): 구글 서비스별 다시 로그인·연결 해제(토큰만 삭제), 계정 전체 로그아웃(구글 쪽 취소 + 토큰 3개 삭제),
  네이버·티스토리 다시 로그인(기존 로그인 스크립트)·로그아웃(프로필 쿠키 삭제, 티스토리는 tistory_cookies.json 도), 카카오 알림 토큰 삭제, GitHub 계정 로그아웃.
  로그아웃 전에 영향받는 자동 작업을 보여 주고 확인받는다.
- **채널 정보**: 연결되면 유튜브 구독자·영상·조회수, 블로거 글 수, 네이버·티스토리 블로그 이름·최근 글, GitHub 저장소 수를 가져온다.
- **비밀값**(설정 탭): 저장된 값은 보여 주지 않고, 새 값을 넣어 저장하면 암호화 저장소에 들어간다.
- **↻ 새로고침**: 지금 보는 탭을 다시 불러온다(계정 연결 탭은 채널 정보까지).

## 편집

- **자동 작업** 탭 '편집': 이름·설명(`config/automations.json`)과 실행 시각(요일·시각 여러 줄, 매월 N일, N분마다).
  시각을 바꾸면 launchd plist 를 고치고 켜져 있던 작업은 바로 다시 올린다. 바꾸기 전 사본은 `data/config-history/`.
- **작업** 탭 목록의 ✎: 제목·실행 시각·반복을 목록 안에서 바로 고친다(콘텐츠 자동 발행 작업 포함).
- **예약 목록**: 콘솔 예약은 '시각 바꾸기'·'취소'(초안으로), 자동 작업은 '편집'으로 위 편집 창을 연다.
  콘텐츠 예약은 채널 묶음이라 취소는 콘텐츠 탭에서.

## 바탕화면 아이콘

`~/Desktop/AX 발행 콘솔.app` 을 더블클릭하면 콘솔 서버를 확인(꺼져 있으면 켬)하고 Chrome 앱 창으로 연다.
USB256 이 없으면 알림만 띄운다. 원본: `launcher/`(open_console.sh, launcher.applescript, AX.icns).
다시 만들기: `osacompile -o "AX 발행 콘솔.app" launcher.applescript` 후 `AX.icns` 를 `Contents/Resources/applet.icns` 로 복사.

## 오케스트레이터 (D1)

- 모든 launchd 작업(`run_*.sh` 맨 앞 한 줄)과 콘솔 자동 발행이 `shared/axlock.py` 의 잠금을 거친다.
  같은 크롬 프로필·하루 한도(`config/automations.json` 의 `locks`)를 쓰는 작업은 차례로 돈다(최대 40분 대기).
- **비상 정지**: 화면 위 버튼. 켜면 발행 작업이 새로 시작하지 않는다(돌던 작업은 끝까지). 유지보수·보고서는 계속 돈다.
- '자동 작업' 탭 맨 위에 실행 중·기다리는 작업과 기록(`data/logs/orchestrator.log`).

## 실패 대응 (D2)

- **감시기**(`app/watcher.py`, 모델 없음): 콘솔 서버가 10분마다 작업 로그의 실패 문구, 예정 시각에 안 돈 작업,
  launchd 에서 내려간 작업, 실패 스크린샷, 콘솔 작업 실패, 잠금 대기 초과, USB·디스크를 보고 '사건'으로 묶는다.
  글은 나가고 일부만 빠진 것은 경고. 사용자가 일부러 끈 작업(note)은 보지 않는다.
- **장애 탭**: 사건 목록·근거(로그 줄, 스크린샷)·원인 분석·해결/무시. 탭 이름에 열린 오류 수.
- **원인 분석 에이전트**(`app/agents/incident.py`): 읽기 도구만(로그·작업 상태·프로세스·계정 상태·스크린샷·코드·
  가린 설정·해결법 모음·git). 기본은 사건마다 [원인 분석] 버튼, 설정 탭에서 자동으로 켤 수 있다.
  해결법 모음: `config/known_issues.json`.

## 진행 상황 (2026-10-18)

설계 문서(`docs/설계.md`)의 단계 기준.

| 단계 | 상태 |
|---|---|
| 0 계정 연결 | 완료 — 구글 토큰 확인·재로그인, 네이버·카카오·Netlify 표시, GitHub 전환 |
| 1 읽기 전용 콘솔 | 완료 — 자동 작업·예약 목록·대시보드 |
| 2 예약 관리 | 완료 — 콘솔 자체 예약(입력·수정·예약·지금 실행·기록), 자동 작업 탭의 launchd 켜기/끄기(bootout·disable / enable·bootstrap)·지금 실행(kickstart, 발행 작업은 "실제로 발행됩니다" 확인)·최근 로그 보기. 제어 대상은 config/automations.json 의 작업만, 콘솔 자신(axconsole)은 끌 수 없음. 일부러 끈 작업(note·reenable)은 켤 때 사유를 다시 보여 준다. 제어 기록은 data/logs/launchd_control.log |
| 3 작성 스튜디오·승인함 | 완료 — 콘텐츠 탭: 기획 → AI 초안 → 검토·점검표 → 채널별 예약 → 발행 확인 (`docs/파이프라인.md`). 채널별 자동 발행: 블로거(학과·개인)·네이버(학과)·X(학과). 인스타는 카드 이미지가 필요해 직접 발행 |
| 4 영상 스튜디오 | 아직 |
| 5 성과 | 아직 (analytics 보고서는 기존대로 돈다) |

남은 확인 사항: 개인 네이버 계정 연결, surveymadang 의 `gh auth login`, 평문 키가 남은 config 백업 8개 정리.
