요청에서 결과 확인까지: AI 실습을 진행하는 방법

작성·갱신: 2026년 11월 11일 | 재난안전과 GeoAI

먼저 결과물을 한 가지로 정함

AI에게 학교 행사 안내 페이지를 요청할 때는 완성된 화면의 모습을 먼저 정하는 것이 도움이 됨. 예를 들어 방문자가 행사명, 활동 내용, 준비물을 확인하는 페이지라면 입력 자료와 표시 항목을 구분해야 함. 행사 일시가 제공되지 않았다면 AI가 임의의 날짜를 채우도록 두지 않고 ‘확인 필요’라고 표시하도록 요청함. 이렇게 하면 문장이 자연스러운지와 별개로 사실을 보존했는지 확인할 수 있음.

Claude Code와 Codex에서 실습할 때는 연습 폴더를 따로 만들고 현재 파일 목록부터 살펴봄. 기존 자료를 읽는 단계와 파일을 수정하는 단계를 나누면 변경 범위를 파악하기 쉬움. 두 도구의 설치 명령, 로그인 방식과 사용 가능한 기능은 달라질 수 있으므로 실습 당일에는 각 제품의 공식 안내를 확인함. 이 교재의 녹화 화면은 특정 시점의 화면과 기록이며 모든 버전의 동일한 동작을 보장하는 자료가 아님.

요청을 다섯 항목으로 점검함

  1. 목적과 대상: 누가 어떤 상황에서 사용할 결과물인지 적음
  2. 입력 자료: 제공한 파일과 확인한 출처를 지정함
  3. 필수 기능: 이번 실습에서 구현할 기능만 정함
  4. 제약 조건: 원본 보존, 미정 정보 표시, 수정 범위를 정함
  5. 확인 기준: 완료 여부를 실제로 판단할 방법을 적음

이 항목은 특정 제품에만 적용되는 명령어가 아니라 실습 요청을 정리하는 기준임. 도구가 지원하지 않는 기능까지 요청문에 적는다고 실행되는 것은 아니므로, 작업을 시작하기 전에 현재 환경에서 사용할 수 있는 기능과 준비가 필요한 기능을 구분함.

학습용 요청 예시

이 실습 폴더에 학교 행사 안내 페이지를 만들어줘.
행사명과 활동 내용은 제공한 자료만 사용해줘.
확인되지 않은 날짜와 장소는 ‘확인 필요’로 표시해줘.
기존 파일을 보존하고 새 파일의 실행 방법을 알려줘.
휴대전화에서 제목, 본문과 버튼이 잘리지 않는지 확인해줘.
실행하지 못한 검사는 미확인으로 표시해줘.

이 예시는 재사용할 수 있는 입력문이며, 실제 행사의 개최나 실습 성공을 뜻하지 않음. Prompt Master를 사용할 때도 같은 입력 자료를 제공하고, 우선 프롬프트만 작성하게 할지 곧바로 개발까지 실행하게 할지 명확히 구분함.

파일 생성과 기능 성공을 구분함

HTML 파일이 만들어졌다는 사실만으로 화면 확인까지 완료된 것은 아님. 파일 생성 → 브라우저 열기 → 주요 기능 조작 → 결과 기록의 순서로 확인함. 룰렛이라면 후보 추가, 후보 삭제, 실행, 결과 표시, 다시 실행을 각각 확인함. 지도라면 제공한 정류장과 화면의 이름·위치를 대조함. 자료가 없는 운행 시간을 AI가 생성한 경우에는 화면이 정상이어도 사실 검증을 통과한 것으로 보지 않음.

확인 기록에는 ‘확인한 동작’, ‘관찰한 결과’, ‘남은 문제’를 함께 적음. 단순히 ‘정상 작동’이라고만 쓰면 다음 사람이 무엇을 검증했는지 알기 어려움. 예를 들어 ‘다시 실행 버튼을 누른 뒤 새 결과가 표시됨’처럼 입력과 결과를 연결해 기록함. 프로그램을 실행하지 못했다면 코드 검토와 실제 실행을 구분하여 남김.

수정은 한 번에 한 조건부터 진행함

화면 색과 동작 규칙, 점수 계산을 한꺼번에 바꾸면 문제가 생겼을 때 원인을 찾기 어려움. 한 조건을 수정하고 관련 기능을 다시 확인하는 방식으로 범위를 좁힘. 수정 전 파일을 보존하고 변경 내용과 확인 결과를 함께 기록하면 보고서의 수행 과정 항목으로 활용할 수 있음. 확인하지 않은 학습 효과나 시간 절감 수치를 결과처럼 작성하지 않음.

도구 시작 방법은 Codex CLI 공식 안내와 Claude Code 공식 안내를 확인함. 교재 3~4단원과 7~8단원에서 관련 요청과 시연을 살펴볼 수 있음.
