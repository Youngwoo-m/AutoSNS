에이전트, 스킬, MCP와 플러그인의 역할을 구분함

작성·갱신: 2026년 11월 11일 | 재난안전과 GeoAI

목표를 수행하는 주체와 작업 지침을 구분함

에이전트는 사용자가 제시한 목표를 바탕으로 자료를 읽고, 작업 순서를 정하고, 허용된 도구를 사용해 결과를 만드는 실행 주체임. 예를 들어 게임의 오류를 수정하는 작업에서는 현재 코드를 읽고, 오류가 생기는 조건을 살펴보고, 수정 후 확인할 기능을 정함. 이 과정에서 어떤 파일을 바꿀 수 있는지와 외부로 무엇을 전송할 수 있는지는 작업 범위와 도구 권한에 따라 달라짐.

스킬은 특정 작업에 필요한 절차·규칙·지식을 담는 자료임. 프로젝트의 문서 양식을 보존하거나 보고서의 확인 항목을 점검하는 데 사용할 수 있음. 스킬 폴더가 있다는 사실과 에이전트가 그 지침을 실제 작업에 적용했다는 사실은 서로 다름. 설치를 확인할 때는 파일 경로, 이름, 설명과 적용 대상부터 확인함.

외부 연결과 배포 단위를 구분함

MCP는 AI 애플리케이션이 외부 도구와 자료를 연결해 사용하는 표준 규약임. 연결된 서버가 제공하는 기능과 허용된 권한에 따라 데이터 조회나 작업 실행이 가능해짐. MCP 자체가 모든 자료에 접근 권한을 부여하는 것은 아님. 서버가 응답하는지, 필요한 도구가 노출되는지, 실제 요청이 성공하는지를 차례로 확인해야 함. 규약의 구성은 MCP 공식 아키텍처 안내를 참고함.

플러그인은 여러 기능을 함께 설치하고 배포하는 묶음으로 이해할 수 있음. 다만 포함할 수 있는 구성요소와 지원 형식은 제품마다 다름. 스킬, 서버 설정이나 보조 기능이 함께 제공될 수 있지만, 한 제품용 패키지를 다른 제품에서도 그대로 설치할 수 있다고 가정하지 않음.

공용 설치와 제품별 설정을 나눔

이 교재에서 사용하는 공용 설치는 강의자의 PC 관리 방식임. 스킬 원본은 사용자 폴더의 .agents/skills에 두고, Claude 쪽에는 원본을 참조하는 연결을 구성함. 이 방식은 자료의 중복을 줄이기 위한 관리 규칙이며 제품이 자동으로 제공하는 공통 설치 기능을 뜻하지 않음. 다른 PC에서는 폴더와 연결 도구가 준비되어 있는지 먼저 확인해야 함.

플러그인은 제품별 등록 형식이 달라 각 제품에서 등록·인식 여부를 따로 확인함. MCP도 공용 목록을 관리하더라도 각 제품의 설정 파일에 반영되고 서버가 실행되는지 별도로 확인함. 설정 파일을 수정하기 전에는 백업을 만들고, 비밀키를 공개 목록이나 교육자료에 기록하지 않음. 학교 계정의 관리 정책이 있는 경우 그 범위 안에서 실습함.

서브에이전트와 훅을 사용하는 경우

서브에이전트는 분리된 범위의 보조 작업을 맡기는 실행 단위임. 게임의 요구사항 조사와 코드 점검을 나누는 데 활용할 수 있음. 같은 파일을 동시에 수정하게 하면 충돌할 수 있으므로 읽기 전용 조사, 수정 대상 파일과 결과 전달 방식을 먼저 정함. 현재 제품이나 환경에서 지원하지 않으면 같은 작업을 순서대로 진행함.

훅은 특정 사건에 연결해 정해진 작업을 실행하는 장치임. 파일 수정 뒤 형식 검사를 실행하는 절차가 예가 될 수 있음. 훅을 등록한 것과 검사가 성공한 것은 다르므로 실행 조건과 검사 결과를 확인함. 검사를 자동화해도 문서 내용의 사실성이나 저작권을 대신 판단해 주는 것은 아님. 훅의 구체적 설정 형식은 해당 제품의 공식 문서를 확인함.

세 단계로 확인함

  1. 존재 확인: 스킬 파일, 플러그인 등록과 서버 프로그램을 확인함
  2. 인식 확인: 새 세션에서 이름과 기능이 보이는지 확인함
  3. 실행 확인: 범위가 작은 읽기 전용 작업으로 실제 응답을 확인함
현재 환경의 스킬, MCP와 플러그인을 읽기 전용으로 확인해줘.
파일 존재, 앱의 인식, 실제 실행 결과를 구분해줘.
새 도구를 설치하거나 설정을 바꾸지 마.
접근할 수 없는 자료는 확인되지 않았다고 알려줘.

교재 5~6단원에서 개념과 요청 예시를 확인함. PLAYMCP의 목록 탐색은 도구를 찾는 단계이며, 계정 연결과 실제 도구 실행이 완료됐다는 증거로 해석하지 않음.
