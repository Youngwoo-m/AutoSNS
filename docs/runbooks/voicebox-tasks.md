# 로컬 Voicebox 음성 작업

Claude Max가 클라이언트·영속 작업 모듈·화면·기동 옵션을 분담 작성하고 Codex가 서버와 편집기 통합 및 시험을 담당했다. 기존 네 메뉴를 유지하며 저장한 원고 편집기에 접힌 **음성 제작** 패널을 배치한다.

## 실행 경계

- `LocalVoiceboxClient`는 이미 실행 중인 `127.0.0.1:17493` Voicebox만 사용한다. 앱 시작·종료, 외부 TTS, 유료 API 우회는 하지 않는다.
- 서버 기본값은 `voice_task_service=None`이다. 조회는 가능하지만 제작 요청은 비활성이다. 서버가 주입한 서비스와 콘텐츠 저장소는 같은 관리 작업공간이어야 한다.
- 생성 요청은 등록된 프로필, 한국어, qwen/0.6B로 고정한다. 브라우저는 프로필·호스트·파일 경로를 지정할 수 없다.
- 작업 완료는 WAV 제작과 콘텐츠 자산 등록만 의미한다. `review_status=not_checked`이며 검토·영상 렌더·발행 완료가 아니다.

## HTTP

모든 경로는 로그인과 기존 요청 출처 검사를 거친다.

| 요청 | 용도 |
|---|---|
| `GET /api/v2/voicebox/capabilities` | 서비스 주입·활성 여부. 실제 준비 상태를 조회하거나 합성하지 않음 |
| `GET /api/v2/contents/{id}/voice-tasks?revision=N` | 원고 버전별 작업 목록 |
| `POST /api/v2/contents/{id}/voice-tasks` | 정확히 `expected_revision`, `script`, `seed`를 받아 작업 생성 |
| `GET /api/v2/voice-tasks/{task_id}` | 저장된 상태 조회 |
| `POST /api/v2/voice-tasks/{task_id}/resume` | 빈 객체 `{}`로 기존 생성 ID의 결과 확인·WAV 등록 재개 |
| `POST /api/v2/voice-tasks/{task_id}/recovery-preview` | `generation_id` 한 건을 입력 원고·등록 음성과 대조. 합성·상태 변경 없음 |
| `POST /api/v2/voice-tasks/{task_id}/recover` | 대조한 `generation_id`, `recovery_fingerprint`로 명시 연결. 결과 확인은 별도 요청 |

## 중복과 중단

합성 POST 전에 작업 의도를 SQLite에 확정한다. 같은 계정·콘텐츠 버전·원고·시드·프로필 요청은 기존 작업을 반환한다. 생성 결과가 불명확하면 `unknown`으로 보존하고 POST를 자동 반복하지 않는다. 생성 ID를 받은 `pending` 작업은 GET으로만 확인한다.

WAV는 별도 보존 후 실측 길이(20초 이하)를 검사하며 입력 콘텐츠 버전에 CAS로 등록한다. 원본 버전은 보존한다. 등록 직후 프로세스가 중단되면 정확한 파일 해시·바이트와 단일 버전 증가를 대조해 기존 자산을 연결한다. 다른 편집이 끼어들면 `content_changed`로 보존한다.

생성 ID 없이 `started` 또는 `unknown`에 남은 작업은 자동 해제하지 않는다. **기존 음성 대조 → 대조한 음성 연결**로 사용자가 알고 있는 생성 ID 한 건만 연결한다. 서버가 원고 버전·소유 계정·대본·프로필·시드·언어·엔진·모델을 확인하며 같은 생성 ID가 다른 작업에 붙어 있으면 거부한다. 대조와 확정 사이 상태가 달라지면 fingerprint/CAS 검증으로 연결을 거부한다. 음성 원문이나 프로필 값은 복구 응답에 넣지 않는다.

합성 POST와 복구는 작업별 OS 파일 잠금을 공유한다. 같은 프로세스의 별도 fd와 별도 Python 프로세스 시험을 모두 통과했다. 복구가 먼저 연결하면 합성 직전에 최신 행을 다시 읽어 새 POST를 생략한다. 살아 있는 합성 작업이 잠금을 보유하면 복구가 끼어들지 않는다.

실제 로컬 클라이언트의 `resume`은 `poll_once()`로 상태 GET 한 번만 수행한다. 합성이 진행 중이면 대기하지 않고 `pending`을 유지한다. 기존 배치 렌더러용 `wait_completed()`는 유지한다.

## 화면과 기동

원고를 열 때는 기능 상태와 저장된 작업 목록만 조회한다. 대본은 자동 복사하지 않는다. **합성 요청**과 **결과 확인** 버튼이 각각 명시적 POST 한 번을 보낸다. 자동 폴링·재합성은 없다. 결과가 불명확하면 입력과 작업을 보존한다. **입력 버리기**는 요청하지 않은 대본·시드 변경만 버리며 저장된 작업을 지우지 않는다.

음성 대본이나 숏츠 계획이 미저장이면 다른 버전 변경 작업을 잠근다. 완료 시 새 버전이 있다는 안내를 표시하며 **최신 버전 열기**로 직접 이동한다. 화면 요청은 45초 제한을 두고 시간이 지나면 busy를 해제하지만 서버의 합성이 취소됐다고 단정하지 않는다.

`production_main.py`는 `--serve --enable-voicebox --voicebox-profile-id <등록된 ID>`를 명시해야만 음성 서비스를 주입한다. `--voicebox-port` 기본값은 17493이며 접속 주소는 항상 127.0.0.1이다. 텍스트 제작 옵션 `--enable-production`과 독립적이다. `--check`는 클라이언트 생성·준비 상태 확인·저장소 생성·합성을 하지 않는다. 옵션을 개발한 것이며 현재 8769 기동에는 음성 활성화 옵션을 넣지 않는다.

## 검증과 남은 연결

임시 저장소·가짜 전송으로 클라이언트, 영속 상태, 동시 요청, 중복 방지, 중단 복구, HTTP 인증·스키마·비공개 필드 제거를 시험했다. 실제 로컬 Voicebox 준비 상태는 이번 점검에서 연결되지 않았다. 앱을 자동으로 시작하거나 실제 음성을 합성하지 않았다.

화면은 브라우저 내부 가짜 응답으로 요청→대기→완료를 확인했다. 검증 이미지는 `ax-console/design/previews/voice-task-fixture.png`이며 실제 음성 제작 증거가 아니다.

실제 Voicebox history 응답 스키마는 아직 확인하지 못했다. 필요한 8개 필드가 없거나 입력 대조가 불확실하면 복구를 거부한다. 개발 시험과 브라우저 예시가 실제 서비스 복구 성공을 뜻하지 않는다.

남은 작업은 실제 Voicebox 응답·음성 품질 검증과 영상 제작 실행 연결이다. SNS 인증·발행 활성화와 분리해 진행한다.

## 설치본 0.5.0 계약 대조와 프로필 결속

2026-11-02 설치 앱 버전 0.5.0과 로컬 DB의 필드 이름을 읽기 전용으로 확인했다. 로컬 API는 연결을 거부하여 앱을 시작하거나 합성하지 않았다. 설치 바이너리의 CArchive/PYZ에서 코드를 실행하지 않고 생성·이력 handler 상수를 정적으로 대조했다. `/generate`와 history의 `generating`을 내부 `running`으로 정규화한다. 그 밖의 알 수 없는 상태는 계속 거부한다. 실제 API 전체 스키마·음성 품질이 검증됐다는 뜻은 아니다. 근거는 `docs/audits/2026-11-02-voicebox-installed-contract.json`과 readiness 보고서에 기록했다.

대기 중이거나 WAV 등록 전인 작업은 최초 원고·소유 계정·manifest와 프로필을 포함한 intent 해시가 현재 등록과 일치하는지 확인한 뒤에만 조회·등록한다. 프로필 설정을 바꾼 채 과거 작업을 재개하면 409로 거부하고 작업·원고·자산을 변경하지 않는다. 완료 작업은 읽기 전용으로 계속 조회할 수 있다. DB schema 1을 유지하며 기존 intent 증거로 결속을 검증한다.

현재 음성 기동은 글로벌 프로필 하나를 개인·학과에서 공유한다. 원고 소유권은 계정별로 보존하지만 계정별로 다른 목소리를 선택하는 설정은 아직 구현하지 않았다. 후속 계정별 제작 설정과 실제 서비스 수락에 포함한다.
