# 로컬 Voicebox 음성 작업

Claude Max가 클라이언트와 영속 작업 모듈을 분담 작성하고 Codex가 서버 통합과 시험을 담당했다. 이 단계는 음성 제작 백엔드이며 웹 편집기의 실행 버튼과 명시적 기동 옵션은 후속 작업이다.

## 실행 경계

- `LocalVoiceboxClient`는 이미 실행 중인 `127.0.0.1:17493` Voicebox만 사용한다. 앱 시작·종료, 외부 TTS, 유료 API 우회는 하지 않는다.
- 서버 기본값은 `voice_task_service=None`이다. 조회는 가능하지만 제작 요청은 비활성이다. 서버가 주입한 서비스와 콘텐츠 저장소는 같은 관리 작업공간이어야 한다.
- 생성 요청은 등록된 프로필, 한국어, qwen/0.6B로 고정한다. 브라우저는 프로필·호스트·파일 경로를 지정할 수 없다.
- 작업 완료는 WAV 제작과 콘텐츠 자산 등록만 의미한다. `review_status=not_checked`이며 검토·영상 렌더·발행 완료가 아니다.

## HTTP

모든 경로는 로그인과 기존 요청 출처 검사를 거친다.

| 요청 | 용도 |
|---|---|
| `GET /api/v2/voicebox/capabilities` | 서비스 주입·활성 여부. 실제 준비 상태를 조회하거나 합성하지 않음 |
| `GET /api/v2/contents/{id}/voice-tasks?revision=N` | 원고 버전별 작업 목록 |
| `POST /api/v2/contents/{id}/voice-tasks` | 정확히 `expected_revision`, `script`, `seed`를 받아 작업 생성 |
| `GET /api/v2/voice-tasks/{task_id}` | 저장된 상태 조회 |
| `POST /api/v2/voice-tasks/{task_id}/resume` | 빈 객체 `{}`로 기존 생성 ID의 결과 확인·WAV 등록 재개 |

## 중복과 중단

합성 POST 전에 작업 의도를 SQLite에 확정한다. 같은 계정·콘텐츠 버전·원고·시드·프로필 요청은 기존 작업을 반환한다. 생성 결과가 불명확하면 `unknown`으로 보존하고 POST를 자동 반복하지 않는다. 생성 ID를 받은 `pending` 작업은 GET으로만 확인한다.

WAV는 별도 보존 후 실측 길이(20초 이하)를 검사하며 입력 콘텐츠 버전에 CAS로 등록한다. 원본 버전은 보존한다. 등록 직후 프로세스가 중단되면 정확한 파일 해시·바이트와 단일 버전 증가를 대조해 기존 자산을 연결한다. 다른 편집이 끼어들면 `content_changed`로 보존한다.

생성 ID 없이 `started` 또는 `unknown`에 남은 작업은 자동 해제하지 않는다. 수동 대조·복구 화면은 아직 없다. `resume`의 준비 상태 확인은 동기 방식이므로 사용자용 실행 화면을 연결하기 전에 장시간 요청 처리를 보완해야 한다.

## 검증과 남은 연결

임시 저장소·가짜 전송으로 클라이언트, 영속 상태, 동시 요청, 중복 방지, 중단 복구, HTTP 인증·스키마·비공개 필드 제거를 시험했다. 실제 로컬 Voicebox 준비 상태는 이번 점검에서 연결되지 않았다. 앱을 자동으로 시작하거나 실제 음성을 합성하지 않았다.

다음 작업은 기존 네 메뉴 안의 음성 작업 UI, 명시적 활성화 설정, 장시간 확인 처리, 실제 Voicebox 응답과 음성 품질 검증이다. SNS 인증·발행 활성화와 분리해 진행한다.
