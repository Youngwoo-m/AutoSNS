# TikTok 로컬 영상·캡션 준비

현재 기능은 저장된 계획의 영상·캡션 준비와 명시 기술 검사다. TikTok API 전송·로그인·게시·대기열 실행·공개 검증을 수행하지 않는다. 기존 `tiktok.queue` 중지는 유지한다. 최종 게시 방식을 사용자에게 질문했으며 답변 전에는 직접 게시나 Inbox Upload를 활성화하지 않는다.

TikTok 공식 지침은 본인·팀 계정용 내부 업로드 도구를 Direct Post 부적합 사례로 명시한다. 따라서 현재 AutoSNS가 심사로 자동 공개 게시를 허용받는다고 전제하지 않는다. Inbox Upload도 앱 승인과 별도 동의가 필요한 다른 경로이며 우회로로 취급하지 않는다. [공식 공유 지침](https://developers.tiktok.com/docs/en/content-sharing-guidelines)

## 사용

개인/학과 콘텐츠 발행 메뉴에서 원고에 MP4 자산을 등록하고, 실제 TikTok 연결의 새 계획에서 영상 하나를 직접 선택한다. 기본 선택·변환·요약·자동 해시태그 추가는 없다. TikTok 변환본이 유일하면 이를, 없으면 원문을 보존하며 캡션은 2200 UTF-16 단위를 검사한다. 계획의 일반 visibility는 TikTok의 실제 공개 범위나 사용자 동의를 대신하지 않는다.

저장한 계획의 ‘TikTok 영상·캡션 준비’를 펼치면 현재 원본 버전·manifest·실제 자산 바이트를 대조한 구성과 인증된 다운로드 링크를 보여 준다. 선택하지 않은 과거 계획은 보존하고 새 계획 저장을 안내한다. 과거 계획·원본을 자동 수정하거나 취소하지 않는다.

‘이번 영상 기술 검사’는 준비 해시와 실제 바이트를 다시 확인한 뒤에만 등록된 로컬 ffprobe를 실행한다. 다른 원고 버전·계획·registry 또는 검사 중 변경된 구성에는 결과를 붙이지 않는다. 결과는 이번 요청의 관측이며 영구 승인으로 저장되지 않는다. 다시 조회하면 검사 결과는 비운다. 실제 게시 가능 길이·음악 권리·현재 계정의 공개 범위·TikTok 수락은 별도다.

## 검사 도구 기동

`production_main.py --serve`에 `--tiktok-ffprobe /신뢰된/절대/경로/ffprobe`를 명시한다. 기존 `--source-root`, 별도 `--workspace-root`, 로컬 host/port 및 로컬 도구 옵션을 유지한다. 이 옵션은 서버 시작이나 GET에서 ffprobe를 실행하지 않고 사용자 검사 요청에만 연결한다. `--check`는 경로 형식만 검사하며 native 실행·원격 호출·할당량 변경이 없다.

검사기는 비공개 임시 파일·최소 환경·고정 인자와 파일 프로토콜/mov demuxer 제한, 15초·64KiB 출력 제한을 쓴다. 임시 파일은 종료 시 정리한다. 현재 자산 상한 100MiB, 영상 360~4096픽셀·23~60fps·h264/hevc/vp8/vp9·최대10분을 로컬 준비 범위로 확인하며 실제 creator 제한을 추정하지 않는다. 오디오는 관측한 코덱명만 표시한다. ffprobe의 mov/mp4 공용 demuxer 관측만으로 모든 MP4/MOV 브랜드의 구별이나 장면 품질을 보증하지 않는다.

실제 기존 GeoAI MP4를 원본 수정 없이 임시 ContentStore/Ledger와 실제 ffprobe로 검사했다. 1080×1920, 30fps, 32057ms, h264/aac로 관측됐고 원본 및 저장 자산의 바이트가 그대로였다. 설치 버전이 빈 `programs`, `stream_groups`를 추가 출력하여 처음 검사에 실패했고, 이 두 빈 목록만 추가 허용해 수정·회귀시험했다. 다른 알 수 없는 출력은 계속 거부한다.

현재 8769는 제작 application 기동 경로와 `/usr/local/bin/ffprobe` 등록을 사용한다. 제작·음성·영상 렌더·이미지·성과 수집·SNS 발행·외부 접속은 켜지 않았다. 기동 전 코드와 관리 DB 백업은 `ax-console/data/deployment-backups/tiktok-preparation-3ac0135*`에 있다. 이 변경에서는 원본 운영 루트의 키·브라우저·스케줄을 수정하지 않았다.

## 남은 범위

사용자가 선택할 최종 게시 방식, 실제 TikTok 결과의 공개 확인·계정 결속·성과 수집이 남아 있다. Direct Post나 Inbox Upload를 추가하려면 실제 앱 적합성·권한·최신 creator 정보·사용자 공개 범위 선택·상호작용/상업 콘텐츠 설정·명시 동의와 실전 수락을 별도로 확인한다. 외부 접속·다른 SNS 실계정 연결·제작 품질·자료 이행·전체 종합 수락도 계속 필수다.
