# 이미지 재사용 수동 확인

저장 원고 편집기의 **이미지 재사용 확인**에서 이미지별 사용 권리·허락과 내용·문자·도해를 사람이 확인해 저장한다. AI 검사 결과나 자동 승인이 아니다. 이미지를 올리거나 계획에 선택하는 것만으로 승인하지 않는다. 체크를 해제해 저장하면 철회 기록을 남긴다.

확인 기록은 소유 계정·콘텐츠·자산 ID·실제 이미지 해시에 연결한다. 같은 이미지가 새 원고 버전에 유지되면 기존 기록을 활용한다. 이미지가 바뀌거나 다른 계정·콘텐츠에 등록되면 새 확인이 필요하다. 과거 원고 조회에서도 같은 이미지의 최신 확인·철회 상태를 표시하고 확인 당시 버전을 구분한다.

`reuse-approvals.sqlite3`는 명시 초기화 때만 생성한다. 기록은 추가만 가능하며 수정·삭제를 막는 DB 트리거를 둔다. 저장은 확인 기록 버전으로 CAS 검사하고 원고 현재 버전도 확인한다. 기록자·소유 계정·해시는 서버가 결속한다. 원고 버전이나 자산 바이트를 변경하지 않는다.

`GET /api/v2/contents/{id}/reuse-approvals?revision=N`은 현재 이미지 상태만 읽는다. 같은 경로의 POST는 `asset_id`, `expected_revision`, `rights_confirmed`, `visual_checked`, `notes`만 받는다. 로그인·요청 출처·정확한 필드 검사를 적용한다. 미저장 입력은 다른 제작과 원고 버전 변경을 잠그며 충돌·응답 오류에도 보존한다.

`ManagedReuseAuthorizer`는 불변 원고의 실제 이미지 바이트, 최신 수동 확인, 선택된 장면, 원고·계획 해시를 다시 대조한다. HTTP나 모델이 준 파일 경로를 읽지 않는다. 미승인 이미지는 대기열 등록 전에 거부하므로 승인 후 같은 계획으로 다시 요청할 수 있다. 제작기 실행 전과 영상 검토·결과 등록 직전에 확인을 다시 수행한다. 렌더 중 철회됐다면 등록을 멈추고 파일을 보존하며, 재확인 후 명시 재개는 재렌더하지 않는다.

확인 패널은 기존 네 메뉴 안의 하위 패널이다. 실제 영상 제작·SNS 발행을 자동 활성화하지 않는다. 검증은 가짜 제작 leaf와 임시 HTTP·DOM 시험으로 진행하며 브라우저 시험 로그인은 사용하지 않는다.
