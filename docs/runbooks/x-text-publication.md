# X 텍스트 발행

개인·학과 namespace의 X 텍스트 게시 기반을 구현했다. 현재 관리 연결은 학과 X 하나이고 대상 ID·인증·실제 실행은 미확인/비활성이다. 새 개인 X 계정이나 대상 ID를 임의 생성하지 않는다. 실제 앱·사용자 문맥·권한·비용·native 등록·공개 probe·실계정 수락은 완료하지 않았다. 이미지·영상 업로드와 실성과 수집도 후속 필수 범위다.

## 계획과 원문

실제 등록 연결의 `text_only` 기능을 명시 선택한다. 원고에 이미지·영상이 있어도 이 선택으로 텍스트만 준비하며 원본 자산을 삭제하지 않는다. 목적지 계정·X 전용 변환본이 유일하면 이를 쓰고, 없으면 원문을 그대로 쓴다. 자동 잘라내기·요약·해시태그 추가·URL 변경은 하지 않는다.

길이 검사는 고정 공식 twitter-text v3 자료로 검증한 오프라인 포트를 사용한다. 계산에만 NFC와 URL·emoji 가중치를 적용하며 반환 원문·공백·줄바꿈은 보존한다. 포트·공식 twemoji 정규식·공식 테스트 자료의 버전, 해시, 라이선스는 `common/publishers/vendor/twitter_text/`와 `tests/fixtures/x-twitter-text/`에 있다. 공식 가중치 44건·URL/TLD 1,682건을 대조했다. 이는 실제 최신 API의 모든 문자열 수락을 보증하지 않으며 라이브 수락 시 최신 계약과 추가 Unicode 사례를 확인한다.

관리 registry의 학과 X에 계획용 `text_only` 기능을 추가하고 revision을 `2026-11-04-x-text-plan-1`로 갱신했다. 기존 관리 계획의 승인은 이전 registry 문맥이므로 현재 문맥에서 재확인이 필요할 수 있다. 실제 연결 활성화·대상·자격·작업 스케줄·기존 교차 경로는 바꾸지 않았다.

## 비용과 전송

`XApiClient`는 OAuth2 사용자 문맥의 `/2/users/me`, 단일 게시 생성, 알려진 게시 ID 읽기만 사용한다. `XHttpsTransport`는 `api.x.com:443`, 기본 TLS 검증과 30초 제한, 1MiB 응답 한도를 사용한다. 환경 proxy·redirect·재시도·대체 계정·목록 검색은 하지 않는다. 전송 활성화와 비용 허가 둘 다 명시되어야 하며 기본은 차단이다.

서비스의 비용 허가도 별도로 기본 거부한다. 자기 계정 조회·게시 읽기·쓰기·공개 probe 전에 검사한다. 이미 제출된 영속 결과의 재생은 API 호출 없이 반환할 수 있다. 사용자 프로필의 ID와 게시 대상이 일치하고 공개 계정임을 확인하며, 이 관측 자체를 익명 공개 증거로 쓰지 않는다. 새 관리 OAuth의 publication 검증은 기존 정책대로 계속 차단한다.

공식 계약 근거: [게시 생성](https://docs.x.com/x-api/posts/create-post), [자기 계정](https://docs.x.com/x-api/users/get-my-user), [단일 게시 조회](https://docs.x.com/x-api/posts/get-post-by-id), [OAuth2 사용자 인증](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code), [공식 twitter-text](https://github.com/twitter/twitter-text). 실제 비용은 현재 앱 계약에서 확인하기 전 허가하지 않는다.

## 중복 방지·검증·복구

별도 `x-submissions.sqlite3`는 명시 초기화하며 논리 의도와 전체 준비물 해시를 결속한다. POST 전 시작을 기록한다. 시작 후 응답이 불명확하거나 원격 게시 ID를 저장하는 중 실패하면 unknown으로 두고 자동 재게시하지 않는다. 응답에서 이미 얻은 ID는 상위 실행 원장으로 보존하여 알려진 ID의 읽기 복구에만 쓴다. POST 이전 정지·비용 차단은 실제 미전송으로 구분하며 새 명시 허가에서만 재개한다.

소유자 API가 t.co로 반환한 텍스트는 실제 URL 엔터티 구간·확장 URL과 승인 전체 원문이 정확히 일치할 때만 대응을 인정한다. 원격 텍스트 해시와 승인 원문 해시는 별도로 보존한다. 쿼리 제거·추정 복원·redirect 조회는 하지 않는다. 엔터티 인덱스 단위가 명시되지 않은 경우 codepoint/UTF-16 후보 각각에서 실제 구간과 전체 원문 일치를 함께 요구한다. 모호하거나 일치하지 않으면 대기한다.

최종 공개 확인에는 별도 신선한 익명 관측과 게시 ID·작성자·본문·URL의 정확한 결속이 필요하다. 기본 probe는 없으므로 소유자 읽기에 성공해도 공개 완료가 되지 않는다. remote ID가 없으면 최근 글을 검색해 추정 연결하거나 재게시하지 않는다. 실제 공개 probe와 운영 bootstrap, 최종 실발행 수락이 남아 있다.
