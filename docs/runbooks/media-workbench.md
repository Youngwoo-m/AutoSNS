# 원고 버전별 숏츠 제작 계획

저장된 관리 원고 편집기의 ‘숏츠 제작 계획’에서 등록 이미지, WAV 음성, 장면 제목·자막·길이와 고지 문구를 편집한다. 계획은 접힌 패널이며 상위 메뉴는 기존 4개를 유지한다. 원고를 먼저 저장하고 이미지·WAV 자산을 등록해야 선택할 수 있다.

## 저장 계약
`GET/POST /api/v2/contents/{id}/media-plan?revision=N`으로 조회·저장한다. POST는 `expected_revision`과 `plan`만 받고 owner·manifest·경로·실행 명령은 받지 않는다. 서버가 원고의 소유 계정·revision·manifest hash를 결속하며 계획 자체의 CAS revision으로 충돌을 막는다. 별도 `media-plans.sqlite3`를 명시 초기화 이후에만 저장한다.

원고 버전이 바뀌면 새 계획은 기본값으로 시작하고 이전 계획은 보존한다. 미저장 계획은 원본 저장·자산 추가·버전 전환을 잠그며, 계획 저장은 계속 가능하다. 401/409는 입력을 보존한다.

계획은 최대 20초, 디오라마 장면 2~3개와 서로 다른 디오라마 이미지 2~3개, 등록된 WAV를 입력 조건으로 삼는다. 미완성 계획도 저장할 수 있고 부족한 입력을 표시한다. 입력 준비는 이미지 실제 내용·음성 실측·재사용 승인·검토 완료를 뜻하지 않는다.

## 등록 제작기 연결
`prepare_short_media`는 저장된 계획의 원고/계정/버전/hash를 대조하고 선택 자산을 `media-artifacts`의 새 시도 폴더에 복사한다. HTTP에서 경로를 받지 않으며 기존 원고·파일을 덮어쓰지 않는다.

`render_prepared_short`에 신뢰된 Remotion runner factory, 재사용 승인자, 실측/영상 검사기를 주입한다. 기본 등록은 없고 누락된 승인·검토를 만들어내지 않는다. 실제 렌더가 성공하고 기존 미디어 검증 계약을 통과한 결과만 `ingest_short_output`으로 CAS 등록할 수 있다. 원고가 바뀌었거나 이미 등록한 산출물을 반복 등록하려 하면 충돌로 거부한다. 검토 완료로 승격하지 않는다.

## 검증과 적용 상태
2026-11-02 8769에 계획 편집/저장 경로를 반영했다. 화면 회귀 276개, 서버·미디어 시험 53개 통과. 별도 임시 저장소의 브라우저에서 WAV와 서로 다른 두 이미지의 6초 계획 저장·입력 준비 판정을 확인했고 임시 서버/자료를 정리했다. 사용자 관리 저장소에 검증 원고를 만들지 않았다.

실제 Remotion 렌더와 Voicebox 합성은 이 화면에서 아직 실행하지 않는다. 실행 원장/worker와 실제 공급자 등록, 렌더 후 사람/독립 검사 증거의 수집은 후속 필수 범위다. 실제 발행·추가 API 결제는 연결하지 않았다.
