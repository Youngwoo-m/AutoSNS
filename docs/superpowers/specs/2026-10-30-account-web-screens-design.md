# 개인·학과 콘텐츠 운영 웹 — 화면 구성안

- 상태: 화면 검토용 초안. 사용자가 화면을 확정하기 전 제품 코드·운영 데이터에 적용하지 않는다.
- 사용자 목표: 개인계정·학과계정의 여러 콘텐츠를 계획하고 채널별 교차 발행까지 운영하는 웹 프로그램.
- 선행 결정: 현재 교차 게시 유지. 실행 규칙 통일 후 폴더·데이터 분리. 독립 작업은 최대한 병렬화.
- 이번 산출물: 8개 메뉴의 화면 구조, 상호작용 가능한 시안, 화면 수락 기준, 승인 후 개발 단계.
- [기존 승인 운영 설계](2026-10-30-account-channel-automation-design.md)와 [실행 계획](../plans/2026-10-30-account-channel-automation.md)을 기반으로 하되 화면을 먼저 확정한다.
- [시안 HTML](../../../ax-console/design/account-operations-v2.html)은 예시 데이터만 사용한다. 시안의 저장·정지·발행 버튼은 실제 작업을 호출하지 않는다.

## 1. 제품의 기준

운영자는 계정마다 흩어진 스크립트를 찾는 대신, 원본 콘텐츠와 그 콘텐츠에서 파생된 글·카드·숏츠·영상 및 채널별 배포를 관리한다. 업무는 기획 → 조사·원고 → 제작 → 검토 → 예약·발행 → 공개·내용 확인 → 성과로 이어진다.

기존 AX 콘솔의 계정 연결·로그인·잠금·예약·감시·발행기를 활용한다. 화면 전체를 기존 618줄짜리 index.html에 계속 붙이는 방식은 피하고, 화면별 렌더·상태·API 접근을 구분한다. 구체적 파일·인터페이스는 화면 승인 후 기존 실행 계획과 통합한다.

접속 범위는 사용자에게 질문 중이다. 시안은 Mac의 기존 로컬 콘솔을 바탕으로 하되 320px 모바일 폭에서도 사용할 수 있게 한다. 외부 접속을 선택하면 인증·접근 통제·로컬 제작/브라우저 워커 연결을 별도로 설계하며 서버를 바로 인터넷에 공개하지 않는다.

## 2. 공통 화면 틀

- 왼쪽: 업무 중심 단일 메뉴. 계정을 바꿔도 메뉴 순서와 위치가 달라지지 않는다.
- 상단: 전체 / 학과 / 개인 조회 필터, 현재 화면, 검색 또는 기간, 새 기획.
- 본문: 현재 업무의 핵심 목록·달력·보드와 필요한 조치.
- 상세: 선택한 콘텐츠·배포·문제를 오른쪽 패널 또는 모바일 전체 화면으로 연다.
- 전역 제어: 전체 발행 정지의 상태·범위를 눈에 띄게 표시한다. 실제 제어는 인증·영향 확인을 거친다.
- 시안 안내: 모든 화면에서 '화면 검토용 · 예시 데이터 · 실제 발행과 연결되지 않습니다'가 보인다.

상단 필터는 조회만 바꾼다. 기존 콘텐츠의 소유 계정이나 게시 대상을 변경하지 않는다. 개인 원본→학과 채널 교차 게시가 두 계정 보기에서 모두 발견되도록 기본은 '관련 계정 기준'이다. 콘텐츠 목록의 소유자 필터와 배포 목록의 게시 대상 필터는 별도로 명명한다.

## 3. 메뉴와 정보 구조

| 메뉴 | 주된 질문 | 내용·주요 행동 |
|---|---|---|
| 오늘 운영 | 오늘 무엇을 내보내고 무엇을 처리해야 하나? | 예정·공개 확인·검토 필요·문제, 계정별 일정, 조치 필요, 새 기획 |
| 콘텐츠 기획 | 무엇을 언제 어떤 형식으로 만들까? | 아이디어→조사·원고→제작→검토 보드, 시리즈·주제·담당·목표 채널 |
| 콘텐츠 보관함 | 원본·변환본·미디어를 어디서 찾나? | 글/카드/숏츠/영상 검색, 계정·시리즈·상태 필터, 콘텐츠 상세 |
| 예약 캘린더 | 어느 채널에 언제 공개되나? | 대상별 배포 일정, 월/주/목록, 한국시간, 제작 회차 보조 레이어 |
| 교차 발행 | 원본이 어디에 어떤 규칙으로 이어지나? | 기존 규칙과 실제 배포 탭, 출발/도착 계정, 지연·간격·변환·활성 상태 |
| 채널·계정 | 연결과 실제 게시 대상이 맞나? | 학과·개인별 채널, 인증·기능 지원·운영 활성·최근 성공 구분, 로그인 도움 |
| 성과 | 어떤 콘텐츠와 채널이 효과적이었나? | 원본→배포별 성과, 기간·계정·채널 비교, 다음 기획에 반영 |
| 장애·설정 | 왜 멈췄고 무엇을 해야 하나? | 조치 필요 / 실행 기록 / 운영 정책 / 시스템 설정 하위 구분 |

브라우저는 별도 최상위 메뉴 대신 채널 연결·로그인 필요·잠금 문제의 문맥에서 연다. 원래 사용자가 연 로그인 창을 강제로 종료하는 행동은 기본으로 제공하지 않는다.

## 4. 화면별 구성

### 오늘 운영

상단 요약은 '공개·내용 확인 완료', '예약·대기', '검토 필요', '조치 필요'다. 콘텐츠 수와 채널 배포 수를 섞지 않고 각각 단위를 쓴다. 예를 들어 원본 5건이 채널 8곳으로 나가면 '콘텐츠 5건 / 채널 게시 8건'으로 표현한다.

주 영역은 오늘 일정이며 행마다 시각, 원본 제목, 소유 계정, 게시 대상 계정·채널, 상태, 다음 행동을 둔다. 보조 영역은 검토함·조치 필요·채널 연결 요약이다. 첫 화면에서 모든 로그·시스템 설정을 펼치지 않는다.

### 콘텐츠 기획

기획 보드는 아이디어 / 조사·원고 / 제작 / 검토 네 단계다. 예약·게시 일정은 캘린더와 콘텐츠 상세에서 관리한다. 카드에는 제목·소유 계정·형식·시리즈·담당/자동 실행·목표 채널·막힌 이유만 표시한다.

새 기획 입력은 소유 계정, 주제, 목적/대상 독자, 형식, 목표 시각, 대상 채널, 참고 자료다. 전체 보기에서 생성할 때도 계정을 명시적으로 선택한다. 원본 계정은 저장 후 조용히 바뀌지 않는다. AI 제안에는 왜 지금·근거·중복 확인·채택/반려 이유를 유지한다.

### 콘텐츠 보관함과 상세

보관함은 생성 단계와 무관하게 콘텐츠를 찾는 곳이다. 제목 검색, 소유 계정, 형식, 시리즈, 기간, 상태 필터를 제공한다. 실제 미디어 없는 예시 카드에 썸네일이 존재한다고 표시하지 않는다.

상세 상단은 원본 제목·소유 계정·버전·원본 제작/검토 상태다. 탭은 개요 / 원고·채널 변환본 / 이미지·영상 / 검토·출처 / 채널별 배포 / 실행 이력이다. 편집 중 버전과 승인 버전을 구분한다.

채널별 배포 행은 대상 계정·채널·실제 연결, 변환본 버전, 공개 예정 시각, 예약 출처, 현재 상태, 마지막 확인, 공개 주소, 다음 행동을 가진다. 원본 하나에 여러 배포가 붙으며 한 채널 실패 때문에 원본 전체를 실패로 바꾸지 않는다.

### 예약 캘린더

기본 표시 단위는 채널별 공개 예정이다. 기획·제작·후처리 자동 실행은 보조 레이어다. YouTube 원격 예약과 콘솔이 나중에 실행할 로컬 예약을 다른 배지로 표시한다.

시간 변경은 달력의 이동만으로 즉시 실제 예약을 바꾸지 않고 영향 확인을 거친다. 로컬 실행 시각만 바뀌는지 플랫폼 예약도 바뀌는지, 승인 재검토와 교차 게시 지연에 어떤 영향이 있는지 보여 준다. 모바일에서는 일자별 목록으로 전환한다.

### 교차 발행

규칙 탭: 원본 계정·채널 → 대상 계정·채널, 트리거·시점·간격, 변환, AI 고지, 활성/중지 상태를 표시한다. 실적 탭: 이 규칙으로 생성된 실제 배포의 현재 상태·원본·게시 주소를 보여 준다.

기존 개인 숏츠→학과 TikTok, 개인 GeoAI 저녁→학과 Threads, 학과 채용정보→개인 Tistory, 개인 Tistory→개인 네이버 및 기준선에서 확인한 추가 경로를 보존한다. 등록부 도입을 이유로 경로를 줄이거나 꺼진 작업을 켜지 않는다. 규칙 수정은 이미 승인·예약된 배포를 조용히 바꾸지 않는다.

### 채널·계정

계정별로 실제 대상·연결 상태·기능 지원·자동 운영 활성·최근 성공·확인 시각을 분리한다. '구현됐지만 인증 미확인', '정상 연결됐지만 사용자가 중지함'이 가능해야 한다.

키·토큰 값은 화면에 표시하지 않는다. 연결·재인증·로그아웃은 영향을 받는 작업과 계정을 표시한다. 개인정보·계정 설정은 시안에 실제 값을 넣지 않는다.

### 성과

원본 제작 성과와 대상 채널 실적을 구분한다. 개인 원본이 학과 TikTok으로 배포됐다면 원본에는 연관 성과로 묶고, 채널 성과는 학과에 귀속한다. 제작비는 원본 소유 계정, 발행량은 대상 계정으로 구분한다.

실제 0·조회 오류·미지원·아직 수집하지 않음을 구분하며 샘플 차트를 실시간 수집 결과로 표시하지 않는다. 다음 기획 제안과 연결하되 자동 채택 정책을 확대하지 않는다.

### 장애·설정

조치 필요는 원인·영향 계정/채널·막힌 회차·해결 행동·확인 시각을 우선 표시한다. 실행 기록은 준비·발행·검증·후처리를 구분한다. 운영 정책과 기술 설정은 별도 하위 탭으로 분리한다.

실패한 채널만 재처리할 수 있어야 하며 결과 불명은 '외부 결과 확인'이 첫 행동이다. 기존 게시물 연결, 미게시 확인 후 재시도 허용, 로컬 요청 취소를 구분한다. 계정·채널 일시 중지와 전체 발행 정지의 범위를 명확히 쓴다.

## 5. 상태와 숫자 표현

| 시스템 상황 | 사용자 표시 | 잘못된 표현 |
|---|---|---|
| 업로드만 완료·공개 시각 없음 | 업로드됨 · 비공개 | 예약됨·발행 완료 |
| 플랫폼의 원격 예약 확인됨 | 예약됨 · 오늘 19:00 공개 예정 | 발행 완료·검증 완료 |
| 실제 공개 확인 | 공개됨 | 내용 확인까지 완료됐다고 추정 |
| 대상·본문·미디어까지 확인 | 공개·내용 확인 완료 | 종료 코드 0만으로 완료 |
| 정상 실행·조건 미충족 | 이번 회차 게시 대상 없음 | 실패·미실행 |
| 일부 성공·일부 실패 | 3개 중 2개 완료 · 1개 조치 필요 | 전체 실패 또는 전체 완료 |
| 응답 유실 | 게시됐을 수 있어 확인 필요 | 미게시로 간주하고 다시 게시 |
| 사용자가 중지 | 사용자가 중지함 | 장애 |
| 인증 키 복구 | 인증 재확인 성공 · 발행은 미완료 | 기존 실패 콘텐츠 자동 완료 |
| 구독 한도 | AI 사용 한도로 중단 · 확인된 해제 안내 | 시각 도달만으로 정상·완료 |
| 브라우저 점유 | 로그인 브라우저 사용 중 · 대기 | 자동화 잔류라고 추정·강제 종료 |

모든 상태는 글자·보조 설명으로 구분하고 색에만 의존하지 않는다. 공개 여부와 내용 검증 여부는 상세에서 각각 확인할 수 있다. 마지막 갱신·조회 실패·불확실성을 숨기지 않는다.

## 6. 시각·접근성 기준

- 밝고 차분한 배경, 네이비 본문, 인디고 주요 행동. 학과와 개인은 색+명칭을 함께 쓴다.
- 모든 화면을 카드로 채우지 않고 목록·표·여백으로 계층을 만든다. 기본 본문 14~16px, 중요한 상태는 읽기 쉬운 크기.
- 데스크톱 좌측 메뉴·오른쪽 상세, 모바일은 메뉴 압축·한 열·전체 상세. 320px 폭에서 가로 전체 넘침이 없어야 한다.
- 버튼·필터·탭은 키보드로 접근 가능하고 선택 상태·닫기·Escape·포커스 이동을 제공한다.
- 실제 저장·발행·재시도·정지는 승인된 백엔드 연결 이후에만 가능하다. 시안의 행동은 검토용 안내만 표시한다.

## 7. 화면 수락 시나리오

1. 전체→학과→개인 필터를 바꿔도 메뉴와 원본 소유권은 그대로이며 해당 계정과 관련된 교차 배포를 찾는다.
2. 개인 콘텐츠 상세에서 개인 YouTube 예약과 학과 TikTok 대기를 동시에 구분한다.
3. 19시 예약된 영상은 공개 전 공개 완료 숫자에 포함되지 않는다.
4. Blogger 성공·네이버 실패인 콘텐츠에서 성공한 원본을 다시 만들지 않고 실패 대상만 연다.
5. 결과 불명은 재게시보다 외부 결과 확인을 먼저 제시한다.
6. 사용자가 중지한 작업과 인증·한도 오류를 구분한다.
7. 기획 보드에서 원고·미디어·검토로 이어지고 보관함에서 같은 콘텐츠를 검색한다.
8. 320px와 넓은 데스크톱에서 필터·채널 상태·상세 패널이 겹치거나 잘리지 않는다.
9. 키보드만으로 메뉴·필터·콘텐츠 상세를 열고 닫는다.
10. 모든 시안 화면에서 예시 데이터·실제 미연결 상태를 확인한다.

## 8. 화면 확정 후 개발 순서

| 단계 | 결과 | 병렬화 |
|---|---|---|
| 1. 화면 틀·조회 | 공통 메뉴·필터·상태·상세, 실제 읽기 전용 조회 연결 | 공통 UI 계약 뒤 화면별 분담 |
| 2. 콘텐츠 기획·보관함 | 원본·버전·자산·검토·채널 변환 저장 | 원고/자산/검토 분리 |
| 3. 배포·예약·교차 발행 | 대상 연결·승인·회차·단일 실행 주인·일정 | 어댑터별 독립 작업 |
| 4. 운영·복구 | 잠금·STOP·한도·unknown·부분 재시도·공개 검증 | 원장·UI·검증 계약 후 분담 |
| 5. 성과·구조 이행 | 계정별 성과·기획 순환, 코드/설정/산출물 분리 | 성과 수집과 경로 분석 분리 |
| 6. 통합 검증·운영 적용 | 채널별 수락 증거와 롤백, 점진 전환 | 실제 프로필·DB·스케줄 전환은 직렬 |

이 순서는 기존 T1~T15 실행 계획을 화면 우선으로 통합하는 방향이다. 읽기 화면을 먼저 연결한다고 실행 원장·대상 검증·복구를 최종 범위에서 빼지 않는다. 실제 외부 접속·배포 방식은 접속 범위 답변과 화면 승인에 따라 정한다.

3단계의 예약·배포 기능은 저장·미리보기·가짜 어댑터 시험까지다. 실제 외부 쓰기 활성화는 4단계의 계정·대상 확인, 승인, 잠금·STOP·한도·응답 유실 복구를 통합 검증한 뒤 6단계의 대상별 운영 적용에서 수행한다. 화면이 먼저 완성됐다는 이유로 보호 장치 없이 게시를 연결하지 않는다.

## 9. 다음 사용자 결정

시안에서 메뉴 구성, 오늘 운영의 우선 정보, 콘텐츠 상세의 원본/대상 구분을 확인한 뒤 화면을 확정한다. 이후 기존 실행 계획을 최신 화면·접속 범위에 맞춰 갱신하고 단계별 개발을 시작한다. 현재 시안 저장만으로 제품 구현이나 화면 승인이 완료됐다고 판단하지 않는다.

## 10. 시안 검증 기록

- 3개 에이전트로 기존 UI 분석, 운영·복구 흐름 분석, 시안 작성을 병렬 진행하고 부모가 통합했다. 별도 검토자가 화면 설계의 모순을 확인했다.
- 실제 로컬 브라우저에서 8개 메뉴의 이동과 각 화면 제목, 전체/학과/개인 필터를 확인했다.
- 학과 필터에서 개인 원본→학과 배포가 유지되고 소유 계정은 바뀌지 않는 것을 확인했다. 필요 조치의 건수도 필터와 일치한다.
- 콘텐츠 상세에서 원본·대상 계정, 개인 YouTube 원격 예약, 학과 TikTok 로컬 대기열을 구분해 확인했다.
- 상세 패널 Escape 닫기, 열린 dialog 제거, 원래 콘텐츠 버튼으로 포커스 복귀를 확인했다.
- 기본 데스크톱 1280px와 모바일 320px에서 문서 폭과 뷰포트 폭이 동일하고 화면 전체 가로 넘침이 없음을 확인했다.
- JavaScript 문법 검사와 브라우저 콘솔 오류 검사를 통과했다. 시안에는 외부 네트워크 요청이나 실제 발행 연결이 없다.
- 데스크톱·캘린더·모바일 스크린샷은 로컬 검토 산출물이며 운영 자료가 아니다. 시안 숫자·날짜는 예시이고 실제 발행 실적이 아니다.

검증 범위는 시안의 화면·상호작용이다. 실제 계정·발행·복구·성과 시스템의 기능 시험 또는 운영 가동 완료 증거로 사용하지 않는다.
