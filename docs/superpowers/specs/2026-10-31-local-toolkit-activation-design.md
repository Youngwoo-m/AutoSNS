# 운영 웹 로컬 도구 활성화 설계 초안

상태: 제안, 사용자 승인 전. 기존 toolkit 구현·화면 배포는 완료했으나 main 정책은 disabled다. 전체 SNS 운영 목표를 이 활성화만으로 완료 처리하지 않는다.

## 목적과 선택지

추가 결제·외부 모델·원격 발행 없이 관리 원본의 제목/태그, 저장 근거 조사, CSV 미리보기/가져오기, 로컬 예약 상태 조회를 실제8769에서 사용한다. 사용자 순서 답변은 아직 없으며 다음 순서는 작성자의 제안이다.

A: 현재 Python3.15를 유지하고 명시 기동 옵션으로 로컬 정책만 활성화한다. 이미지 기능은 환경 미준비로 표시한다. 변경과 의존이 가장 작다. B: 기존 개인작업 Python3.12/Pillow 환경으로 서버를 실행하고 등록 폰트/renderer를 주입한다. 이미지 출력이 가능하지만 웹의 장기 실행이 개인작업 환경에 의존한다. C: 기본 비활성을 유지하고 SNS 인증부터 연결한다. 완성된 로컬 기능의 실제 사용이 늦어진다. **제안은 A 후 이미지 환경 별도 수락**이다. 사용자 선택으로 기록하지 않는다.

## 기동과 저장 계약

`AX_LOCAL_TOOLKIT` 명시 값 `1`일 때만 main이 ToolkitPolicy(enabled=True)를 주입한다. 미설정/0은 기존 비활성, 다른 값은 시작 전에 오류로 종료하여 오타를 조용히 허용하지 않는다. 활성에는 기존의 명시 AX_WORKSPACE_ROOT가 필요하다. 저장소 없는 읽기전용8767은 opt-in을 거부하며 원고/CSV 쓰기503 계약은 그대로다. HTTP body·선호 저장·페이지 열기로 정책을 바꿀 수 없다. factory 기본값은 계속 disabled다.

서버 content/metrics/runtime 동일 객체를 사용하고 기존 초기화·인증·Host/Origin·CAS·digest/receipt를 유지한다. 관리 원본만 분석 가능하며 legacy 원고는 기존 가져오기 절차를 따른다. 개인 원본·학과 변환문은 기존 등록 교차 경로와 불변 target이 있어야 한다. target 미확인을 임의 값으로 채우지 않는다.

## 변경하지 않는 권한

ExecutionService/ExecutionPolicy, SNS 인증·토큰 refresh, launchd, 원본R/8700, 프로필, STOP, quota, 비용 gate는 활성화하지 않는다. 추가 API/credit 소비0. CSV는 legacy_reported/미배정이며 검증 게시로 승격하지 않는다. 8769 로컬 도구 활성은 새 계정 연결이나 실제 발행 승인이 아니다.

## 이미지와 사용자 표시

A에서는 renderer/authorizer 미주입을 유지한다. Pillow 없는 이미지 검사와 썸네일은 unavailable을 표시한다. 환경 오류를 성공·0으로 바꾸지 않는다. 전체 자산을 무조건 승인하는 callback은 금지한다. 향후 이미지 없는 고정 썸네일은 별도 검증 환경에서, 이미지 재사용은 서버의 명시 승인 근거를 설계한 뒤 연결한다. 화면 메뉴는9개를 유지한다.

## 수락과 원복

미설정/0/1/오타 설정, 저장소 없는 opt-in, factory 기본disabled, paid/credits/unknown 차단, 최신revision·계정·변환문·교차target 검증, 실제실행 서비스 None을 시험한다. 기존 인증 아래 격리 HTTP에서 후보→명시variant 초안→CAS, CSV0/오류/중복,401/409/503 입력 보존을 확인한다. 실제8769에서는 기존 자료를 덮어쓰지 않고 가용상태·원격실행비활성만 확인한다.

적용 전 owned8769만 확인/정지/전체workspace백업 후 같은코드·환경에 AX_LOCAL_TOOLKIT=1을 추가한다.8767은 그대로다. 오류 시 옵션을 제거해 재시작한다. 새 사용자 CSV/원고를 과거DB로 덮어쓰지 않는다. 실제 이미지환경·SNS권한·실성과·발행·외부Mac/휴대폰·폴더이행은 필수 후속이다.
