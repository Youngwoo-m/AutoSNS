# 운영 웹 6A — 공통 실행 진입점·제작 경계·기존 블로그/YouTube 어댑터 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 원장과 승인 관문을 실제로 호출 가능한 실행 서비스·제작 전용 공급자·기존 5개 블로그/2개 YouTube 연결 어댑터에 연결하고, 운영 전환 없이 격리 수락시험으로 작동을 증명한다.

**Architecture:** phase1~5의 ContentStore/Ledger/RuntimeStore와 PublicationAdapter를 재사용한다. 서버 소유 등록부로 요청·제작·읽기 관측·발행을 분리하고, 기존 실행 환경 안의 고정된 bridge가 대상 하나의 외부 변경만 수행한다. 기존 작업은 legacy, 연결·워커·제작은 기본 비활성이며, 실제 계정 관측과 발행·스케줄 전환은 대상별 증거 체크포인트를 거친다.

**Tech Stack:** Python 3 표준 라이브러리, 기존 SQLite v3 원장·axlock, 기존 프로젝트별 Python 가상환경/Google 클라이언트/Selenium, 현재 웹 서버·ES modules, unittest·Node test runner. 새로운 SaaS·모델 API·학교 API·운영 데몬을 기본으로 추가하지 않는다.

**Spec:** [계정 운영 승인 설계](../specs/2026-10-30-account-channel-automation-design.md), [화면 승인 설계](../specs/2026-10-30-account-web-screens-design.md), [원 실행 계획 T9~T15](2026-10-30-account-channel-automation.md).

상태: **2026-10-31 사용자 6A 개발 승인, 구현 진행 중. 실제 계정 접속·모델 호출·발행·스케줄 전환은 승인 범위 밖이다.** 2026-10-30 작성. phase5의 Python481/Node107 검증 근거는 [phase5 수락](../../audits/2026-10-30-web-phase5-acceptance.md)을 따른다. 이 숫자는 6A의 시험 결과가 아니다. 부모 작업은 phase5 최종 수락·개발 서버 반영·문서 커밋 `d9c5ce6`까지 완료했다. 8769는 관리 웹, 8767은 W=None 읽기 전용이며 실제 신규 성과 DB0/legacy179/교차경로23/연결11개 execution=false가 관측됐다. 이 상태는 발행 활성화 증거가 아니다.

## Global Constraints

- “현재 교차 게시 방식 유지. A(실행 규칙 통일 후 폴더 분리) 선택.” 기존 등록부23개 경로와 disabled/unknown 상태를 보존한다.
- “원본 소유 계정과 실제 게시 대상 계정은 별도로 기록한다.” 개인 원본→학과 배포도 제작1회·대상별 승인/잠금/한도로 처리한다.
- “기존 작업별 승인·자동 진행 수준은 초기 정책으로 이관하고 확대하지 않는다.” 제작 완료·계획 승인·발행 승인·운영 활성은 별개다.
- “실제 대상을 확인할 수 없으면 게시하지 않고 `needs_auth` 또는 `needs_review`로 보낸다.” 표시명·이메일·제목만으로 불변 대상을 추정하지 않는다.
- “전역 STOP은 진입 시·잠금 대기 중·잠금 획득 직후·공개 부작용 직전에 확인한다.” profile 별칭 정규화와 사용자 로그인 브라우저 점유를 존중하며 기존 wrapper의 첫 axlock 줄을 유지한다.
- “플랫폼이 보장하지 않는 원격 게시의 exactly-once를 보장한다고 주장하지 않는다.” 응답 유실·기록 실패는 unknown, 재전송보다 조회가 우선이다.
- “기존 암호화 비밀 저장소·키 이름·실제 로그인 디렉터리는 초기 단계에서 그대로 유지한다.” 요청·stdout·로그·산출물에 비밀값이나 permit nonce를 넣지 않는다.
- 개인 구독-only 작업은 내부 생성·검토를 포함해 유료 모델 키·학교 API로 우회하지 않는다. 학과의 기존 허용 정책은 별도 유지하며 개인 제한을 학과 전체의 영구 정책으로 확대하지 않는다.
- “접속 범위는 사용자 선택으로 Mac과 휴대폰의 외부 접속까지 포함한다.” 6A localhost 검증으로 최종 외부 접속 요구를 완료하거나 삭제하지 않는다.
- 원본 R=`/Volumes/USB256/devAPP/AutoSNS`는 이번 계획의 정적 읽기 근거다. 구현 단계도 별도 체크포인트 전에는 작업 사본 W에서만 수정한다. 키·토큰·환경값·프로필 읽기, legacy 모듈 import/실행, 실제 로그인·발행·launchd·폴더 이동은 계획 작성에서 수행하지 않았다.
- 파일 소유가 겹치는 작업은 직렬 실행한다. 다른 담당자의 변경을 되돌리지 않는다. 아래 커밋 명령은 향후 구현자가 해당 단계 검증 후 실행하는 절차이며 이 계획 작성에서 커밋하지 않는다.

### A1. 등록된 실행 요청과 단일 owner fence

**Files:** Create `common/operations/execution_catalog.py`, `entrypoints.py`, `cli.py`, `tests/integration/__init__.py`, `tests/integration/test_entrypoints.py`; Modify `common/operations/dispatch.py`, `registry.py`.

**Interfaces:**
- Consumes: 위 현재 `submit_trigger`, `load_registry(Path)`, `ExecutionPolicy`.
- Produces: `ExecutorSpec(id, job_ids, phases, interpreter, cwd, module, mutation_actions, environment_names)` frozen dataclass; `ExecutionCatalog(executors, callers, production_jobs)`; `resolve_entrypoint(caller_id: str, job_id: str, registry, catalog) -> dict`와 `submit_registered(request: dict, *, caller_id: str, store, registry, policy, catalog) -> dict`.
