# 운영 웹 5단계 — 성과·기획 근거와 구조 이행 준비 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 개인·학과의 저장된 성과와 원본/대상 귀속을 조회하고 다음 기획의 근거로 저장하며, 기존 계정별 파일을 잃지 않는 구조 이행 계획을 생성한다.

**Architecture:** 운영 원장 v3는 유지하고 별도 `metrics.sqlite3`에 불변 관측·가져오기 매핑을 저장한다. 웹 GET은 저장 자료만 읽는다. 실제 수집은 검증된 게시 ID와 서버 등록 읽기 전용 수집기 계약으로 분리하며 이번 배포에는 실수집기를 등록하지 않는다. 경로 이행은 순수 resolver·정적 inventory·계획까지 구현하고 T10~T12 선행 조건이 갖춰지기 전 운영 파일 이동은 차단한다.

**Tech Stack:** Python 표준 라이브러리·SQLite, 기존 인증 HTTP 서버, 순수 JavaScript 모듈·CSS, unittest·Node test.

**Spec:** `docs/superpowers/specs/2026-10-30-account-web-screens-design.md` §성과·§8, `docs/superpowers/plans/2026-10-30-account-channel-automation.md` T13·T14. 조사: `docs/audits/2026-10-30-web-phase5-readiness.md`, `2026-10-30-web-phase5-provider-docs.md`.

## Global Constraints

- 사용자에게 보이는 글은 한국어로 쓴다. 기존8개 메뉴와 개인/학과 필터를 유지한다.
- 제작비는 원본 소유 계정, 채널 성과·발행량은 실제 대상 계정에 연결한다. 교차 배포를 복제 원본으로 만들지 않는다.
- 실제0·조회 오류·미지원·미수집을 구별한다. 누적값을 기간 발생량으로 표시하지 않는다.
- 기존 교차 규칙23개·꺼진 작업·실행 주인 legacy·구독 전용 정책을 보존한다.
- 운영 source·키·토큰·프로필·.venv·launchd·8700은 변경하지 않는다. 자동 로그인·실제 API·모델 호출·수집기 실행·발행은 이번 범위에 없다.
- 운영 원장은 공용으로 유지한다. R(source), W(managed), code_root를 명시하고 계정 누락/unknown에 개인 fallback을 하지 않는다.
- 브라우저/발행은 원본 shared/axlock.py 규칙을 따른다. 이번 서버 기본 adapter/probe/collector 등록은 비어 있고 실행 disabled를 유지한다.
- Codex의 Metricool·vidIQ 설치는 웹 runtime 인증이 아니다. Instagram·Threads·X·Tistory·Facebook을 지원표에서 숨기거나 가상 계정을 만들지 않는다.
- 320/1280px에서 전체 가로 넘침0, 키보드 접근·Escape·포커스 복귀·저장 충돌 시 입력 보존을 유지한다.

## 단계 경계와 후속 의무

이 계획은 화면 순서의5단계 중 **성과 저장/조회/기획 근거 및 구조 이행 준비**다. 공식 API 수집기와 실제 개인 코드 이동까지 끝났다는 의미가 아니다. 전체 T13의 실제 이동은 T10~T12의 채널·제작·진입점 연결 후, T14 실수집은 계정별 읽기 권한·비용·대상 확인 후 후속 계획에서 구현·수락한다. 따라서 이번 종료 상태는 `local_metrics_ready`, `migration_plan_ready`이며 `live_collection_ready=false`, `physical_migration_ready=false`, `production_ready=false`다.

원본에 존재하는9개 analytics JSON은 실제 저장 자료로 읽되 관측 시각/계정/게시 ID 근거가 부족한 값은 `legacy_reported`로 표시한다. 샘플 수집기를 실제 성과로 대신하지 않는다. 실채널 활성화·발행 권한 없는 제작/독립 검토·진입점 단일화·안전한 물리 이동·실수집·보호된 Mac/휴대폰 외부 접속은 전체 목표에 그대로 남는다.

## Review Focus

1. 같은 게시물을 legacy 파일과 관리 원장에서 읽는 중복: 원천 키와 검증 연결이 없으면 합산하지 않는다(S2/S3).
2. 파일 수정 시각이 최근이지만 내부 통계는 과거: mtime을 observed_at으로 승격하지 않는다(S1/S2).
3. 개인 원본→학과 대상: 연관 표시는 양쪽에서 가능하되 지표 총합은 대상에 한 번 귀속한다(S3).
4. 링크 중첩·cwd·없는 계정으로 경로가 다른 계정을 가리킴: 명시 오류/격리하고 비밀·subprocess 접근0을 지킨다(S5).
5. 성과 조회/새로고침/기획 저장이 외부 수집 또는 승인으로 이어짐: GET 외부 호출0, 제안은 draft만 생성한다(S4/S6).

## 파일 지도와 공통 계약

- 신규 `common/operations/metrics_models.py`: MetricResult·MetricObservation 불변 자료형/검증. Result는 `status=ok|unsupported|error`, values(number이며 bool/NaN/Infinity 금지), observed_at(UTC timezone 포함 또는 실패 시None), remote_id,target_id,definition_id,basis(`lifetime|interval`),period(start,end,timezone 또는None),source. 오류 values는빈dict, `ok`는 실제 시점·식별자 필수.
- 신규 `metrics_store.py`: W/metrics.sqlite3 명시 initialize·읽기 전용 open, 관측 저널/legacy 매핑/제안 근거만 소유. runtime 승인/상태 변경 없음. schema version1, unique observation_key, import source_key+row_hash 이력. 생성자/GET 이행 없음.
- 신규 `metrics.py`: `collect_delivery_metrics(ctx,remote_id,collector)->MetricResult`, `record_metrics(store,delivery_id,result)->dict`. ctx는 서버가 만든 owner_account_id,destination_account_id,connection_id,target_id,content_id,revision,verified_at를 가진 frozen MetricsContext. verified_at 없는 제출/예약은 수집 차단. collector는 명시 전달, 기본None이면 unsupported; 네트워크 구현은 이번 등록 안 함.
- 신규 `legacy_metrics.py`: `load_legacy_metrics(source_root,registry)->dict`, `build_import_plan(snapshot,registry)->dict`, `import_snapshot(store,plan)->dict`. legacy source만 관측으로 저장, ContentStore 원본/승인/verified를 합성하지 않는다.
- 신규 `planning_context.py`: `build_planning_context(account_id,registry,store)->dict`는 저장 성과/등록된 사이트/이력만 반환. 기존 자동 planner/토큰 코드는 호출하지 않는다.
- 신규 `web_metrics.py`: 성과 HTTP 검증/응답, 신규 `ax-console/app/web/metrics_panel.js`: 독립 성과 UI. `app.js`, `web_server.py`, `styles.css`는 통합 담당만 수정.
- 신규 `layout.py`, `environment_manifest.py`, `common/tools/audit_account_paths.py`, `docs/migrations/account-paths.md`: 계정 경로·호환 링크·호출자·환경 기호 참조와 이동 전제조건.
- 신규 시험 `tests/operations/test_metrics*.py`, `test_planning_context.py`, `test_migration.py`, `tests/test_web_metrics.py`, `tests/web_metrics.test.mjs`. 실제 함수/타입 변경 시 먼저 위 계약과 후속 소비자를 함께 갱신한다.
