# 계정별 운영 웹 1단계 Implementation Plan

> 에이전트 구현자는 `superpowers:subagent-driven-development`를 적용한다. 독립 파일을 병렬 구현하고 각 작업 및 전체 통합을 검토한다.

**Goal:** 확정된 8개 화면을 공통 UI로 만들고, 실제 운영 파일에서 부작용 없이 읽은 데이터를 표시한다.
**Architecture:** 독립 조회 모델 + 기존 인증을 재사용한 로컬 읽기 전용 서버 + 분리된 HTML/CSS/JS 화면. 기존 server.py와 운영 스케줄을 바꾸지 않는다.
**Tech Stack:** Python 표준 라이브러리·기존 auth.py, buildless HTML/CSS/JavaScript, unittest·Node 문법/순수 함수 시험.
**Spec:** [사용자가 확정한 화면](../specs/2026-10-30-account-web-screens-design.md), [기존 API 준비 점검](../../audits/2026-10-30-web-read-api-readiness.md).

## Global Constraints

- 사용자 '네'로 화면 구성 및 1단계 개발 승인. 기존 교차 게시 유지.
- 기존 운영 main·실제 게시·스케줄·STOP·비밀값 변경 금지. 기존 인증을 우회하지 않는다.
- 1단계는 조회만 제공한다. 생성·저장·예약 수정·발행·정지·재시도 제어는 비활성으로 표시한다.
- 샘플 수치·성공 상태를 실제 데이터 빈칸에 채우지 않는다. 미수집·실패·0을 구분한다.
- 조회 모델은 secret_config·token_store·기존 server.py를 import하지 않고 subprocess·브라우저·모델·외부 네트워크를 호출하지 않는다.
- 인증 세션 메타데이터 갱신은 기존 인증을 따른다. 콘텐츠·운영 자료는 변경하지 않는다.
- localhost 전용이며 외부 접속은 별도 사용자 선택 대기다. API는 인증이 필요하다.

## Review Focus

1. 파일이 없거나 JSON/JSONL 한 줄이 손상돼도 전체 화면이 정상인 척하거나 빈 샘플로 대체되지 않아야 한다 → R1.
2. 조회 중 파일 mtime·내용·기존 waiting 기록이 변경되지 않아야 한다 → R1.
3. 개인 원본→학과 채널은 양쪽 관련 계정 필터에 나타나되 소유권은 바뀌지 않아야 한다 → R1/R3.
4. 로컬 done·예약 기록만으로 공개·검증 완료를 표시하면 안 된다 → R1/R3.
5. 사용자 작성 제목·URL, 경로 우회, 인증 없는 요청·쓰기 요청이 안전하게 처리되어야 한다 → R2/R3.

## 공통 응답 계약

`GET /api/v2/snapshot?account=all|dept|personal`는 아래 JSON 객체를 반환한다. 루트 경로는 서버 시작 시 `AX_SOURCE_ROOT`로만 지정하며 HTTP에서 받지 않는다. 응답에 원본 디스크 경로·비밀값·쿠키·토큰·내부키·원문 로그 전체를 노출하지 않는다.

```text
schema_version: 1
read_only: true
generated_at: 한국시간 aware ISO 문자열
scope: all|dept|personal
warnings: 문자열 배열
accounts: [{id,label}]
contents: [{id,title,owner_account_id,kind,series,status,revision,summary,created_at,updated_at,channels:[]}]
deliveries: [{id,content_id,owner_account_id,destination_account_id,channel,target_label,status,schedule_kind,scheduled_at,url,checked_at,evidence}]
channels: [{id,account_id,platform,label,target_label,configured_status,auth_status,enabled}]
schedule: [{id,title,owner_account_id,destination_account_id,channel,scheduled_at,kind,status,content_id}]
incidents: [{id,title,account_id,severity,status,summary,last_at}]
crossposts: [{id,owner_account_id,destination_account_id,source_channel,destination_channel,title,condition,enabled}]
proposals: [{id,owner_account_id,title,summary,status}]
metrics: {status: unavailable,items:[]}
```

- nullable는 없음을 null로 표시한다. auth_status는 이번 단계에서 unknown이다. 설정 등록과 실제 로그인 성공을 혼동하지 않는다.
- content status: idea/drafting/review/scheduled/reported_published/failed/unknown. kind: article/card/short/video/unknown.
- delivery status: draft/queued/scheduled_recorded/reported_published/verified/failed/unknown/paused. `done`은 reported_published, 업로드 예약 JSON은 scheduled_recorded다. verified는 별도의 명시적 검증 근거가 있을 때만 허용하며 1단계 로컬 완료만으로 승격하지 않는다.
- schedule_kind: local_request/remote_recorded/unknown. remote_recorded도 현재 원격 플랫폼 재조회 결과가 아니다.
- scope는 콘텐츠 소유 계정 또는 연결된 배포·규칙의 도착 계정으로 필터한다. 관련 원본은 유지하고 반환 배포·일정·채널은 해당 계정과 관련된 것만 남긴다.
- URL은 http/https만 표시·링크한다. 제목·요약·출처는 HTML로 신뢰하지 않는다.
- 콘텐츠 상세는 스냅샷의 해당 원본·배포를 이용한다. 전체 원문 편집은 아직 미지원이다.
- 미지원 성과·교차 규칙 누락·시각 미확인은 명시적으로 표시한다.

## R1. 부작용 없는 실제 파일 조회 모델

**소유:** backend worker. **Files:** `ax-console/app/read_model.py`, `tests/test_read_model.py`만.
**Interface:** `build_snapshot(source_root:Path, account:str='all', *, now:datetime|None=None, launchagents_dir:Path|None=None)->dict`. 잘못된 계정은 ValueError. 함수 호출·import만으로 파일을 생성하거나 수정하지 않는다.
**자료:** config/accounts.json·automations.json, ax-console/data/content/*/*/*/meta.json·tasks.json·incidents(archive 제외)·proposals, personal/claude-jobs/state/*.jsonl, dept/disaster-shorts/*/upload.json, dept/youtube-shorts-auto/posts/tiktok_queue.json, launchd plist 메타데이터. 사용 가능한 파일만 읽고 누락·손상을 warnings로 알린다. JSONL·큐·glob은 제한을 두고 가장 최근 자료 위주로 다룬다. 비밀파일·Chrome 쿠키·토큰·로그 본문은 읽지 않는다.

- [ ] 임시 원본 파일 fixture에서 schema·두 계정·교차 필터·손상 줄·누락 설정·mtime/바이트 불변·악성 URL·done≠verified를 시험한다. 실제 source_root나 홈 프로필을 시험에 사용하지 않는다.
- [ ] `python3 -m unittest discover -s tests -p test_read_model.py -v` RED를 확인한다.
- [ ] 순수 파일 해석과 상태 정규화를 구현한다. 안정적 ID로 원본/배포를 연결하고 키가 겹치거나 다른 원본인 경우 임의 합치지 않는다. 원본 없는 실제 게시기록은 별도 원본으로 표시한다. 스케줄은 Asia/Seoul aware로 계산하되 간격 작업의 정확한 다음 시각은 추측하지 않는다.
- [ ] 같은 명령 GREEN, 모든 fixture 파일의 재귀 바이트·mtime 스냅샷 불변을 확인한다.
- [ ] 부모가 해당 두 파일만 검토·커밋한다.

## R2. 인증을 유지하는 조회 전용 로컬 서버

**소유:** server worker. **Files:** `ax-console/app/web_server.py`, `tests/test_web_server.py`만.
**Interface:** `create_server(host:str='127.0.0.1',port:int=0,*,source_root:Path,web_root:Path,auth_backend=None,snapshot_builder=None)->ThreadingHTTPServer`. snapshot_builder는 R1과 같은 인자를 받는다. `main()`만 실제 serve_forever를 실행한다. import·factory는 기존 scheduler/watcher/google 검사나 게시를 시작하지 않는다.
**실행:** `AX_SOURCE_ROOT=/운영루트 AX_AUTH_DIR=/기존인증자료 AX_PORT=8767 python3 ax-console/app/web_server.py`. 기본 host는 loopback만 허용한다.
**경로:** `/`·`/web/`(새 화면), allowlist 정적 `/web/styles.css`, `/web/app.js`, `/web/api.js`(필요한 신규 파일은 frontend가 목록을 알려 통합), `/login`(기존 login.html), `/api/auth/status`, 인증 후 `/api/v2/snapshot`. POST는 기존 로그인·로그아웃만 지원하고 setup은 인증 자료가 없는 별도 개발 fixture에서만 필요 시 지원한다. 비밀번호 변경·콘텐츠/게시/설정 쓰기는 405/404로 거부한다. 내부키는 기존 파일이 있을 때만 비교하고, 조회를 위해 새로 생성하지 않는다.

- [ ] fake auth와 임시 파일/가짜 snapshot으로 인증 401·root login redirect·정상200·잘못된scope400·모든 쓰기거부·경로순회차단·부적절Origin거부·부작용 없는 import/factory를 시험한다.
- [ ] `python3 -m unittest discover -s tests -p test_web_server.py -v` RED를 확인한다.
- [ ] 실제 기존 auth.py의 verify/new_session/check/drop/cookie 기능만 재사용한다. 기본 인증 저장 위치는 source_root의 ax-console/data/auth로 고정하며 보호된 내부키를 브라우저 JavaScript에 삽입하지 않는다. 오류 응답에 디스크 경로·예외 원문을 그대로 노출하지 않는다.
- [ ] 같은 명령 GREEN. R1 완료 후 실제 read_model을 주입하는 임시 HTTP 통합 시험을 추가한다.
- [ ] 부모가 해당 두 파일만 검토·커밋한다.

## R3. 확정 화면을 실제 데이터 표시용 모듈로 구현

**소유:** frontend worker. **Files:** `ax-console/app/web/index.html`, `styles.css`, `api.js`, `app.js`(필요 시 `view_helpers.js`), `tests/test_web_frontend.mjs`, 모듈 해석용 `ax-console/app/web/package.json`만. package.json은 type=module/private만 가지며 의존성 설치는 없다. 기존 시안 HTML은 변경하지 않는다.
**입력:** 위 계약. `api.js`는 같은 출처 GET /api/v2/snapshot만 호출한다. 인증401은 /login으로 안내하며 오래된 데이터·실패·갱신 시각을 표시한다. hardcoded sample 데이터·실제 쓰기 호출 없음.
**화면:** 확정 8개 메뉴, 관련 계정 필터, 기획 단계·보관함 검색/형식/시리즈, 배포별 캘린더/목록, 원본·대상 상세, 교차 경로, 채널 상태, 미지원 성과, 조치/기록. 생성/편집/예약/제어는 미지원 안내와 비활성 버튼으로 표시한다. 화면별 데이터가 없으면 이유를 설명한다.

- [ ] 순수 필터·상태 라벨·안전 URL·집계·날짜 함수 시험을 Node 표준 assert로 작성한다. 교차 원본은 두 계정 보기에서 추적하고 예약/업로드/게시기록을 검증 완료로 세지 않는다.
- [ ] `node --test tests/test_web_frontend.mjs` RED를 확인한다.
- [ ] 시안의 스타일·메뉴·상세 흐름을 분리 모듈로 옮기고 snapshot에 연결한다. 외부 CSS/JS/CDN/이미지 요청·플러그인·localStorage 인증키 저장은 금지한다. 텍스트는 textContent 또는 escaping, 링크는 안전 URL 검사·noopener로 처리한다. 늦은 응답이 최신 계정 선택을 덮어쓰지 않게 한다.
- [ ] 같은 Node 시험 GREEN, 각 JS `node --check`, 320/1280px·키보드·상세 포커스·에러/빈상태를 실제 브라우저에서 검증한다.
- [ ] 부모가 소유 파일만 검토·커밋한다.

## 통합과 종료 기준

1. 부모가 임시 데이터/임시 인증으로 로컬 서버를 띄우고 8개 화면·필터·상세·401·실패/빈상태를 확인한다. 샘플 fixture를 실제 운영 데이터로 표시하지 않는다.
2. 운영 데이터를 읽는 별도 인스턴스는 명시적 AX_SOURCE_ROOT와 기존 인증을 사용하고 localhost에만 바인딩한다. 기존 8700 콘솔을 교체·재시작·병합하지 않는다.
3. 운영 파일 조회 전후의 내용·mtime이 같고 기존 작업 실행/STOP/원격 예약/발행에 변화가 없는지 확인한다. 원본에서 다른 자동 작업이 동시에 바꾼 파일은 읽기 코드의 부작용과 구별한다.
4. 전체 unittest·Node 시험, HTTP 회귀·최종 리뷰를 통과하고 새 화면·남은 미지원 기능을 보고한다.
5. 이 단계 완료는 전체 자동 운영 웹 완료가 아니다. 기획 저장·실행 원장·발행 연결·복구·성과·운영 이행은 기존 전체 실행 계획의 다음 작업으로 이어진다.
