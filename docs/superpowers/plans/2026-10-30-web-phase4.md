# 운영 웹 4단계: 실행 관문·운영 제어·복구 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 실제 운영에 사용할 실행 원장·중복 방지·정지·한도·불확실 결과 복구를 구현하고 웹에서 실행 가능 여부와 복구 근거를 관리한다.

**Architecture:** 기존 콘텐츠·계획은 보존하고 SQLite v3에 실행 기록을 추가한다. 계획 컨텍스트와 별도로 서버가 실제 실행 컨텍스트를 구성하며, 워커가 lease와 일회성 permit을 통해서만 어댑터를 호출한다. 시험에서는 같은 인터페이스에 가짜 어댑터를 주입하고 기본 서버에는 실제 제출 어댑터를 등록하지 않는다.

**Tech Stack:** Python 표준 라이브러리·SQLite·기존 buildless JavaScript·unittest·Node test. 추가 유료 호출 없음.

**Spec:** [확정 화면 설계](../specs/2026-10-30-account-web-screens-design.md), [승인 운영 설계](../specs/2026-10-30-account-channel-automation-design.md), [전체 계획 T6~T9](2026-10-30-account-channel-automation.md), [사전 점검](../../audits/2026-10-30-web-phase4-readiness.md).

## Global Constraints

- 사용자 지정 병렬 에이전트 방식 유지. 최대 3개 독립 구현 작업과 통합 담당 1개를 사용한다. 공통 계약을 먼저 고정하고 각 작업을 독립 검토한다.
- 기존 교차 게시 규칙 23개와 legacy 실행·일정 주인은 보존한다. 신규 실행 기능이 기존 대기열을 가져오거나 같은 교차 게시를 추가하지 않는다.
- 계획 승인 scope=plan, 기존 컨텍스트 dry 고정은 유지한다. 발행 승인은 별도 scope=publication과 독립 검토 근거를 요구한다.
- 실제 source_root의 STOP 변경·프로필 열기·원격 조회/로그인·AI 호출·게시/예약·launchd 변경·8700 재시작은 이번 구현에서 실행하지 않는다. 읽기와 fixture 시험만 한다.
- 실제 실행 계약을 구현한다. 시뮬레이션 전용 테이블이나 시험 성공을 실제 공개 성공으로 표시하는 기능은 만들지 않는다.
- 새 서버의 기본 실행 정책은 disabled다. HTTP가 이를 켜거나 credential/profile/executor/계정 소유를 재정의할 수 없다. 실제 활성화는 전체 계획 T10~T15와 연결별 수락 증거가 필요하다.
- 비밀값·permit 원문·절대 운영 경로·프로필 경로는 응답/로그에 노출하지 않는다. 원본 운영 JSON·기존 인증 저장소는 변경하지 않는다.
- GET·모듈 import·객체 생성은 외부 호출·초기화·이행·대기자 정리를 하지 않는다. 관리 DB는 명시적 initialize로만 이행한다.

## 공통 계약

### 컨텍스트와 어댑터

`runtime_models.py`의 frozen dataclass는 깊은 불변성을 보장한다. 시간은 aware UTC, 오류는 기존 `ContractError(code)`를 사용한다.

- `PublicationContext`: 기존 계획의 content/revision/manifest/owner/destination/connection/target/purpose/slot/options/schedule_condition/registry_revision/policy_revision을 별도로 재검증한 실행 스냅샷. `scope=publication`, 인증 관측 시각/만료 및 독립 검토 report hashes를 포함한다. HTTP의 dry 플래그를 뒤집어 생성하지 않는다.
- `RunLease(run_id,worker_id,generation,expires_at)`; 프로세스 신원은 PID 단독이 아니라 시작 시각·호스트 식별자를 함께 기록한다.
- `SubmissionPermit(attempt_id,nonce,run_id,generation,expires_at,context_hash,approval_hash)`; nonce는 메모리에만 유지하고 DB에는 SHA256만 저장한다.
- `SubmissionResult(outcome,remote_id,url,scheduled_at,evidence)`의 outcome은 submitted/scheduled/unknown/failed. `LookupResult(outcome,candidates,evidence)`는 matched/ambiguous/not_found/unsupported/error. `VerificationResult(outcome,checked_at,evidence)`는 verified/pending/failed/unsupported/error.
- `PublicationAdapter`: `inspect_target(ctx)->dict`, 순수 `prepare(ctx,snapshot)->dict`, `submit(ctx,prepared,permit)->SubmissionResult`, 읽기 전용 `lookup(ctx,attempt)->LookupResult`, `verify(ctx,remote_id,snapshot)->VerificationResult`. 지원 안 하는 동작은 unsupported. 기존 dry_run 실행기를 prepare/verify에 연결하지 않는다.
- `ExecutionPolicy(enabled,allowed_connection_ids,cutover_revision,provider_policy)`: 서버 시작 인자로 주입한다. 기본 disabled, 공인된 cutover 증거 없는 live 요청은 거부한다. 테스트에서만 명시적 시험 정책과 가짜 어댑터를 주입한다.

### 영속 상태

v3는 기존 v1/v2 테이블·본문·승인 해시를 바꾸지 않는다. `runtime_runs`, `runtime_deliveries`는 기존 run/delivery ID를 참조하며 기존 계획 상태와 실행 상태를 별도 필드로 응답한다. 기존 계획 승인으로 실행 행을 자동 생성하지 않는다.

추가 테이블: `runtime_runs`(state/version/worker/generation/lease/process_identity), `runtime_deliveries`(context/state/version/remote ID), `attempts`(ordinal/context/approval/reservation/request_started/result), `submission_permits`(nonce_hash/expiry/consumed/invalidated), `quota_buckets`, `quota_reservations`, `operation_evidence`, `publication_approvals`, `control_events`. delivery당 미해결 attempt는 최대 하나다. attempt·permit 소비·request_started와 submitting 전이는 한 트랜잭션이다.

상태: queued → running → submitting → uploaded/scheduled/published → verified. 명확한 미제출 실패만 retry_wait로 이동한다. 요청 시작 후 결과 불확실은 unknown, 인증/검토/불충분 근거는 needs_review다. 실행 완료 집계는 필수 대상 전부 verified일 때 completed, 일부 성공+실패는 partial, unknown/검토/인증은 waiting이다. 비게시 작업은 정의된 산출물 조건으로 집계한다.

### 잠금·정지·한도

`LockPaths.from_root(source_root)`와 `AxLock(paths)`를 추가하고 기존 모듈 함수/CLI는 기본 인스턴스로 호환한다. `read_control_state(paths,process_probe)->dict`는 clear/stopped/unknown을 반환하며 정리/쓰기를 하지 않는다. STOP 저장은 같은 디렉터리 임시 파일+atomic replace, 해제는 명시적 CAS를 요구한다.

STOP 작성과 permit 발급/소비는 source_root의 `control:publish-gate`를 공유한다. 계정 프로필 장기 대기·네트워크 동안 제어 잠금/SQLite 트랜잭션을 잡지 않는다. 프로필 획득 후 관문을 재검사한다. STOP 선행이면 제출 0, 소비 선행이면 이미 시작된 요청의 결과 수습을 허용하고 후속 제출을 막는다. 사람이 연 로그인 브라우저를 닫지 않는다.

한도는 대상 게시량·공용 API 사용량·콘텐츠 소유 계정 제작비를 별도 bucket으로 원자 예약한다. 관측 수동 사용량·보류 예약을 포함하고 관측이 없거나 만료된 필수 bucket은 차단한다. unknown 예약은 유지한다. 미제출 확정만 해제하며 실제 사용은 정산한다. 외부 수동 게시와 플랫폼 API 전체를 원자 제어한다고 주장하지 않는다.

### API와 화면

기존 인증·Host/Origin·JSON 제한을 그대로 적용한다. 임의 명령·모듈·토큰 입력은 없다.

- `GET /api/v2/operations?account=all|personal|dept`: 실행 목록·집계·정지 관측·실행 정책과 차단 이유. 읽기 전용.
- `GET /api/v2/operations/<delivery_id>`: 시도·비밀 제거 증거·원격 상태·복구 가능 동작.
- `POST /api/v2/operations/<delivery_id>/reconcile`: expected_version/request_key 필수. 서버 등록 읽기 전용 adapter만 호출한다. 기본 미등록이면409 adapter_unavailable, 네트워크 0.
- `POST /api/v2/operations/<delivery_id>/resolve`: expected_version/request_key/kind/evidence/note 필수. kind=link_existing/confirmed_not_posted/cancel_local. actor는 서버 인증 사용자, 사용자가 임의 actor를 보낼 수 없다.
- `POST /api/v2/operations/<delivery_id>/retry`: 동일 실행의 재개만 허용. 신규 게시 요청으로 바꾸지 않는다. 기본 disabled이면409 execution_disabled, 기록/제출 0.
- `POST /api/v2/control`: scope=managed|account|connection, id, action=pause|resume, expected_version, request_key, reason. 관리 DB 정책만 변경한다. resume은 catch-up enqueue를 하지 않는다. legacy 전역 STOP은 이번 UI에서 관측만 하며 미연결 범위를 명시한다.

‘문제·복구’는 unknown/인증/검토/실패 필터와 시도·근거·복구 상세를 표시한다. ‘오늘’은 기존 발행 관측·관리 계획·관리 실행을 분리한다. 계정/채널 중지의 적용 범위와 기존 작업에 대한 미적용을 표시한다. 원격 예약 취소·원격 삭제 버튼은 제공하지 않는다. disabled 동작은 이유를 보이고 강제로 저장하지 않는다.
