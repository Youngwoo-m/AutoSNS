# 계정별 콘텐츠 저장·연동 설정 2단계 구현 계획

> 구현은 `superpowers:subagent-driven-development`를 적용한다. 독립 파일 소유권을 나누고 통합·커밋은 부모가 수행한다.

**Goal:** 확정된 기획·보관함 화면에서 개인/학과 원본·버전·변환본·자산·검토를 저장하고, 계정별 SNS 도구 선택을 관리한다.
**Architecture:** 기존 자료는 읽기 전용으로 유지한다. 새 관리 자료는 별도 로컬 저장 루트의 SQLite 및 불변 파일에 저장하고 기존 조회 화면에서 출처를 구분해 함께 조회한다. 발행·제작 실행 연결은 이후 단계다.
**Tech Stack:** Python 표준 라이브러리 SQLite·파일 해시, 기존 독립 웹 인증, buildless JavaScript.
**Spec:** [확정 화면 및 추가 SNS 범위](../specs/2026-10-30-account-web-screens-design.md), [승인 운영 설계](../specs/2026-10-30-account-channel-automation-design.md).

## 공통 제약

- `AX_WORKSPACE_ROOT`는 서버 시작 때 명시한 새 저장 루트다. 기본값으로 운영 루트를 쓰지 않는다. 미설정이면 기존 조회 전용으로 실행한다.
- 기존 server.py의 content_approve/content_draft/csave를 호출하지 않는다. 저장·검토는 예약이나 자동 작업을 생성하지 않는다. 기존 JSON·토큰·프로필·launchd·STOP은 변경하지 않는다.
- 개인·학과만 원본 소유자가 될 수 있다. 원본 소유권은 생성 후 고정한다. UI 조회 필터는 저장 소유권의 암묵적 기본값이 아니다.
- 목표 채널은 기획 메타데이터다. 연결 성공·발행 권한·예약을 뜻하지 않는다. 개인 원본과 학과 대상 계획을 함께 보존한다.
- 새 저장소는 `operations.sqlite3`, 계정별 파일은 `<account>/content/<id>/revisions/<revision>/`에 둔다. 원문·미디어 바이트는 파일로, 상태·해시·참조는 DB로 관리한다. 기존 JSON과 양방향 동기화하지 않는다.
- 비밀번호·토큰 입력/저장·외부 서비스 호출은 이 단계에 넣지 않는다. 플러그인 설치나 서비스 연결을 가장하지 않는다. 설정 활성은 웹의 사용 선호만 나타내며 기존 자동 작업을 바꾸지 않는다.
- API 쓰기는 기존 로그인·같은 출처 검사에 추가해 정확한 JSON 스키마와 요청 크기를 검증한다. 사용자 제공 디스크 경로를 받지 않는다.

## 검토 중점

1. 두 창의 동시 저장은 마지막 요청으로 덮어쓰지 않고 409 충돌로 표시 → P1/P3.
2. 파일 저장 실패·프로세스 중단 시 현재 버전이 반쪽 파일을 참조하지 않음 → P1.
3. 구자료 ID와 새 관리 ID가 겹쳐도 잘못 편집하거나 소유 계정을 바꾸지 않음 → P2/P3.
4. 자산 이름의 경로 우회·실행 파일·한도 초과가 서버 경로나 비밀을 읽거나 실행하지 못함 → P1/P2.
5. 원문·변환·자산 수정 후 이전 버전의 검토 결과를 현재 검토 완료로 사용하지 않음 → P1/P3.

## 공통 계약

신규 `common/operations/content_store.py`의 `ContentStore(root:Path)`는 명시적 `initialize()` 뒤에만 쓴다. 읽기 메서드는 디렉터리·DB를 만들지 않는다. `StoreError(code)` 및 `ConflictError`를 정의한다.

- `create(owner_account_id:str, payload:dict)->dict`
- `update(content_id:str, expected_revision:int, payload:dict)->dict`
- `get(content_id:str)->dict|None`, `list(account:str='all')->list[dict]`
- `add_asset(content_id:str, expected_revision:int, filename:str, media_type:str, data:bytes)->dict`: 새 revision 생성.
- `record_review(content_id:str, revision:int, manifest_hash:str, kind:str, decision:str, notes:str)->dict`: 해당 불변 버전에만 귀속. 실제 독립 검토 실행 여부는 별도 표시.

content 응답: `id(managed_ 접두사), source=managed, owner_account_id, revision:int, title, kind(article/card/short/video), series, status(idea/drafting/review/archived), original, variants:[{destination_account_id,platform,text}], sources:[{url,note}], assets:[{id,filename,media_type,size,sha256}], manifest_hash, reviews, created_at,updated_at`. ID·파일 경로는 서버가 생성한다. 데이터에 경로·credential_ref를 넣지 않는다. 2단계에서는 승인 상태를 만들지 않는다.

JSON payload 한도 1MiB, title 300자, original/각 변환본 200000자, sources 최대100·변환본 최대30. 자산은 JPEG/PNG/WebP·MP4·MP3/WAV 허용, 파일당100MiB·콘텐츠 합계500MiB. 확장자·시그니처·타입 조합을 확인하며 SVG/HTML·실행 파일은 받지 않는다. 크기 초과는413, 스키마 오류400, 없는ID404, revision충돌409, 저장실패503.

## P1. 불변 콘텐츠·자산·검토 저장소

**소유 파일:** `common/operations/__init__.py`, `content_store.py`, `tests/test_content_store.py`.

- [ ] 생성·수정·불변 과거버전·두 연결 CAS충돌·소유권변경 거부·경로 우회·파일실패 주입·변경 후 검토 미승계 시험을 작성하고 `python3 -m unittest discover -s tests -p test_content_store.py -v`로 요구에 따른 RED를 확인한다.
- [ ] SQLite contents/revisions/reviews/events 스키마와 짧은 트랜잭션을 구현한다. 파일은 새 불변 revision에 먼저 준비하고 DB commit으로 노출한다. DB 실패 시 이전 current_revision을 유지한다. 재사용 자산도 해시·크기 참조를 검증한다. initialize는 트랜잭션 스키마 버전과 잠금 timeout을 고정한다.
- [ ] 동일 시험 GREEN 및 원본 운영 디렉터리 미접근 검증 후 담당 파일만 부모가 커밋한다.

## P2. 인증 API·조회 통합·자산 전달

**선행:** P1 계약. **소유 파일:** `ax-console/app/web_content.py`, `web_server.py`, `tests/test_web_content.py`, `test_web_server.py`.

- [ ] 임시 저장소·fake auth로 인증/같은출처/크기·스키마·충돌·legacy 편집거부·읽기모드 쓰기거부를 RED로 확인한다.
- [ ] `/api/v2/contents` GET/POST, `/api/v2/contents/<managed_id>` GET/PUT, `/api/v2/contents/<id>/assets` POST(단일 raw 바이트·검증된 메타 헤더), `/api/v2/contents/<id>/reviews` POST를 추가한다. 원본 읽기 모델은 그대로 두고 새 조회 조합 모듈에서 managed 자료를 합친다. 응답은 기존 요약 계약을 유지하며 상세만 추가 필드를 준다.
- [ ] 자산 GET은 인증 후 DB 참조로만 경로를 해석하고 파일 hash를 확인한다. 외부 URL 다운로드는 하지 않는다. 범위/상태 코드는 공통 계약을 따른다.
- [ ] HTTP 시험 GREEN, source_root 불변 및 저장 루트 미설정시1단계 호환을 검증하고 부모가 커밋한다.

## P3. 기획·편집·원본 상세 화면

**선행:** P1/P2 응답 계약. **소유 파일:** `web/content_editor.js`, `web/app.js`, `web/api.js`, `web/styles.css`, `web/index.html`, `tests/test_content_editor.mjs`.

- [ ] 폼 변환·원본소유명시·대상계정보존·409초안유지·검토버전표시를 Node 순수 함수 시험 RED로 고정한다.
- [ ] 새 기획 생성, managed 원고·대상별 변환·출처·시리즈 편집, 자산 등록·표시, 버전 선택·검토 기록 화면을 연결한다. 저장중/실패/충돌과 미저장 이탈 안내를 제공한다. legacy는 읽기 전용이며 명시적 새 초안 복사만 지원한다.
- [ ] 검토 기록은 사람의 수동 기록으로 명시하고 독립 검산·출처 검토 실행 성공으로 표시하지 않는다. 승인·예약·발행은 비활성이다.
- [ ] Node GREEN, 브라우저 생성→수정→새로고침 보존, 2창 충돌, 계정교차 대상, 320/1280px·키보드·HTML문자 안전 표시를 검증하고 커밋한다.

## P4. 계정별 도구 선택 설정

**소유 파일:** `common/operations/integration_store.py`, `ax-console/app/web_integrations.py`, `web/integration_settings.js`, `tests/test_integration_store.py`, `tests/test_web_integrations.py`, `tests/test_integration_settings.mjs`. 공용 라우팅·화면 연결은 P2/P3 후 부모가 직렬 통합한다.

연결 설정키는 `(account_id,provider_id,connection_id)`이며 payload는 `platform,target_label,enabled_preference,notes,expected_revision`만 받는다. provider=metricool/vidiq/local, platform은 카탈로그 allowlist다. `enabled_preference`는 발행 활성과 구분한다. 비밀·자유실행명령·모듈경로·OAuth scope를 저장하지 않는다.

- [ ] 개인/학과 동일플랫폼 독립저장·409충돌·알수없는플랫폼거부·토큰필드거부·설정저장후 connected승격없음을 RED로 고정한다.
- [ ] 비밀 없는 계정별 선호 설정·수정 이력을 SQLite에 저장하고 GET/PUT `/api/v2/integrations/settings` 및 화면을 구현한다. 실제설치·인증·실행 상태는 별도 미확인으로 유지한다.
- [ ] Python/Node GREEN, 새로고침 보존과 계정필터 전환을 검증한다. 기존 Claude 전역 플러그인 toggle 및 전역 X_TOKEN/THREADS_TOKEN은 호출하지 않는다.

## 통합 완료 기준

- [ ] Python/Node 회귀와 임시 HTTP·브라우저 수락 시험, 독립 작업 검토·전체 검토를 통과한다.
- [ ] 실제 운영 파일을 수정하지 않고 별도 테스트 저장 루트에서 기획·자산·검토·선호 설정이 재시작 후 보존되는 것을 증명한다.
- [ ] 현재 단계와 실제 외부 연결·제작 실행·승인·예약·발행·복구·성과·외부접속의 남은 범위를 구분해 전달한다. 운영 데이터 전환과 실제 발행은 이 계획의 완료 조건이 아니다.

## 계획 자체 점검

화면 2단계의 원본·버전·자산·검토·채널 변환 저장은 P1~P3에, 추가 SNS의 계정별 사용 설정은 P4에 배정했다. 외부 로그인·비밀 보관·실행 연결은 별도 후속 범위로 남겼다. 공통 ContentStore 계약과 HTTP 오류·한도를 맞췄으며 검토 중점 5개를 각 소유 시험에 연결했다. 기존 운영 설계의 승인·실행·배포 상태는 콘텐츠 편집 상태와 합치지 않는다. 이 문서는 향후 구현 계획이며 시험 통과 기록이 아니다.
