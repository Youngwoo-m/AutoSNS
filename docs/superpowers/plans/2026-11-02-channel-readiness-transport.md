# 채널 연결 준비 상태와 명시 Threads 전송 경계

기존 네 메뉴를 유지하며 개인/학과 계정 연결 화면에 접힌 채널별 준비 상태를 추가한다. 구현된 코드·저장된 연결 기록·실제 로그인/실행을 구분하고 플랫폼별 다음 조치를 한국어로 표시한다. 원본 자동 작업 상태를 관리 웹의 상태와 혼동하지 않는다.

- 순수 manifest는 현재 서버 등록부만 받아 9개 채널의 개인·학과별 연결/미등록 상태를 만든다. 토큰·경로·scope·자격 저장소·외부 API에 접근하지 않는다. 구현 여부는 서버 코드 등록 사실이며 실계정 수락 완료가 아니다.
- 인증된 GET /api/v2/channels/readiness?account=...에서 조회하며 저장된 OAuth overlay가 있으면 읽기 전용 projection만 반영한다. 연결·기동·로그인·발행 변이는 하지 않는다.
- 접힌 UI는 펼칠 때만 GET하고 계정 전환의 늦은 응답을 차단한다. raw reason code 대신 필요한 등록/대상 확인/수락 조치를 표시한다. 기존 OAuth/연동 화면과 동작은 보존한다.
- Threads HTTPS transport는 고정 host·허용된 요청·응답 크기·TLS·오류 정리·리다이렉트/재시도 금지 계약을 구현한다. 생성자는 I/O가 없고 명시 서버 활성화 없이는 전송하지 않는다. RFC6750의 Bearer header를 구현하되 Threads의 실제 허용·host 수락 검증은 미완료다. 기존 client의 기본 transport=None와 OAuth 정책 차단은 유지한다.
- 가짜 HTTPS 연결/임시 HTTP/DOM으로 비밀 비노출·기본 비활성·계정 결속·상태 표시·무변이를 검증한다. 실제 TLS/API·OAuth·로그인·발행은 실행하지 않는다. 실제 앱/비용/권한 계약과 운영 수락은 필수 미완료 범위다.
