# 공개 검증 게시물의 명시 성과 수집

기존 네 메뉴와 성과 조회·CSV·과거 자료 가져오기를 유지하며, 성과 화면 안에 접힌 수집 패널을 추가한다. 기존 목표의 실제 성과 연결 구현이며 개발 완료 후 종합 검토한다는 지시에 따라 중간 승인 질문을 반복하지 않는다.

- 서버가 기존 원장과 등록부에서 공개 검증 완료 게시물의 계정·채널·원격 ID를 조회한다. 클라이언트는 delivery_id만 제출한다. 예약·미검증·불명확한 게시물은 대상이 아니다.
- 명시 활성 수집 서비스와 등록 collector가 있을 때만 원본 공통 잠금 안에서 원장을 재검증한 뒤 수집·관측 저장한다. 발행·원고·예약 상태는 바꾸지 않는다. 생성자·GET·목록은 자격·API를 호출하지 않는다.
- YouTube 수집기는 불변 채널·영상 ID·공개 상태를 확인하고 조회수, 제공되는 좋아요·댓글 수만 lifetime 관측으로 정규화한다. 빠진 값은 0으로 채우지 않으며 비공개 응답·예외·토큰 원문을 저장하지 않는다.
- GET /metrics/collection-targets?account=...는 안전한 대상 목록과 활성 여부만 반환한다. POST /metrics/collect {delivery_id}는 명시 수집 한 번이다. 기본 서비스 없음·비활성을 유지하며 자동 OAuth/실계정 수집을 켜지 않는다.
- 임시 원장·가짜 SDK·HTTP·DOM으로 잠금·계정·대상·오류·입력 보존·동시 요청과 기존 성과 조회 회귀를 검증한다. 실제 자격/수집 운영 기동·실성과 수락은 남은 필수 작업이다.
