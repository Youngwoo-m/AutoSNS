# 계정별 콘텐츠 운영 구현 순서

## Instagram 이미지·REELS·캐러셀 기반

순수 자산 선택 payload, Facebook Login 경로의 명시 API client, 실제 바이트와 승인 문맥을 결속하는 공개 미디어 공급자 주입 경계를 추가했다. 이미지·영상·캐러셀 순서를 자동 선택/변환/절단하지 않는다. 기본 네트워크·공급자·최종 승인 guard는 미등록이며 관리 웹의 기존 실행 상태도 바꾸지 않았다. 가짜 공급자와 HTTP 조립 시험은 선택 자산의 순서·원문·소유자와 배포 계정·실제 바이트 해시·URL 영수증의 전달을 검증한다.

이어서 선택 형식/자산 순서의 계획 저장, 저장된 계획의 수동 최종 검토·철회와 인증 HTTP/접힌 패널, 실제 원고/선택 자산 재검증을 연결했다. 원격 전송 서비스와 leaf 원장은 staging·각 컨테이너·publish 시작을 먼저 보존하고 불명확한 요청을 반복하지 않는다. 실제 review·ContentStore·Ledger·media factory·client·서비스·원장을 가짜 공급자로 연결한 시험에서 미검토/철회·권한 변경·순서 변경·URL 만료를 검증한다.

공통 adapter/bridge와 원본 전달 영수증 기반 공개 검증·읽기 복구를 연결했다. 실제 원격 캡션·형식·첫 자식 ID 순서 핀·공개 URL을 대조하며 변환된 원격 미디어 해시는 None으로 남긴다. 공개 probe가 없거나 원본 영수증이 없으면 완료하지 않는다. 가짜 HTTP와 실제 저장소를 연결한 시험에서 3가지 형식과 unknown 응답 유실의 무재게시 복구를 검증했고, 실제 BridgeHost의 permit/부모 잠금/자격/STOP 경계도 별도로 검증했다.

실제 공급자 기동/native bootstrap 수락·새 인증 문맥의 안전한 컨테이너 복구는 후속 필수 범위다. 실제 공개 호스팅/노출 동의·회수, 프로페셔널 계정 권한, Instagram Login 및 직접 resumable 영상 계약·수락도 남아 있다. 기존 23개 교차 규칙 중 Instagram 3개는 legacy 소유를 보존하며 전환하거나 다시 실행하지 않았다. 실제 게시 완료나 전체 프로그램 완료로 간주하지 않는다.

## 2026-11-02 Facebook Pages 연결 기반

개인·학과별 승인 원고를 Facebook 페이지 텍스트로 준비하는 순수 변환과 명시 API 버전의 요청·응답 client 경계를 추가했다. 원문·계정별 변형·자산을 보존하며 기본 transport는 비활성이다. 로그인 주체와 페이지 ID·페이지 자격을 구분하고, API 공개 플래그만으로 공개 검증을 완료하지 않는다. 시험은 가짜 전송만 사용한다.

Facebook 연결은 실제 등록부에 아직 없으며 기존 23개 교차 규칙과 운영 스케줄을 유지한다. 이어서 단일 POST 영속 원장·adapter·handler·공통 승인/실행 원장·텍스트 전용 계획 화면·공개 URL 저장까지 연결했다. 실제 client부터 공통 원장까지의 가짜 HTTP 통합 시험은 원본 이미지가 있는 개인 원고→학과 페이지 변형, 응답 유실의 중복 방지, 공개 probe와 빈 원격 첨부 관측을 검증한다. 실제 전송·페이지 권한 attestor·익명 공개 probe와 native bootstrap은 여전히 미등록·비활성이다. 실제 인증·권한·페이지 tasks·비용·게시·공개 수락과 전체 채널·성과·경로 이행·외부 접속은 계속 필수 미완료 범위다. 상세는 `docs/runbooks/facebook-pages-publication.md`를 따른다.

사용자 최신 기준: 상위 메뉴 4개, Claude Max 협업, 개발 완성 후 종합 검토. 콘텐츠 자체의 발행 전 검토는 유지한다.

## 완료된 화면 연결
- 개인/학과 계정 연결과 콘텐츠 발행 네 메뉴, 기존 보조 기능 유지.
- 계정별 신규 기획 소유자 기본값, 원본과 교차 게시 대상 분리.
- 원고·버전·자산·수동 검토·배포 계획·실행 원장·로컬 도구 화면은 기존 구현을 재사용한다. 실제 실행과 원격 연결 완료를 뜻하지 않는다.

## 제작부터 완성하는 다음 순서
1. 제작 전용 서버/worker 조립: 발행 adapter를 연결하지 않는 명시 startup factory, 기본 비활성, 가짜 공급자로 HTTP 요청→불변 산출물 통합 검증.
2. 구독 제작 공급자 설치·격리·로그인 상태 검증과 실제 원고 제작 연결. 비용 우회와 묵시적 fallback 없이 명시된 구독 범위를 유지한다.
3. 이미지·음성·숏츠 제작과 미디어 검증·버전 보존. 기존 Remotion 및 계정별 제작 규칙 적용.
4. 채널별 실제 OAuth/대상 확인·예약·교차 발행·공개 검증·후처리 연결. 기존 교차 경로와 잠금·STOP·한도·중복 방지 유지.
5. 실제 성과 수집, 개인/학과 데이터 경로 이행, Mac·휴대폰 외부 접속.
6. 전체 프로그램 종합 검토와 실제 운영 수락 검증.

위 항목은 목표 전체의 남은 범위다. 가짜 API·임시 저장소 시험만으로 실계정 연결이나 실제 제작·발행 완료를 주장하지 않는다. 기존 OAuth 복구 수용 검증의 미완료 항목도 마지막 종합 수락에 포함한다.

## 2026-11-02 제작 조립 구현
Claude Max가 제작 전용 startup factory와 통합 시험 초안을 작성하고 Codex가 웹 접수 연결 시험, 발행 기능 비노출/거부와 미등록 공급자 상태를 보완했다. 신규 `production_startup.py`는 기본 비활성, 명시 초기화, 수동 worker 실행 계약으로 기존 실행 서비스를 조립한다. 실제 8769의 기본 기동은 변경하지 않았다.

다음 구현은 신뢰된 기동 설정에서 이 factory를 선택하고, 실제 구독 공급자/계정별 제작 작업/한도 관측을 결속하는 경로다. 현재 단계의 가짜 공급자 통합 검증을 실제 원고 제작 완료로 간주하지 않는다.

## 제작 웹 기동 경로 구현
Claude Max와 함께 `production_application.py`를 추가했다. Codex는 기존 채널·교차 게시를 유지하는 조회/실행 등록부 분리, 명시 저장소 준비, 실제 로컬 HTTP와 가짜 worker 연결, 기동 실패 경합을 보완했다. 기본 서버 기동을 전환하거나 실제 모델을 호출하지 않았다. 현재 남은 핵심은 실제 구독 공급자·기동 설정과 제작 작업/한도 관측의 연결이다.

## Claude 구독 공급자 연결 구현
설치·인증·도구 격리 검증 어댑터와 제작 서비스의 `subscription_runner` 결속을 추가했다. 실제 CLI 최소 probe가 성공했고, 가짜 프로세스를 사용해 정책/계정/명령 주입과 공급자→worker→불변 원고의 경로를 검증한다. 실제 콘텐츠 제작·기동 전환·제작 quota 정책 생성은 실행하지 않았다. 다음 필수 작업은 명시된 계정별 제작 작업·한도 정책과 기동 설정을 UI에서 준비하는 경로다.

## 계정별 제작 설정 반영
Claude Max가 설정 저장소와 제작 등록부 컴파일러를, Codex가 인증된 HTTP·화면·실행 연결 시험을 구현했다. 개인/학과 발행 화면에 접힌 제작 설정 패널을 추가했다. 계정별 CAS 저장, 미저장 이탈 보호, 다른 계정 응답 차단과 기존 운영 DB 무변이를 검증했다. 화면 회귀 267개, 서버/기동 37개와 별도 설정→제작 worker 연결 시험을 통과했다.

운영 기본값은 사용 안 함/한도 미지정이다. 실제 기동 명령에서 저장 설정을 읽어 구독 실행기를 검증하고 기존 quota를 보존하며 명시된 관리 제작 횟수 관측을 연결하는 작업이 남아 있다. 실제 콘텐츠·미디어 제작, 원격 채널 연결·발행·성과·외부 접속도 계속 필수 범위다.

## 명시 제작 기동과 일일 창 보존
저장 설정을 읽는 `production_main.py` 명령과 `production_quota.py`를 추가했다. 기본은 무변이 점검이고, 명시 기동 시에만 초기화/검증/worker를 연결한다. 실제 관리 저장소 점검은 두 계정 비활성으로 확인했다. 기존 사용·예약을 유지한 capacity 변경, 날짜 변경 이후의 제작, 한도 초과 추가 공급자 호출 차단을 가짜 공급자로 검증했다.

제작/발행 운영 전환은 여전히 비활성이다. 다음 필수 범위는 실제 원고 제작 수락과 이미지·음성·Remotion 숏츠 제작 경로, 채널 인증·발행·공개 확인·성과·외부 접속이다.

## 형식별 원고 제작과 실제 구독 수락
글·카드뉴스·숏츠/영상 대본의 제작 규칙을 연결했다. Claude Max와 함께 순수 prompt builder를 작성하고 Codex가 기존 제작기/원본 보존/입력 중복 절감과 실제 구독 수락을 검증했다. 격리된 저장소에서 검증 원고 한 편이 revision 2로 생성되어 검토 대기로 저장됐고, 재접수 추가 호출과 운영 DB 변경은 없었다.

전체 프로그램이나 실제 채널 발행 수락이 끝난 것은 아니다. 이어서 미디어 제작 경로와 채널별 인증·예약·교차 발행·공개 검증·성과·외부 접속을 완성한다.

## 버전별 미디어 계획과 제작기 경계
Claude Max 두 작업으로 계획 저장소와 편집 패널을 병렬 구현했다. Codex가 원고 편집기 보호, 인증 HTTP, 고정 자산의 Remotion 연결과 검증 산출물 CAS 등록을 추가했다. 화면 276개, 서버/미디어 53개 시험을 통과했고 격리된 브라우저에서 계획 저장을 확인했다. 실제 사용자 원고·미디어 생성과 렌더·Voicebox 실행은 하지 않았다.

다음은 미디어 실행 원장과 Voicebox/등록 Remotion 공급자의 실제 기동 경로, 미디어 검토 증거 수집이다. 새 계획 UI로 전체 자동 제작·발행 목표가 완료됐다고 간주하지 않는다.

## 음성·영상 제작과 계획 연속성
음성 작업 원장·명시 기동, 영상 작업 원장·고정 Remotion 등록·수동 영상 검토와 자산 등록, 이미지 재사용 확인까지 구현했다. 기본 웹의 실제 제작·발행은 활성화하지 않았다. 이전 계획을 새 원고 버전에 명시적으로 가져오는 경로를 추가하여 음성 제작이 만든 새 버전에서도 이미지·장면·자막을 재작성하지 않고 새 WAV를 선택할 수 있게 했다. 가져오기는 같은 소유자와 실제 자산 바이트, 소스·대상 계획 버전을 대조하고 검토·승인은 복사하지 않는다.

남은 제작 필수 범위는 비용 없는 실제 이미지 제작 경로와 등록, 설치된 실제 음성 서비스 계약 확인, 실제 음성·영상 품질 수락 및 명시 운영 기동이다. 이후 채널별 실제 OAuth·예약·교차 발행·공개 검증·성과 수집·계정 경로 이행·외부 접속과 전체 종합 수락을 계속 진행한다. 가짜 공급자의 통합 시험은 실제 미디어 품질이나 전체 운영 완료의 증거가 아니다.

## 로컬 카드·절차 도식 이미지 경로
공용 LocalCard 정지 이미지 제작기와 작업 원장, 계정별 원고 자산 등록, 접힌 이미지 패널과 명시 기동 설정을 연결했다. 기존 학과 카드뉴스·영상 템플릿은 보존한다. 고정 입력·소스·글꼴·브라우저 경로와 공통 renderer 잠금을 사용하며, 자동 모델·외부 사진·유료 호출·브라우저 다운로드를 하지 않는다. 실제 생성 시에는 generated 출처를 원장에 보존하고 자산·검토는 분리한다.

원고 CAS·멱등 작업·불명확한 결과 재실행 차단·결과 등록만 재개를 가짜 PNG와 임시 저장소로 검증했다. 실제 설치 소스와 글꼴의 읽기 검사는 통과했지만, 실제 렌더·한글 레이아웃 품질과 운영 활성화는 아직 검증하지 않았다. 기본 이미지 설정은 비활성·브라우저 미등록이다. 디오라마/임의 그림 제작, 실제 음성 서비스 계약과 음성·영상 품질 수락, 이후 SNS 실연결·운영·성과·외부 접속은 계속 필수 범위다.

## 계정별 음성 프로필 준비
개인·학과 콘텐츠 발행 메뉴에 다음 기동용 음성 설정을 추가했다. 계정별 CAS 저장과 신뢰된 서비스 매핑을 연결하고, 실제 원고/작업 소유자로 공급자를 선택한다. 공용 CLI 프로필은 호환 모드로 보존한다. 저장만으로 음성 서비스를 켜지 않으며 비활성 계정은 다른 계정에 fallback하지 않는다. 실제 Voicebox API/모델·음성 품질 수락과 운영 활성화는 여전히 미완료다.

## YouTube 공개 증거 연결
기존 YouTube 검증이 원격 변환 영상의 원본 바이트 해시를 얻지 못해 영구 대기하던 경로를 보완했다. 실제 바이트를 확인한 미디어 factory의 typed 봉투와 SDK 원격 ID로 업로드 영수증을 저장하고, 공통 검증기가 영속 제출 원장·승인 snapshot·새 공개 관측을 결합한다. 과거 영수증 없는 게시와 unknown 제출은 계속 자동 완료하지 않는다. 로컬 해시를 원격 해시로 만들지 않으며 블로그 검증과 23개 교차 게시 규칙은 보존한다.

실제 계정 접속·업로드·공개 수락은 하지 않았다. OAuth→발행 자격 브리지, Instagram·Threads·X·Facebook·TikTok adapter, 블로그 미디어 공개 증거, 실성과·외부 접속과 전체 종합 수락은 계속 남아 있다.

## 명시 성과 수집 연결
공개 검증 완료·등록 수집기 대상 목록과 명시 수집 HTTP·화면을 연결했다. 원격 식별자는 서버 원장으로 정하고 원본 프로필/계정/연결 잠금 안에서 재검증한 뒤 별도 관측을 저장한다. YouTube의 공개 영상 조회수와 제공되는 좋아요·댓글 수를 lifetime으로 보존하며, 기존 조회·CSV·과거 보고와 기획제안 기능은 유지한다. 수집 구현과 실제 권한 확인을 구분해 표시한다.

고정 기동 설정과 별도 --enable-metrics를 추가했으나 기본은 비활성이다. 실제 자격 접근·수집·운영 스케줄 전환은 하지 않았다. OAuth→발행 자격 브리지, 추가 SNS 발행/공개 확인/성과, 실제 운영 수락, 데이터 경로 이행·Mac/휴대폰 외부 접속과 전체 종합 수락은 계속 남아 있다.

## 관리 OAuth 자격 읽기 브리지
새 소유 자격 참조를 기존 Google 읽기 서비스에 전달하는 서버 경계를 추가했다. 작업공간·계정·플랫폼·연결·대상·세대·실관측 범위·만료를 검증하고, 읽기 handler 전체에서 OAuth writer guard를 유지한다. Google SDK 변환은 이 guard 안에서만 수행하며 실제 vault/API를 기본 활성화하지 않는다. 기존 고정 암호화 자격 경로는 보존한다.

새 자격의 발행 권한 확인 모델은 아직 없으므로 publication scope와 실제 submit은 원격 요청 전에 거부한다. 실제 OAuth 비용·앱 등록 차단, 운영 child bootstrap, 신규 SNS adapter와 실계정 수락은 그대로 미완료다. 이번 메모리 vault·가짜 SDK 시험은 실제 OAuth/발행 완료의 증거가 아니다.

## Threads 텍스트 발행 기반
Threads의 명시 텍스트 전용 payload, API client 경계, 컨테이너/게시 영속 journal, adapter·host 조립과 공개 증거 결속을 추가했다. 준비 옵션은 계획 승인에 보존하며 기존 미디어 자산은 변경하지 않는다. 응답 불명확 시 자동 재게시하지 않고, owner API만으로 공개를 추정하지 않는다. 가짜 공개 probe가 확인한 실제 URL은 영속 원장에 저장되는 경로를 시험했다.

기본 네트워크 전송·실제 익명 probe·child bootstrap은 미등록이며 새 OAuth 발행 차단도 유지한다. 실제 인증 헤더/host·앱/비용/권한 계약과 실게시 수락이 남아 있다. Threads 미디어·다른 SNS adapter, 실제 OAuth 발행 브리지·운영 전환·성과·계정 경로 이행·외부 접속과 종합 수락은 계속 필수 범위다.

## 채널별 준비 상태와 명시 Threads 전송

Threads의 기본 비활성 HTTPS transport 코드도 추가했다. 실제 인증 헤더와 host 수락, 앱/비용/권한 계약은 미검증이며 기본 client와 native child는 활성화하지 않았다. 실제 SNS 운영·공개 probe·추가 발행기·성과·계정 경로 이행·외부 접속 및 종합 수락은 계속 남아 있다.
