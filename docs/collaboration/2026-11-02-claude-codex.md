# Claude·Codex 협업 기준

## 수정된 최종 목표
개인·학과 계정의 연결과 콘텐츠 기획·제작·예약·채널별 교차 발행·공개 확인·성과를 웹에서 운영한다. 상위 메뉴는 개인 계정 연결, 학과 계정 연결, 개인 콘텐츠 발행, 학과 콘텐츠 발행 4개로 통합한다. 기존 기능과 교차 게시 경로를 보존한다.

개발을 먼저 완성한 뒤 종합 검토한다. 이 변경은 실제 콘텐츠의 발행 전 검토·승인을 생략한다는 뜻이 아니다.

## 역할과 이번 작업
Claude Max 구독 CLI: 격리된 화면 복사본에서 4개 메뉴와 계정별 탐색 구현. Codex: 기존 변경 보존, 통합, 최종 검증. 유료 API 우회·실제 로그인·발행·운영 스케줄 전환은 이번 개발에 포함하지 않는다.

1. 현재 화면을 별도 작업 폴더에 복사하고 Claude에 제한된 구현 작업 전달.
2. 계정별 연결/발행 탐색 통합과 기존 기능 접근 보존.
3. 제작 완료 후 계정 전환·미저장 가드·모바일·회귀 시험 종합 검토.
4. 검증된 결과만 반영하고 한계와 후속 범위 기록.

기존 OAuth 복구 문서의 미커밋 변경은 보존한다. 이전 단계 미완료 작업은 삭제하거나 완료로 간주하지 않는다.

## 이번 협업 결과
Claude Sonnet(Max 구독 CLI)이 격리된 복사본에서 4개 메뉴와 계정별 탐색을 구현했다. Codex가 최종 통합하면서 계정 연결 화면의 null 표시 방지, 성과 입력의 이탈 보호, 새 모듈의 서버 허용 목록을 보완했다. 8769에 적용했으며 원본 8700과 실제 발행 작업은 변경하지 않았다.

검증: Node 화면 회귀 256개 통과, 서버·로컬 도구 수용 시험 34개 통과. 브라우저에서 학과 연결, 학과 발행, 개인 발행 전환을 확인했다. 390px 휴대폰 폭은 상위 메뉴를 두 열로 배치한다.

한계: 새 기획의 원본 소유 계정은 편집기에서 직접 선택해야 한다. OAuth 결과 복귀의 기존 전체 계정 조회는 유지한다. 실제 SNS 인증·발행 활성화와 기존 미완료 OAuth 복구 수용 보완은 별도 미완료 범위다. 이 결과는 전체 프로그램 완성을 뜻하지 않는다.

## 계정별 제작 흐름 후속 구현
개인·학과 발행 메뉴에서 새 기획을 열면 해당 계정을 소유자로 지정한다. 새 복사본의 소유 계정만 현재 메뉴를 따르며 기존 관리 원본의 소유권은 바꾸지 않는다. 변환본 추가의 기본 게시 대상은 원본 계정이며 계정 간 교차 배포를 계속 선택할 수 있다. 계정 기본값만 적용한 빈 초안은 미저장 경고가 발생하지 않는다.

Claude Max가 편집기 구현, Codex가 메뉴 컨텍스트 연결·시험을 담당했다. 전체 화면 회귀 263개 통과. 추가 시험 7개는 두 계정 신규 저장 payload, 잘못된 컨텍스트 fallback, 기존 원본·교차 변환 보존, 수집 요약 복사, 변환본 기본값, 늦은 조회 응답의 계정 침범 방지를 확인한다.

브라우저에서 학과 새 기획의 학과 소유 기본값과 계정 선택 잠금을 확인했다. 실자료 저장·SNS 발행은 실행하지 않았다. 실제 모델 제작 실행과 공급자 인증, 외부 접속·성과 수집은 여전히 후속 필수 범위다.
