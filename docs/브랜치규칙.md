# 브랜치 규칙 (2026-10-21)

AutoSNS 는 자동 작업(launchd)이 `main` 폴더의 파일을 그대로 읽는다. 그래서 `main` 은 항상 동작하는 상태로 둔다.

## 브랜치

| 브랜치 | 쓰임 |
|---|---|
| `main` | 자동 작업이 읽는 동작 상태. 직접 커밋은 작은 수정·문서뿐 |
| `claude/<계정>-<영역>-<해시>` | 영역별 세션의 워크트리 브랜치(세션이 만든다). 계정은 폴더 트리와 같다: `dept`(학과: dept/ 아래 채널), `personal`(개인), `common`(공통: common/ 아래). 예: `claude/dept-youtube-shorts-ab12cd`, `claude/personal-geoai-…`, `claude/common-shared-core-…`. 기존 영역 이름(console, writing, media, claude-jobs, insta, blog-publish, analytics, shared-core, site)은 계정 뒤에 그대로 붙인다. 기존 브랜치는 이름을 바꾸지 않는다(2026-10-25 개편 이전 것) |
| `backup/<설명>-<날짜>` | 큰 작업 전 되돌림용 태그. 지우지 않는다 |
| `insta-manual-public` | 별개 저장소 이력. 건드리지 않는다 |

## 작업 순서

1. 세션은 자기 워크트리·브랜치에서만 작업한다. main 폴더의 파일을 직접 고치지 않는다.
2. 병합 전에 main 을 먼저 합친다(sync). 폴더 이동 같은 큰 변경 뒤에는 필수.
3. `git diff main..<브랜치> --stat` 으로 비밀값(config.json·토큰·쿠키·`chrome-profile-*`·backups/)이 섞이지 않았는지 본다.
4. 영역별로 하나씩 main 에 병합한다. 병합 전에 `python3 shared/axlock.py status` 로 실행 중인 자동 작업이 없는지 본다.
5. 푸시는 대상 저장소·브랜치를 정해 사용자 승인을 받은 것만. 강제 푸시·이력 다시 쓰기·원격 브랜치 삭제는 따로 승인.

## 주의

- `git add -A` / `git add .` 금지. 경로를 지정해서 add 한다(로그인 세션 폴더가 섞일 수 있다).
- 남의 미커밋 변경은 stash·reset --hard·checkout -- 로 지우지 않는다.
- 여러 영역에 걸친 변경(예: shared + 채널 코드)은 한 커밋에 담고 메시지에 영역을 적는다.

## 커밋 메시지

한국어, 첫 줄에 무엇을 왜 바꿨는지 한 문장. 끝에 줄 하나 띄우고 공동 작성 줄을 붙인다.

```
콘솔: 콘텐츠 탭 동작 버튼을 편집 창 위로 옮김

Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>
```
