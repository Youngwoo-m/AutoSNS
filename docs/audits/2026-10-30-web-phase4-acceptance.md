# 운영 웹 4단계 검증 기록

2026-10-30. 사용자 승인 범위는 실행 원장·정지·한도·중복 방지·복구 화면 구현이다. 실제 계정 발행과 기존 스케줄 전환은 비활성이다. 이 문서는 최종 수락 작업 중이며 마지막 검증·개발 서버 이행 결과를 아래에 확정한다.

## 구현 경계

- 기존 plan/dry 컨텍스트·계획 승인은 보존하고 별도 publication 컨텍스트·승인·독립 검토 영속 저널을 추가했다. 승인된 원고/변환본/자산 bytes와 대상·정책·검토 근거를 제출 전 다시 확인한다.
- v3 실행 원장에 회차·lease·시도·일회성 permit·다차원 한도·근거·관리 중지를 저장한다. 생성/GET는 DB 생성·이행이나 원본 파일 쓰기를 하지 않는다. 명시 initialize만 additive 이행한다.
- source_root별 AxLock으로 프로필 별칭·제어 관문을 공유한다. STOP clear/stopped/unknown을 구별하며 손상/접근 오류도 신규 제출을 차단한다. 프로필 대기·제어 잠금·DB 대기 후 만료를 재검사한다.
- 제작 단위 비용은 원본/버전/manifest/서버 production ID로 한 번 계산하며 여러 기간 예산을 동시에 적용한다. 대상 게시량·공용 API는 배포별이다. unknown 사용량은 보류한다. 실제 생성기·과금은 호출하지 않았다.
- 원격 요청 시작 뒤 응답 유실/저장 실패는 자동 재전송하지 않는다. 강한 대상/게시 ID/시각/본문·미디어 지문으로 조회·검증한다. 예약은 공개 전 verified가 아니다.
- 재개는 이전 worker full identity dead·lease 만료·선택 대상 잠금 free·최신 승인/정책·CAS를 요구한다. 같은 회차의 unknown 형제를 보존하면서 선택한 미제출 대상만 영속 선택 범위로 재개한다. 원격 삭제와 로컬 취소는 구별한다.
- 웹은 서버 소유 policy/adapter/probe만 사용한다. 기본 adapter/probe는 미등록, 실행 정책 disabled다. 기존 전역 STOP은 관측 전용이고 관리 중지는 별도 관리 DB에만 적용한다.

## 자동 시험 증거

- 저장소/잠금 초기 독립 검토 후 전체 Python 180개 통과(23.525초). 이후 변경의 최종 통과 근거는 아래 최종 실행으로 갱신한다.
- 실제 공통 worker→permit 소비→가짜 원격 수락 후 응답/원장 실패→DB 재개방→만료 복구→lookup→공개 verify에서 누적 submit=1을 확인했다. 독립 통합 수락 5개와 operations 186개가 구현 시점에 통과했다.
- 별도 프로세스 프로필 시험은 부모 naver 잠금에서 자식 tiktok/youtube-dept 획득 거부, 개인 tistory 독립, 해제 후 자식 획득 성공을 확인했다. 실제 로그인 폴더를 열지 않았다.
- 운영 HTTP 20개 통과(3.744초): 인증/Origin/query/body 위조 차단, source 무쓰기, 관리 CAS·동일 요청키, 실제 S5 복구·동일 ID 재개, 취소 뒤 remote_uncertain 유지와 재취소 차단을 포함한다.
- 최종 전체 Python: `python3 -m unittest discover -s tests -p 'test_*.py'` **343개 통과**,39.546초. Node: `node --test tests/*.mjs` **74개 통과**,336.962ms. 실패·skip·warning 없음. 코드 기준 `0a3f21b`. 로그는 `/private/tmp/autosns-phase4-final-{python,node}.log`.

## 실제 브라우저 증거

검증 서버 8768은 임시 source/인증/관리 자료만 사용했다. 화면의 ‘검증 자료’ 공개 완료/예약/unknown은 가짜 어댑터·로컬 fixture이며 실제 채널 실적이 아니다.

1. 1280px에서 원본 제목·계정/채널·계획/실행 상태·시도·안전 근거·비활성 이유를 확인했다. 복구 JSON은 고급 항목으로 접고, 로컬 취소는 검토 메모만으로 기록했다.
2. 메모 작성 뒤 새로고침해 입력을 보존했다. 두 번째 창에서 먼저 로컬 취소를 기록한 뒤 첫 창 저장은409로 거부하면서 원래 메모·버전을 유지했다. 사용자 확인창을 호출하지 않고 검증 초안을 명시 폐기했다.
3. 로컬 취소 뒤에도 remote_uncertain=true인 기록이 전체 문제/게시 여부 불확실 필터에 남고 별도 경고를 표시함을 확인했다.
4. 320px에서 document/body/viewport 폭이 모두320이었다. 메뉴·카드·취소 경고에 문서 가로 넘침이 없었다.
5. 관리 중지·재개 연속 동작의 최신 CAS 버전 처리를 보완한 뒤 같은 창에서 재개→중지→재개가 첫 요청으로 성공했다. 브라우저 warn/error는0건이었다. 임시 runtime 회차는4개로 같고 관리 제어 이력만4개 생겼으며 임시 source STOP은 계속 부재였다.

## 개발 서버 갱신·자료 보존

현재 실제8769는 이전 개발 프로세스를 보존 중이다. 새 app 통합은 HEAD에 기록했으나 실행 중 구버전 static allowlist와 충돌하지 않도록 작업 파일을 잠시 이전 상태로 유지했다. 최종 검증 후 소유 서버만 종료하고 SQLite backup API+콘텐츠 백업→v3 명시 이행→새 서버 시작→조회/정책·원본 불변 검증 결과를 이 절에 기록한다. 기존8700/launchd/큐/로그인 프로필은 변경하지 않는다.

## 판단과 틀렸을 때의 비용

실행 중 판단 기록을 원래 순서대로 남긴다. 원장은 구현 검토의 대체물이 아니다.

| 순서 | 판단 | 근거와 비용 |
|---|---|---|
| 1 | 사용자 지정 병렬 에이전트 유지, 파일 소유 분리 | 인터페이스가 어긋나면 통합 재작업. 공통 계약과 작업별 검토로 제한 |
| 2 | runtime SQL을 RuntimeStore에 집중하고 원자 메서드 공개 | 후속 요구에 reviewed 메서드 추가 필요, 임의 SQL 호출은 금지 |
| 3 | subscription_only는 새 runtime 정책, legacy 과금 보호 완료와 구별 | 실제 격리 제작기는 T12에서 여전히 구현해야 함 |
| 4 | S2의 독립 잠금을 S1과 병렬 구현 | 저장소 연결 부분은 계약 확정까지 대기. 잠금 API 변경 시 조정 비용 |
| 5 | 웹 파일 지도는 실제 app/web 디렉터리로 정정 | 동작 변경 없음. 잘못되면 import/정적 서빙 수정 필요 |
| 6 | S6를 독립 UI와 서버 통합으로 분리 | 응답 계약이 바뀌면 UI 수정. 전체 화면 수락은 별도 필수 |
| 7 | occurrence 읽기 투영을 저장소 API에 추가 | dispatch/recovery에 SQL 유출하지 않음. 공개 메타데이터 확장 검토 필요 |
| 8 | heartbeat는 DB 현재 lease·worker·generation을 권위로 사용 | 초기 토큰 뒤에도 정상 장기 작업 갱신 가능. 만료 DB lease 재생성은 금지 |
| 9 | prepare/verify에 별도 submit phase 추가 | 기존 회차 키는 보존. 실제 스케줄 어댑터가 단계 의미를 명시 이행해야 함 |
| 10 | 순수 S4 계약 작업은 S3 검토와 병렬 진행 | S3 인터페이스 변경 시 관문 연동 조정 비용 |
| 11 | 내부 plan reader와 명시 runtime run_id로 publication bootstrap | plan dry 회차 재사용 금지. 실제 호출자는 새 실행 회차를 제공해야 함 |
| 12 | S5의 독립 복구·검증도 S4와 병렬 진행 | 저장소 hunk 소유를 조정하고 최종 결합 시험 필요 |
| 13 | app 통합을 별도 보존해 이전8769 화면을 보호 | 최종 재적용/서버 갱신을 누락하면 새 UI가 보이지 않음. 증거와 해시 보존 |
| 14 | 명시 재개 대상만 영속 선택, unknown 형제는 보존 | 전체 차단으로 기능을 축소하지 않음. 잘못되면 선택/이전 generation 복구 재작업 |

부가 설계: 독립 검토는 콘텐츠 단위 영속 저널로 먼저 기록한다. 단순 보고서 개수로 독립 검토를 인정하지 않는다. 제작비는 배포 비용과 다른 생명주기를 가진다. 실제 생성 전 예산 통제와 채널별 과금 관측 연결은 T12 및 채널 운영 적용 수락에서 별도 입증해야 한다.

## 남은 전체 목표

실제 SNS 연결/어댑터(Instagram·Threads·X·Tistory·Facebook 포함), 발행 권한 없는 제작기·독립 검토 실행, legacy 진입점·스케줄 전환, 실제 공개 확인, 성과 수집·기획 순환, 보호된 Mac/휴대폰 외부 접속은 완료하지 않았다. 이번 단계의 fixture 검증을 실제 자동 운영 완료로 표시하지 않는다.
