# 운영 웹 1단계 검증 기록

검증일: 2026-10-30. 구현 기준: `721d873` 및 진로 숏츠 소유 계정 매핑 보완. 전체 자동 운영 시스템의 완료 기록이 아니라 화면·읽기 전용 조회 단계의 증거다.

## 실행과 데이터

- 신규 조회 서버: `http://127.0.0.1:8767`. `AX_SOURCE_ROOT=/Volumes/USB256/devAPP/AutoSNS`, 기존 인증 디렉터리와 명시적 LaunchAgents 경로를 사용한다. 기존 8700 서버와 발행 일정은 변경하지 않았다.
- 임시 자료·임시 인증 화면 시험: `http://127.0.0.1:8768`. 콘텐츠 제목에 `[검증용]`을 붙인다. 실제 발행 실적으로 사용하지 않는다.
- 8767 인증 조회 결과: 전체 원본 176·배포 247·채널 15, 학과 관련 원본 97·배포 77·채널 7, 개인 관련 원본 143·배포 214·채널 8. 관련 원본은 두 범위에 포함될 수 있으므로 합산하지 않는다. 모두 누적 로컬 기록이며 오늘 발행 수가 아니다.
- 공개 검증 완료는 모든 범위에서 0이다. 로컬 게시·예약 기록을 공개 검증으로 승격하지 않는다.
- 인증 없는 조회는 401, 지원하지 않는 POST는 405였다. 내부 인증키는 메모리에서만 사용하고 출력하지 않았다.
- accounts.json·automations.json·tasks.json·기존 auth.json·기존 sessions.json 5개 파일의 조회 전후 SHA256 및 mtime이 동일했다. 이는 점검 파일에 관한 증거이며 전체 디스크 불변을 뜻하지 않는다.

## 시험과 검토

- `python3 -m unittest discover -s tests -p 'test_*.py'`: 51개 통과(조회 모델20·HTTP22·기존 watcher9).
- `node --test tests/test_web_frontend.mjs`: 11개 통과.
- 각 작업 독립 검토에서 세션 파일 충돌·비밀번호 변경 후 세션 유효·태블릿 캘린더 잘림을 발견해 수정했고, 수정 범위 재검토를 통과했다.
- 임시 브라우저에서 8개 메뉴 제목·콘솔 오류 없음, 1280/320px 문서 폭 일치, 800px 캘린더의 7일 표시와 문서 폭 일치, 페이스북 카탈로그와 연결 미확인·웹 실행 미연결을 확인했다.
- 전체 단계 독립 최종 검토에서 critical/important 지적이 없었다. minor인 `publish_career` 소유 계정 매핑 누락은 실제 생산 코드와 대기열 fixture를 근거로 보완했고 scoped 재검토에서 ADDRESSED 판정을 받았다.

## 남은 범위

기획 저장·불변 버전·자산·검토 귀속, 계정별 도구 연결 설정, 실제 제작·예약·발행·복구·성과, Mac/휴대폰 외부 접속은 후속 단계다. 현재 버튼 비활성은 해당 기능이 구현됐다는 의미가 아니다.

인증 구현 판단: 기존 비밀번호는 읽기 전용으로 공유하고 새 웹의 세션·쿠키는 분리했다. 기존 콘솔과의 세션 파일 충돌을 막지만 새 화면에서 한 번 더 로그인해야 한다. 비밀번호 변경·삭제·재생성은 새 웹 세션도 무효화한다.
