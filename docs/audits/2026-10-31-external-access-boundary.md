# Mac·휴대폰 외부 접속 경계 감사

2026-10-31, 저장소 코드 읽기 기준. 외부 접속 설계 확정·서버 관측·보안 수락·운영 완료 판정이 아니다. 서비스 실행, 네트워크 요청, 인증 파일 내용 열람, 제품 수정은 하지 않았다. 외부 접속은 최종 사용자 요구이며 localhost 시험으로 대체할 수 없다.

## 현재 경계와 재사용할 코드

| 경계 | 확인한 코드 근거 | 외부 접속 설계에 필요한 결정 |
|---|---|---|
| 소켓 | `ax-console/app/web_server.py:620`의 factory는 IP를 파싱하고 `:631`에서 loopback만 허용한다. `:694`의 AX_HOST도 이 검사를 통과한다. TLS 서버를 구성하는 코드는 이 factory에 없다. | 애플리케이션을 loopback에 유지할지, 어느 신뢰 경계에서 TLS를 종료할지 결정한다. 단순 0.0.0.0 변경은 현재 계약에 맞지 않는다. |
| Host | `web_server.py:273`은 정확한 allowed_hosts만 받으며 `:686`은 바인딩한 loopback host:port와 localhost:port만 생성한다. | 외부 도메인·포트 allowlist와 프록시→앱 Host 전달 규칙을 명시한다. 임의 Host를 허용하지 않는다. |
| Origin·교차 요청 | `web_server.py:278`은 Origin이 있으면 정확히 `http://Host`여야 하며 Sec-Fetch-Site=cross-site도 거부한다. `:268`은 중복 주요 헤더를 거부한다. | 외부 HTTPS Origin은 현재 거부된다. 공개 origin과 내부 origin의 관계, Origin 없는 요청, 신뢰 프록시 주소·헤더 정책을 명시해야 한다. 현재 검사는 동기화 CSRF 토큰 방식이 아니다. |
| 프록시 | `web_server.py:603`은 socket peer IP를 로그인 제한에 사용한다. `_validated_target`·`_authed`에는 Forwarded/X-Forwarded-* 신뢰 판정이 없다. | 전달 헤더를 무조건 신뢰하지 않고 어떤 프록시가 재작성하는지 고정한다. 현 로그인 제한은 프록시 뒤에서 사용자별이 아니라 프록시 IP 기준이 될 수 있다. |
| 쿠키 | `ax-console/app/auth.py:155`는 HttpOnly·SameSite=Strict·Path=/·Max-Age를 설정하며 Secure는 없다. `:25`는 최대30일/유휴3일이다. | 외부 HTTPS의 Secure 쿠키, 세션 수명·로그아웃/분실기기 대응을 정한다. proxy가 TLS를 종료해도 앱 쿠키 계약은 별도 검증해야 한다. |
| 인증·세션 | `web_server.py:178`은 기존 비밀번호/내부키 위치와 새 웹 전용 sessions·ax_web_session 쿠키를 분리한다. `:125`~175는 비밀번호 파일 버전과 세션을 결속해 변경 시 구세션을 무효화한다. `auth.py:111`~137은 임의 토큰의 해시 저장·유휴 만료를 구현한다. | 기존 비밀번호 인증을 외부에 어떤 추가 경계로 보호할지 결정한다. 이 감사는 비밀번호/키 값을 읽지 않았다. |
| 내부키 | `web_server.py:320`은 X-AX-Internal이 등록 내부키와 일치하면 세션 없이 인증한다. | 외부 경계가 내부키 헤더를 제거/차단할지, 내부 클라이언트가 어떤 경로로 접근할지 명시한다. 키를 웹/브라우저에 배포하는 방식으로 바꾸지 않는다. |
| 사용자·계정 권한 | `web_server.py:374`, `:383`, `:390`, `:396`, `:407`은 공통 `_authed` 확인이다. 실행 actor는 `:378`에서 console_user 고정이다. 조회 account=personal/dept는 `:294`~300의 필터이며 별도 사용자별 ACL이 아니다. | 현재 단일 운영자 콘솔 모델을 유지할지 결정한다. 개인/학과 필터를 로그인 사용자 권한 격리로 오해하지 않아야 한다. 다중 운영자를 지원하려면 별도 역할/쓰기 권한 계약이 필요하다. |
| 쓰기 범위 | `web_server.py:362`는 tools POST에 명시 초기화한 저장소를 요구한다. `:637`은 관리 저장소와 원본 루트를 분리한다. `:665`~679의 실행/도구 정책 및 서비스 주입은 별도이다. main `:694`~698은 실행 서비스와 enabled 정책을 주입하지 않는다. | 외부 접속 허용과 실제 발행 활성화를 분리한다. 조회, 원고·CSV 저장, 운영 제어, 발행 승인 각각의 허용 범위를 정한다. |
| 정적·자산 | `web_server.py:421` 이후 인증 뒤 정적 allowlist를 제공한다. `:333`~342는 resolve한 파일의 부모를 web_root로 제한한다. `:575`~581은 자산 Range 거부·등록 media type 확인·attachment 응답이다. | 외부 경계에서 인증 없는 정적/자산 우회 캐시를 만들지 않는다. 실제 휴대폰의 다운로드·큰 자산·세션 만료 UX를 시험한다. |
| 응답 보안·로그 | `web_server.py:221`은 URL/인증헤더/원본예외 요청 로그를 남기지 않는다. `:230`~234는 no-store/nosniff/no-referrer/frame deny/CSP를 설정한다. CSP에는 inline script/style 허용이 있다. | 프록시 로그의 쿠키·내부키·쿼리·본문 노출 여부를 별도로 확인한다. 현재 앱 로그 억제가 프록시 로그까지 보호한다는 증거는 없다. 외부 환경 CSP·오류 관측을 검토한다. |
| STOP | `ax-console/app/web/operations_panel.js:146`은 기존 전역 STOP을 읽기 전용으로 표시한다. `common/operations/publication_gate.py:158`은 실제 발행 관문에서 원본 잠금 경로의 STOP을 검사한다. `docs/runbooks/account-operations-cutover.md:35`는 잠금 대기·획득 후·외부 쓰기 전 STOP 확인을 요구한다. | 외부 화면의 정지 표시가 실제 원본 STOP/관리 정지를 혼동하지 않는지 확인한다. 네트워크 단절 중 정지·재접속·진행 중 작업 정지의 실제 수락이 필요하다. |

## 다음 설계의 필수 입력과 수락

1. 외부 접속 대상은 기존 사용자 선택대로 Mac과 휴대폰이며, 어느 주소·네트워크 경계에서 접근할지 정한다. 특정 외부 서비스·요금·가입은 이번 감사에서 추천하거나 가정하지 않는다.
2. 외부 HTTPS origin/허용 host/신뢰 프록시/쿠키/내부키 차단 계약을 한 묶음으로 설계한다. 현재 헤더 검사를 느슨하게 하는 것만으로 해결하지 않는다.
3. 개인/학과는 콘텐츠 소유·대상 구분이며 현재 사용자별 로그인 ACL이 아니라는 사실을 설계에 명시한다. 별도 운영자 권한이 필요하다면 추가 요구로 결정한다.
4. loopback 직접 접근과 외부 경계 접근을 모두 시험한다. 위조 Host·Origin·전달 헤더·내부키, 미인증 정적/자산/POST, 만료·로그아웃 세션, HTTPS 쿠키, 원고 저장 CAS 충돌 보존을 포함한다.
5. 실제 Mac·휴대폰 외부망에서 로그인·계정 전환·편집/다운로드·정지 표시·재시작/연결 복구를 확인한다. 실제 발행 활성화·스케줄 전환·키/프로필 이동은 별도 수락과 원복 범위를 유지한다.

이 문서는 코드상 경계를 구체화한 후속 설계 입력이다. 외부 접속 구현이나 보안 검증 통과로 표시하지 않는다.
