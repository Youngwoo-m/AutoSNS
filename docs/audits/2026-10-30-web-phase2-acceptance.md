# 운영 웹 2단계 통합 검증

검증일: 2026-10-30. 코드 기준 `98a561d`. 사용자 ‘2단계 개발 시작’ 승인에 따른 기획 저장·계정별 도구 사용 선호 구현이다. 실제 발행·외부 로그인·운영 전환은 포함하지 않는다.

## 확인한 기능

- SQLite·불변 파일로 원본·과거 버전·변환본·출처·자산·수동 검토를 저장한다. 원본 소유 계정은 생성 때 명시하며 이후 바꾸지 않는다.
- CAS의 expected_revision이 다른 두 번째 저장은409다. 실패한 요청이 이전 버전 또는 승자의 파일을 지우지 않는 저장소 시험을 통과했다.
- 관리 저장 루트는 운영 자료 루트와 분리한다. import와 server factory는 초기화하지 않으며 main에서 명시적으로 초기화한다. 미설정 상태는 조회 전용이다.
- 개인/학과·도구·연결 ID 복합키로 사용 선호를 저장한다. 설정 저장은 기존 자동 작업·Codex/Claude 플러그인 설치·로그인·발행 활성 상태를 바꾸지 않는다.

## 시험

- `python3 -m unittest discover -s tests -p 'test_*.py'`:82개 통과. HTTP28·콘텐츠 저장15·연동 저장5·연동 HTTP 도우미1·조회 조합4 및 기존 회귀 포함.
- `node --test tests/test_web_frontend.mjs tests/test_content_editor.mjs tests/test_integration_settings.mjs`:24개 통과.
- P1·P2·P4 독립 작업 검토에서 필수 수정 사항이 없었다. P3에서 ‘버리고 이동’ 확인 뒤 도구 설정 초안이 남는 문제가 발견돼 공개 discardChanges와 실제 상태 전이 시험을 추가했다. scoped 재검토에서 해결 판정을 받았다.
- 임시 인증·임시 자료의8768 HTTP에서 생성201→수정200→과거 원문 보존→오래된 버전409→버전2 수동 검토→자산 등록 버전3→자산 바이트 재조회→버전3에 검토 미승계→버전2 검토 보존을 확인했다.
- 같은 임시 HTTP에서 개인 원본·학과 페이스북 계획이 학과 조회에 남고 원본 소유는 개인인 것을 확인했다. 개인/학과에 동일 연결 ID의 페이스북 사용 선호 2개를 저장했으며 상태는 unknown/not_connected였다.
- 새 관리 기획은 배포·예약을 만들지 않았다. 임시 자료의 기존 배포3·일정3은 유지됐고 managed content_id를 참조하는 배포·예약은 없었다. 학과 범위 수와 전체 범위 수를 섞어 비교하지 않는다.

## 실제 화면 수락 검증

초기 브라우저 연결 오류는 CUA 세션 초기화 후 복구했다. 8768의 임시 인증·임시 저장소에서 다음을 직접 확인했다. 실제8769 관리 저장소에는 시험 콘텐츠를 넣지 않았다.

- 새 기획에서 소유 계정이 비어 있으며 개인을 직접 선택하고 원문·학과 페이스북 변환본을 저장했다. 저장 뒤 소유 계정 선택은 사라지고 고정 개인 원본으로 표시됐다.
- 수정으로 버전2를 만들고 버전1 선택 시 이전 원문이 그대로이며 저장 버튼이 비활성임을 확인했다. `<태그>`·`<script>문자열</script>` 입력은 문자로 표시됐다.
- 같은 원본을 두 탭에서 버전2로 열었다. 먼저 저장한 탭은 버전3, 뒤늦은 저장은 충돌 안내를 표시했고 입력 초안과 원래 버전2를 보존했다.
- 버전2에 출처 수동 검토를 기록하고 사람의 기록임을 표시했다. 새 버전에는 이전 검토가 복사되지 않았다.
- 파일 선택창을 통해 68바이트 PNG를 등록해 버전4와 자산 이름·타입·크기를 확인했다. 업로드 도구가 오래 대기했지만 완료 후 실제 새 버전·등록 결과를 다시 관찰했다.
- 학과 보기에서 개인 원본과 학과 목표 채널을 함께 표시했다. 검색으로 동일 원본을 찾아 편집 화면을 다시 열었다.
- 개인 local/tistory 사용 선호를 화면에서 저장하고 새 탭에서 재조회했다. 인증 미확인·실행 미연결 상태를 유지했다. 상단 새로고침 때 미저장 설정 메모와 CAS 버전1을 보존했다.
- 깨끗한 폼에서 학과 필터를 선택하면 학과 설정만 표시되고 개인 설정 행은 사라졌다. 개인 필터 전환도 동작했다.
- 320px에서 문서·편집 dialog 모두 가로320px, 1280px에서 문서1280px·편집 dialog600px였다. dialog 내부 가로 넘침이 없고 Tab 초점은 dialog 안에 머물렀으며 Escape로 닫혔다.
- 확정한 8개 메뉴를 이동하며 각 화면 제목을 확인했다. 브라우저 오류 로그는 없었다.

검증 스크린샷은 `ax-console/design/previews/phase2-editor-{desktop,mobile}.jpg`와 충돌 기록이다. 임시 자료의 화면이며 실제 발행 실적이 아니다.

미저장 설정 이동 확인창을 자동으로 취소하려 할 때 브라우저 제어가 시간 초과됐다. 사용자가 ‘취소 눌렀음’으로 처리했다. 이후 탭 정리로 해당 폼 상태를 직접 재조회하지 못했으므로 이 한 경로를 자동 브라우저 시험 성공으로 세지 않는다. 승인 시 초기화·취소 시 초안과 범위 유지의 실제 production 상태 전이는 Node 회귀 시험으로 검증했다.

전체 단계 독립 코드 검토에서도 Critical/Important 문제는 발견되지 않았다. 선택적 개선으로 같은 계정에서 상단 새로고침 시 도구 설정 목록도 갱신하도록 보완했다. 이때 설정 초안과 CAS 버전을 보존하는 시험2개를 추가했고 최종 수정 scoped 검토에서도 해결 판정을 받았다. 화면 검증 뒤 최종 Python82개·Node24개도 다시 통과했다.

## 외부 플러그인 읽기 점검

Metricool의 연결된 `Primary`·`SMUDS` 링크에서 각각 브랜드1개의 조회 응답을 받았다. Primary 응답에는 TikTok·YouTube, SMUDS 응답에는 Instagram·TikTok·YouTube 네트워크 항목이 있었다. 항목 존재만으로 토큰 유효성·개인/학과 소유권·현재 발행 권한을 검증한 것은 아니다. 브랜드 ID·hash·원본 응답·비밀값을 이 문서나 웹 저장소에 저장하지 않았다. 개인·학과의 정확한 대상 연결은 후속 명시적 대상 확인 단계에서 수행한다. 이 조회는 Codex의 연결 도구를 사용했으며 독립 웹 서버에 실행 권한을 이관하지 않았다.

## 구현 판단

공용 DB 스키마는 콘텐츠 저장소 담당자가 일괄 초기화하고, 연동 저장소는 그 스키마를 사용한다. 파일은 UUID를 포함하는 불변 경로로 준비해 같은 revision 경쟁에서 덮어쓰지 않는다. 수동 검토만 기록하며 독립 검토 실행·승인을 가장하지 않는다. 자산은 인증 후 전체 파일로 전달하고 Range는416으로 거부한다. 이 판단이 맞지 않으면 API·저장 이행 작업과 대용량 영상 미리보기 Range 지원을 추가해야 한다.

파일 fsync·프로세스 중단 시험은 수행했으나 전원 차단·USB 분리 시 디렉터리 내구성은 아직 검증하지 않았다. 실제 운영 저장소 전환 수락 시험에서 확인할 범위다.
