# 운영 웹 2단계 통합 검증

검증일: 2026-10-30. 코드 기준 `98a561d`. 사용자 ‘2단계 개발 시작’ 승인에 따른 기획 저장·계정별 도구 사용 선호 구현이다. 실제 발행·외부 로그인·운영 전환은 포함하지 않는다.

## 확인한 기능

- SQLite·불변 파일로 원본·과거 버전·변환본·출처·자산·수동 검토를 저장한다. 원본 소유 계정은 생성 때 명시하며 이후 바꾸지 않는다.
- CAS의 expected_revision이 다른 두 번째 저장은409다. 실패한 요청이 이전 버전 또는 승자의 파일을 지우지 않는 저장소 시험을 통과했다.
- 관리 저장 루트는 운영 자료 루트와 분리한다. import와 server factory는 초기화하지 않으며 main에서 명시적으로 초기화한다. 미설정 상태는 조회 전용이다.
- 개인/학과·도구·연결 ID 복합키로 사용 선호를 저장한다. 설정 저장은 기존 자동 작업·Codex/Claude 플러그인 설치·로그인·발행 활성 상태를 바꾸지 않는다.

- 새 관리 기획은 배포·예약을 만들지 않았다. 임시 자료의 기존 배포3·일정3은 유지됐고 managed content_id를 참조하는 배포·예약은 없었다. 학과 범위 수와 전체 범위 수를 섞어 비교하지 않는다.

## 아직 완료되지 않은 검증

브라우저 제어 연결이 `browser.user is unavailable`을 반환했다. 기존 핸들·문서에 따른 새 탭 핸들 연결에서도 같았으며, 이 오류를 서버 종료나 UI 결함으로 간주하지 않았다. 생성/수정/두 창 충돌·설정 저장·모바일320/데스크톱1280·키보드 접근의 **실제 DOM/화면 수락 시험은 남아 있다.** Node 함수 시험과 정적 검토는 이 검증을 대신하지 않는다.

전체 단계 독립 코드 검토에서도 Critical/Important 문제는 발견되지 않았다. 선택적 개선으로 같은 계정에서 상단 새로고침 시 도구 설정 목록도 갱신하도록 보완했다. 이때 설정 초안과 CAS 버전을 보존하는 시험2개를 추가했고 최종 수정 scoped 검토에서도 해결 판정을 받았다. 화면 수락 전에는 2단계 전체 완료라고 보고하지 않는다.

## 외부 플러그인 읽기 점검

Metricool의 연결된 `Primary`·`SMUDS` 링크에서 각각 브랜드1개의 조회 응답을 받았다. Primary 응답에는 TikTok·YouTube, SMUDS 응답에는 Instagram·TikTok·YouTube 네트워크 항목이 있었다. 항목 존재만으로 토큰 유효성·개인/학과 소유권·현재 발행 권한을 검증한 것은 아니다. 브랜드 ID·hash·원본 응답·비밀값을 이 문서나 웹 저장소에 저장하지 않았다. 개인·학과의 정확한 대상 연결은 후속 명시적 대상 확인 단계에서 수행한다. 이 조회는 Codex의 연결 도구를 사용했으며 독립 웹 서버에 실행 권한을 이관하지 않았다.

## 구현 판단

공용 DB 스키마는 콘텐츠 저장소 담당자가 일괄 초기화하고, 연동 저장소는 그 스키마를 사용한다. 파일은 UUID를 포함하는 불변 경로로 준비해 같은 revision 경쟁에서 덮어쓰지 않는다. 수동 검토만 기록하며 독립 검토 실행·승인을 가장하지 않는다. 자산은 인증 후 전체 파일로 전달하고 Range는416으로 거부한다. 이 판단이 맞지 않으면 API·저장 이행 작업과 대용량 영상 미리보기 Range 지원을 추가해야 한다.

파일 fsync·프로세스 중단 시험은 수행했으나 전원 차단·USB 분리 시 디렉터리 내구성은 아직 검증하지 않았다. 실제 운영 저장소 전환 수락 시험에서 확인할 범위다.
