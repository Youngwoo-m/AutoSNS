- **따라쓰기 PDF 는 클로드가 직접 만든다(2026-10-18 사용자 지정).** 원문의 'PDF 스킬'은 Codex 스킬이 아니라 클로드의 PDF 작업(pdf 스킬이 있으면 그것)으로 한다. 파이썬은 `GeoAI_NA/claude-jobs/.venv/bin/python`(reportlab·pypdf·pypdfium2·pdfplumber·pillow)만 쓰고, Codex 런타임(`~/.cache/codex-runtimes/…`) 파이썬은 쓰지 않는다. 원본 Q-net 답안지 위에 겹쳐 쓰고, 모든 쪽을 pypdfium2 로 렌더링해 눈으로 확인한다.
- **기술사 글 문체(2026-10-27 사용자 지정, 측량·토목·건축·건설안전 모든 글과 PDF).** 아래가 각 작업 지시문·작성기준의 옛 문체 문장(‘~이다/~한다체’ 등)보다 우선한다.
  - 설명하는 말(도입·해설·학습 안내)은 수험생에게 말하듯 **친절한 어투**(‘~해요/~합니다’)로 쓴다. 허위 경력을 만들지 않는 규칙은 그대로다.
  - **답안 작성 부분**(답안 목차·답안 예시·모범 답안)은 앞뒤를 구분선 `<hr>` 으로 나눠 시작하고 끝낸다. 그 안은 **문어체**(‘~함/~임/~필요’ 같은 명사형 종결)로 쓰고 **개조식**(번호·글머리 항목)으로 정리한다.
  - **답안 예시 PDF(따라쓰기 포함)** 도 문어체·개조식으로 쓴다.
  - **표 안의 내용은 가운데 정렬**한다. HTML 은 `th`·`td` 마다 `style="text-align:center"`, PDF 표도 가운데 정렬.
  - **답안 작성 이론을 설명하는 곳**(목차 잡는 법·요구사항 읽는 법·그림과 표 쓰는 법 같은 답안 작성 요령)은 친절한 어투가 아니라 **문어체**(‘~한다’)로 쓴다(2026-10-28 사용자 지정). 장 전체가 이론이면 그 장을 문어체로, 해설 중간에 잠깐 나오면 `<blockquote><p><strong>답안 작성 요령</strong> — …</p></blockquote>` 로 묶어 어투가 바뀌는 곳을 보이게 한다.
  - **발행 전 humanizer-kr 로 두 번 다듬는다**(2026-10-28 사용자 지정). 1차: 번역투 접속어·명사화·부풀린 말·어투 섞임을 고친다. 2차: 1차 결과를 다시 읽고 밋밋하거나 같은 끝맺음이 이어지는 곳, 남은 군더더기를 한 번 더 고친다. 두 번 모두 사실·수치·링크·법령명은 바꾸지 않고, 위 어투 구분(친절한 설명·문어체 이론·구분선 안 답안)을 지킨다.
- 발행기 출력 마지막 줄은 JSON 이다: `status` 가 `published` 일 때만 성공. `duplicate` 면 이미 같은 제목 글이 있다는 뜻이니
  다시 올리지 말고 그 글을 기준으로 남은 단계만 처리한다. `error` 면 원고를 보존하고 실패를 보고한다.
- 발행 뒤에는 공개 URL 을 `curl -sL` 등으로 열어 제목·본문·첨부(파일 이름)·링크가 실제로 보이는지 확인한 뒤에만 완료로 적는다.
- 같은 글을 두 번 올리지 않는다. 실패한 채널만 다시 시도한다.
- 유튜브 업로드·댓글은 위 도구로만 한다. 회차마다 업로드 스크립트를 새로 쓰거나 YouTube API(videos().insert·commentThreads().insert)를 직접 부르지 않는다 — 잠금·시험 실행·중복 방지를 건너뛰게 된다.

## 숏츠 제작 — 숏츠 제작 에이전트 (2026-10-19 사용자 지정)

숏츠(20초 이하 세로 영상)는 작업이 직접 만들지 않고 `shorts-maker` 서브에이전트(`.claude/agents/shorts-maker.md`)에 맡긴다.
Agent 도구로 불러 작업 이름, 시험 여부, 질문·핵심 답·공식, 시험 이름, 학습 분야·기출 표기(확인된 것만), 출력 폴더, 블로그 글 주소(있으면)를 넘긴다.
서브에이전트는 **백그라운드로 돌리지 말고(`run_in_background` 쓰지 않음) 끝날 때까지 기다려** 결과를 받은 뒤 이어간다(백그라운드로 두면 이 실행이 먼저 끝나 영상이 안 만들어진다 — 2026-10-21).
에이전트가 대본 → 디오라마 2~3장 → 음성(Voicebox 내 목소리) → Remotion 렌더 → 장면 확인·길이 점검까지 하고 영상·제목·설명·태그 파일을 돌려준다.

- 에이전트는 **만들기만** 한다. 주제 중복은 작업이 `published_history.py` 로 먼저 조회하고, 수식이 든 핵심은 `calc-verifier` 로 먼저 검산하고,
  대본·설명은 올리기 전에 `source-reviewer` 로 검토하고, 업로드·예약·댓글은 작업이 `geoai_short_post.py` 로 한다.
- 에이전트가 `status: error` 이거나 `problems` 가 남아 있으면 올리지 말고 영상·자료를 보존한 채 실패로 보고한다.
- 디오라마 그림은 실제 모습을 공식 자료로 확인한 특징만 그린다(확인 못 한 사물은 빼거나 단순하게). 그림이 영상 내용과 모순되면 다시 그린다.
- 화면 자막은 그 장면 대본 문장 그대로 쓴다(줄이거나 바꿔 쓰지 않는다, 2026-10-22 사용자 지시).
- 대본은 디오라마 2~3장에 맞춰 장면 단위(문장 1~2개 = 그림 한 장)로 쓰고, 장면마다 카메라 기법을 정한다(2026-10-26 사용자 지시). 작업이 대본을 미리 써서 넘길 때도 같은 장면 구성으로 쓰고, 기법은 `--camera` 로 전달된다(`shorts-maker.md` 1·2단계).
- 공식·계산 과정을 움직여 보여 줄 장면은 Manim 클립(`remotion-shorts/manim/`, 로컬·무료)으로 넣을 수 있다(2026-10-22). 크레딧을 쓰지 않으며, 디오라마 2~3장을 대신하지 않는다. 방법은 `shorts-maker.md` 4번.
- 첫 2초 훅 제목은 HyperFrames(motion-graphics)로 만든 투명 webm 을 첫 장면 `overlay` 로 얹을 수 있다(2026-10-22, 선택, 로컬·무료). 글자는 화면 위쪽 제목 자리에 두고 그림 위에는 얹지 않는다. 방법은 `shorts-maker.md` 4번.
- 게이트웨이 크레딧은 이 에이전트의 디오라마 그림에만 쓴다(한 장 약 39). 시험 실행에서도 그림은 실제로 그리지만, 최근 시험 그림이 있으면 그 파일을 쓰게 한다.

## 기술사 글 검색어·글머리 (2026-10-28 사용자 지정)

측량·토목·건축시공·건설안전 모든 기술사 글(하루 한 문제·친구 요청·입문 글)에 적용한다. 각 작업 지시문의 첫 문단 규칙보다 우선한다.

- **연관 검색어를 넣는다.** 글마다 ① 시험 이름(정식 이름과 줄임말 둘 다 — 예: 측량및지형공간정보기술사·측량기술사), ② 주제어와 그 동의어·약어·영문(예: DOP·정밀도 저하율), ③ 수험생 검색어(`기출`·`기출문제`·`답안`·`모범답안`·`답안 작성`·`회차`)를 고른다. 제목 앞부분, 첫 문단, 소제목 1~2곳, 그림 alt, 태그(5~10개)에 자연스럽게 나눠 넣는다. 같은 말을 억지로 되풀이하거나 숨긴 글자·관계없는 인기 검색어를 넣지 않는다.
  - 고르는 근거: 그 시험의 `기출분석_2022-2026/키워드집계.json`·문항 원문의 표현, 네이버 데이터랩 검색어트렌드(NAVER API HUB `POST https://naverapihub.apigw.ntruss.com/search-trend/v1/search`, 헤더 `X-NCP-APIGW-API-KEY-ID`/`X-NCP-APIGW-API-KEY` = secret_env 의 NAVER_SEARCH_CLIENT_ID/_SECRET). 2026-10-28 조회(건설안전기술사=100): 건설안전 100·건축시공 88·토목시공 60·측량및지형공간정보기술사 1.8. `기술사 시험일정` 105·`기술사 응시자격` 약 71·`거푸집 동바리` 약 23·`한중콘크리트` 15(11~12월에 오름)처럼 시험 이름이나 일반 주제어는 검색이 많고, `기출`·`답안`·`모범답안` 조합어는 거의 0이다. 그래서 제목·첫 문단에는 시험 이름과 일반 주제어를 앞에 두고, `기출`·회차는 뒤에 붙인다.
- **글머리 = 인사 + 오늘 주제 요약 + 관련 분야 이슈·트렌드.** 본문 맨 앞(친구 요청 링크가 있으면 그 바로 아래) 문단을 이렇게 쓴다.
  1. 인사와 요약을 한 문장으로 — 예: "안녕하세요. 오늘은 위성 배치와 DOP(정밀도 저하율)를 논술형 모범답안으로 정리했어요." 검색 결과 설명으로 쓰이니 주제어를 넣는다.
  2. 이어서 1~3문장으로 오늘 주제와 이어지는 **최근 그 분야 이슈나 트렌드**를 적고 출처 링크와 날짜를 단다. 최근 한두 달 안의 정부 발표(국토교통부·고용노동부·국토지리정보원 등), 법령·기준 개정, 시험 공고(Q-net), 업계 기사 가운데 고른다. 찾을 때는 네이버 뉴스 검색 API·기관 보도자료를 쓰고, 기사 내용보다 세게 말하지 않는다.
  3. 건설안전 등에서 사고 기사를 쓸 때는 피해를 자세히 묘사하지 않고 제도·대책·점검 쪽으로 쓴다.
  4. 알맞은 최근 이슈를 못 찾으면 지어내지 말고 Q-net 시험 일정·출제기준 같은 확인된 사실로 대신한다.
  - 글머리 이슈의 출처·날짜는 `source-reviewer` 가 다른 출처와 같이 점검한다. 어투는 친절한 어투(기술사 글 문체)를 따른다.

## 전문 글쓰기 기준 (2026-10-22 사용자 지정)

기술사 풀이·해설과 건강·안전 정보 글은 초안 단계부터 아래를 지킨다. `source-reviewer` 가 같은 항목을 점검한다.

- **사실·해석 구분**: 출처가 보인 것은 수치와 함께 쓰고, 글쓴이의 풀이는 "~로 보입니다"처럼 해석임이 드러나게 쓴다.

- **한계를 본문에 적는다**: 표본이 작거나 특정 집단·실험실 조건이면 그 사실을 같은 문단에 쓴다.
- **자료 시점**: 참고자료마다 검토일·개정판을 적고, 갱신 예정일이 지난 자료는 그렇다고 밝힌다.
- **가상 예시 표시**: 만든 일정·수치·사례에는 '가상 예시'임과 공식 기준이 아님을 적는다.
- 상투어·형식적 맺음말·내부 작업 설명은 본문에 넣지 않는다.

## 시험 실행 (AX_DRY=1)

환경변수 `AX_DRY=1` 이면 시험 실행이다. 발행기(tistory_post.py·blogger_post.py·geoai_short_post.py)는 자동으로 발행 직전에 멈추므로 **발행기는 실제처럼 그대로 호출해** 경로를 점검한다. 이때는
대기열 claim/published/finish, queue.py add-post, deploy.py, 카카오톡 전송, 유튜브 업로드·댓글·공개 설정 변경, 작성상태·일차 갱신처럼
**바깥 상태를 바꾸는 일은 하지 말고**, 원고·PDF 를 `GeoAI_NA/claude-jobs/dry/<작업>/<날짜>/` 에만 만든 뒤
"시험 실행 — 무엇을 했고 실제라면 무엇을 했을지"를 보고한다.
로컬에서 끝나는 제작(숏츠 음성 합성·렌더링·ffprobe 길이 확인, PDF 렌더링)은 시험 실행에서도 실제처럼 끝까지 하고, 유튜브 도구도 `geoai_short_post.py upload … --go` 그대로 불러(자동으로 점검만 함) 길이·채널·중복 점검 결과를 보고에 넣는다. 대본만 쓰고 멈추지 않는다.
